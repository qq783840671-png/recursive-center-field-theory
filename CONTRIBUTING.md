# Contributing

Contributions are welcome when they provide a reproducible Skill failure, a theoretical counterexample, a controlled comparison, or a small implementation improvement.

Before opening a pull request:

1. identify whether the change concerns theory, Skill behavior, runtime code, evaluation, or documentation;
2. preserve the difference between definitions, hypotheses, implementation claims, and empirical evidence;
3. add the smallest test or counterexample that demonstrates the change;
4. avoid unrelated restructuring and private material;
5. run `python -m unittest discover -s tests -v` and the relevant evaluation tests.

Use the issue templates for a Skill failure or theory challenge. Use Discussions for interpretation and application ideas. Be respectful, criticize claims rather than people, and do not publish credentials or private data.

The maintainer decides what enters the canonical public theory. A declined change may still be valuable; it only means that it did not fit the current public contract.
