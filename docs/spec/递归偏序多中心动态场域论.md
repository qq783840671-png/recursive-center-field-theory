# 递归偏序多中心动态场域论 v0.7-draft

> 状态：内部结构规范候选  
> 日期：2026-08-29  
> 上位约束：递归中心场偏序动力模型、场域相对的递归动态寻址理论  
> 证据边界：本文件把用户明确提出的“多中心更新进体系”形式化为可讨论、可寻址和可验证的结构候选，不宣称它已经成为普遍本体论。构造型Focus能在父任务过程中维护一个选中中心及平级中心引用，并让冲突使局部闭合和父接口失效；它仍不等于完整多中心生命周期或多中心联合调度已经实现。v0.17 sidecar只保留历史轨迹导入与审计。

## 1. 为什么需要多中心扩展

原有理论允许一个场恢复出多个中心候选，也允许中心内部出现分叉、并联和有类型汇合，但这还不足以表达以下结构：

- 同一场契约同时包含多个不可相互删除的闭合义务；
- 每项义务都形成一个只对该义务`\Omega_i／\Gamma_i`最小充分的功能偏序；
- 任一义务都不能被另一义务或一个空洞的共同上位词无损吸收；
- 多个中心之间仍存在约束、支持、竞争、共享位置或联合闭合关系。

如果强行把这种场压成单一中心，会丢失中心之间的差异和耦合；如果把它们拆成完全无关的多个场，又会丢失它们共同受同一场契约约束的事实。多中心场用于保存这一区间结构。

### 1.1 适用层级：完整场域多中心，Focus偏域单中心

多中心描述完整开放场域的上位全景，不规定当前Focus必须同时运行多个中心。Focus接收任务、尺度和副场契约以后，对完整场域作任务相对投影，只选定一个当前主要中心：

\[
P_q:\mathfrak C_F\longrightarrow
F_q=\langle\Gamma_q,G_q,K_q,Frontier_q,R_q\rangle,
\]

其中`K_q`是当前Focus偏域唯一的活动中心，但它自身仍是可以分叉、并联和汇合的偏序结构，不等于单点或单链。未选中心不被删除，只在当前Focus中保留为平级场引用、中心候选或已审计压缩接口；未选中心仍需执行时，必须切换Focus、建立另一Focus实例或返回完整场调度，不能作为“并行贡献”偷渡进当前`Ready_t`。

因此必须同时守住：

```text
完整场域：允许多中心、平级、并行和耦合
Focus偏域：一次只运行一个选定中心
递归完整子场：可以形成失败、单中心或多中心
递归Focus投影：进入任一子场时仍只运行一个已激活中心
```

多中心全景属于上位场维护；Focus不升级为多中心联合调度器。

### 1.2 当前工程层：过程内单中心投影，不是多中心联合控制

新Focus调用把LLM正常任务执行作为父场，但不再等到结果完成后才进入。Focus在父任务内部形成任务相对投影，选择一个`selected_center_id`，保存必要`peer_center_ids`，并只把当前中心的合法前沿交给父执行层。它不把多中心联合`Ready`调度强加给父任务，也不取得父任务的权限或工具控制权。

因此“完整场可多中心”在当前运行面的最低证据要求是：每个已实现中心节点都有对应执行或分析证据；中心关系和汇合规则有结构与证据支持；未执行的平级中心不得为了显示完整而标为`[+]`。平级中心变化若破坏投影证书、输入接口或闭合条件，Focus必须返回`REOPEN_INTERFACE／REFRAME_FIELD／SPLIT_BRANCH`之一，而不是继续沿旧投影执行。

## 2. 三层中心身份

必须区分：

1. **候选中心集** `\widehat{\mathbb K}_F`：分析过程中尚待删除、替代、闭合和证据检验的中心候选。
2. **活动中心集** `\mathbb K_F^{\sigma_t}`：当前场版本与分支状态下，实际承担闭合义务的中心。
3. **中心系统** `\mathfrak C_F`：活动中心、中心间关系、联合闭合规则、证据和谱系组成的完整结构。

同一个功能位置的多个可替代载荷属于一个中心的实现族，不构成多中心。`ANY`规则下尚未选中的替代候选也不属于本轮活动多中心。

## 3. 多中心场的判定

场`F`只有同时满足以下条件，才登记为真正的多中心场：

1. 当前活动中心数量不少于两个；
2. 每个中心本身通过中心候选的删除、替代、顺序、汇合、压缩、闭合、环和空洞检验；
3. 各中心在同一父场契约下同时承担可说明的闭合义务；
4. 删除任一活动中心，都会使至少一项必要义务、中心汇合规则或父接口在当前容差内失效；
5. 不存在一个接口等价的单一中心，能够在不丢失义务、差异和失效条件的情况下替代全部活动中心；
6. 中心间关系和联合闭合规则已声明，不能只把若干中心名称并列；
7. 每项判定均绑定场版本、任务尺度、证据和允许容差。

因此：

- 多个算法方案通常是替代载荷，不是多中心；
- 多条普通并联支路只有在各自承担独立中心义务时才升级为多中心；
- 多个观察视角不自动等于多个结构中心；
- 多个互不相关的契约应拆成平行场，不应伪装成一个多中心场；
- 无法恢复非空洞共同契约时，应执行`Split`或报告定场失败。

### 3.1 中心不可约分解与复合单中心边界

单个中心本身可以包含多个节点、不可比分支和汇合规则，因此“节点多”或“结构复杂”不能证明多中心。给定场契约`\Gamma_F`、任务尺度`\sigma`和当前允许的父接口语言`\mathcal L_{\Gamma,\sigma}`，每个活动中心必须具有可独立审计的中心签名：

这里必须明确“充分”的作用域：`K_i`只需对自己的不可替代义务`\Omega_i`和局部契约`\Gamma_i`充分，不要求它单独满足完整`\Gamma_F`；完整场的充分性属于`K_F^{multi}=Compose(\{K_i\},R_F^C,\mathcal J_F^C)`及其联合闭合审计。若某个`K_i`已经能无失真承担完整场契约，而其他候选只提供可替换实现，则应重新检查它们是否其实属于复合单中心或载荷族。

\[
\Theta_i=
\langle
\Omega_i,Cl_i,I_i,Fail_i,Reopen_i,Lineage_i
\rangle .
\]

- `\Omega_i`：该中心承担的不可替代父契约义务；
- `Cl_i`：可以独立判断的中心闭合状态；
- `I_i`：父向返回接口；
- `Fail_i／Reopen_i`：可以独立定位的失效与重开条件；
- `Lineage_i`：中心自身的版本与运动谱系。

多个候选只有在存在一个当前尺度允许的单中心压缩`h`，并且不保留逐中心身份或状态向量仍能同时恢复父场决策、失败定位、重开入口、证据和谱系时，才可合并为一个复合单中心。若所谓“单中心接口”仍携带`\{\Theta_i\}`、逐中心闭合向量或逐中心失效入口，它只是多中心包装器，不是接口等价单中心。

因此必须区分：

```text
复合单中心：内部结构复杂，但父场只需一个不可再分的闭合／失效身份
多中心包装器：外部名称只有一个，内部仍保留多个独立闭合／失效身份
真正多中心：当前尺度下至少两个中心签名不可无失真合并
```

中心分解相对于契约、尺度、版本和接口语言成立，不保证存在脱离语境的唯一分解。若两个分解都通过检验且彼此不可比较，应保留分支版本或报告分解不确定，不能用显示习惯强选唯一答案。

## 4. 形式结构

单个活动中心写为：

\[
K_i=(X_i,C_i,\preceq_i,c_i,Z_i,\mathcal J_i,\Gamma_i,\epsilon_i,E_i).
\]

其中：

- `X_i`是该中心的功能位置；
- `C_i`是不可无失真删除的构成条件；
- `\preceq_i`是中心内部必要偏序；
- `c_i`与`Z_i`是中心起点和闭合端；
- `\mathcal J_i`是中心内部并联汇合规则；
- `\Gamma_i／\epsilon_i`是闭合要求与容差；
- `E_i`是中心成立证据。

多中心系统写为：

\[
\mathfrak C_F=
\left(
I_F,
\{K_i\}_{i\in I_F},
R_F^C,
\mathcal J_F^C,
\Sigma_F^C,
L_F^C
\right).
\]

- `I_F`：中心身份集合；
- `R_F^C`：中心之间的有类型关系；
- `\mathcal J_F^C`：中心级联合闭合规则；
- `\Sigma_F^C`：候选、活动、阻断、闭合、失效等中心状态；
- `L_F^C`：中心出生、分裂、合并、替代和失效谱系。

场的完整承重结构不再写成一个未经区分的`K_F`，而写成：

\[
K_F^{multi}=
\operatorname{Compose}
\left(
\{K_i\}_{i\in I_F^{active}},
R_F^C,
\mathcal J_F^C
\right).
\]

这不是把所有中心节点简单取并集。`Compose`必须保留每个位置属于哪个中心、哪些位置由多个中心共享，以及跨中心关系的类型。

`K_F^{multi}`只表示场级中心系统的复合承重结构，不是一个新的单中心候选，也不得仅因它有一个符号或一个外层接口就进入`center-merge`。只有通过3.1的不可约压缩检验，多个中心才真正变成一个中心；保留逐中心签名的封装仍然属于多中心。

## 5. 中心之间的关系

中心关系至少区分：

| 关系 | 含义 |
|---|---|
| `requires` | 一个中心闭合是另一中心闭合的必要前提 |
| `co_required` | 多个中心共同构成父契约的不可删义务 |
| `constrains` | 一个中心限制另一中心的合法状态或资源 |
| `supports` | 提供证据、能力或条件，但不是严格前提 |
| `competes` | 争用有限资源或互相降低可达性 |
| `conflicts` | 当前版本中无法同时满足 |
| `aggregates_with` | 必须经过联合算子形成父接口 |
| `shares_position` | 不同中心共享同一场内功能位置 |

只有严格必要先行关系进入中心级偏序`\preceq_F^C`。支持、竞争、冲突和耦合保存在完整关系图中。若两个中心在同一版本中形成必要环，必须通过时间展开、接口压缩、版本反馈或场分裂处理，不能把环冒充偏序。

## 6. 联合闭合

多中心场的闭合不能由任一中心单独宣布。联合闭合审计至少包括：

```text
各活动中心自身闭合
+ 中心级必要偏序成立
+ 中心级汇合规则满足
+ 跨中心冲突已解决或处于契约容差内
+ 共享位置和资源约束一致
+ 父接口误差与活动剩余低于阈值
+ 证据和版本有效
```

中心级规则可以采用`ALL／K_OF_N／AGGREGATE`或领域约束函数。`ANY`通常用于中心候选或替代实现的选择；选择完成后，只有被激活者进入当前活动中心集。不能为了制造“多中心”而把未选候选也计入闭合。

多中心场仍然是相对闭合的。潜在中心、潜在前沿和潜在剩余可以继续存在，只要它们当前不阻断父契约。

## 7. 地址与共享位置

地址继续锚定场内功能位置，不为每个中心复制一套对象。版本化地址记录增加：

```text
center_system_id
center_membership:
  - center_id
  - center_role
  - obligation_ref
  - status
  - obligation_status
  - evidence_ref
  - validity_window
  - closure_effect
center_relation_refs
center_join_rule_ref
center_lineage_refs
```

一个地址可以属于一个中心、多个中心或只属于外围关系图。地址候选先保存在`A_t^{cand}`，通过全场契约、父绑定、功能身份和必要偏序标定后才进入`A_t^{legal}`；中心归属不能替代地址合法性标定。地址级`[+]／[◇]`只表示合法功能位置本身是否实现，不自动证明它对所有中心义务都已满足；每个归属项必须分别保存`obligation_status`、适用时间窗、证据和对该中心闭合的影响。`center_membership`变化通常推进`address_revision_id`和`field_version_id`；只有场身份、父绑定、根路径或功能身份改变时才迁移稳定`address_id`。

`[◇]`严格表示“已标定合法但未实现”，不包含`hypothesized`。`[-]／[∅]`属于寻址结果而不是共享地址。潜在剩余也不是某个中心的`[◇]`地址；它以`bound／candidate／unaddressed`绑定记录连接地址账本，激活后才决定进入某中心的必要前沿、地址标定、活动剩余或场外处置。共享地址的模态、逐中心义务状态、前沿归属和剩余绑定因此是四个独立维度。

完整地址显示可以写成：

```text
F_n@root_path:node {C1,C3}
```

花括号只显示中心归属，不属于稳定地址字符串本体。机器层应通过ID引用，避免中心改名造成地址迁移。

## 8. 多中心运动

中心系统至少允许以下运动：

| 运动 | 含义 |
|---|---|
| `center-candidate-birth` | 新建待检验中心候选 |
| `center-activate` | 候选通过检验并进入活动中心集 |
| `center-demote` | 活动中心退回潜在候选或普通子结构 |
| `center-split` | 一个中心因无法无损统一而分裂 |
| `center-merge` | 多个中心被证明可由一个接口等价中心替代 |
| `center-substitute` | 保持中心义务不变而更换中心实现 |
| `center-rebind` | 中心的义务、关系或父契约发生非等价变化 |
| `center-invalidate` | 新证据使中心或中心关系失效 |

所有运动都必须保存来源版本、目标版本、证据、受影响义务、地址修订和旧新谱系。`merge`不能只因为名称相似；`split`不能只因为观察更细；两者都要通过接口等价或不可压缩差异检验。

## 9. 完整场全景、Focus投影与失效传播

完整场全景保存活动中心、跨中心关系、联合闭合规则和未选前沿；当前Focus状态`Q_t^q`只运行一个`selected_center_ref=K_q`，并以`peer_center_refs`保存投影证书要求的平级接口。`V_t^q`再从`Q_t^q`生成本轮不等深视图。

投影不是简单“隐藏其他中心”。每次投影必须生成：

```text
ProjectionCertificate
  source_field_version
  source_center_system_version
  selected_center_ref
  required_peer_interfaces
  omitted_obligations
  assumptions
  invalidation_triggers
```

Focus返回完整场时必须生成：

```text
FocusReturn
  selected_center_closure
  outputs
  evidence
  peer_interface_effects
  residuals
  reprojection_request
```

`selected_center_closure`只表示当前中心偏域闭合，不能单独生成完整场闭合证书。完整场必须重新审计全部活动中心签名、中心级关系和联合规则。

Focus必须：

- 只展开当前选定中心内部的合法位置或关系；
- 保留该中心对副场、平级中心和父返回接口的边界引用；
- 不把贡献权重或聚焦优先级改写成中心结构必要性；
- 不因没有把其他中心装入当前运行面就宣称它们不存在；
- 跨中心接口变化时退出当前偏域，向完整场全景返回重审请求。

Execute只编译`K_q`内部的合法并联分支及其`D_t/Ready_t`，不计算多个中心的联合Ready。未选中心只能通过已经审计的压缩接口向`K_q`提供输入，不得直接进入本轮执行队列。完整场中的另一中心失效时，先由上位场全景更新关系；只有该变化破坏投影证书、`K_q`的副场契约、平级接口或闭合条件时，才使当前Focus重开、重定场或上升。这样既保存完整场的多中心结构，又避免多中心运行时进入Focus。

## 10. 与相邻结构的边界

### 10.1 多中心与多场

共享一个不可空洞化的场契约并接受联合闭合审计时，可以形成多中心场。契约、闭合端和证据标准彼此独立时，应保存为多个场，通过跨场关系连接。

### 10.2 多中心与多父绑定

多中心描述一个场内部有多个承重中心；多父绑定描述一个场实例同时对多个父场承担路径相对义务。二者可以同时出现，但不能互相替代。本版本仍采用单一`primary_parent`，多父DAG继续作为独立开放问题。

### 10.3 多中心与并联

并联是位置或分支的组合结构，多中心是闭合义务的承重结构。一个中心内部可以并联，多个中心之间也可以并联或汇合，但并联宽度不等于中心数量。

## 11. 失败条件

出现以下情况时，不得登记为已经成立的多中心场：

- 只是把多个候选、视角、对象或实现并列；
- 无法说明每个中心独立承担的闭合义务；
- 删除某个“中心”不影响任何义务或接口；
- 一个等价单中心能够无失真替代全部结构；
- 中心关系没有类型、方向、证据或版本；
- 跨中心必要环没有经过时间或版本展开；
- 完整场全景删除或遗失未被当前Focus选中的中心及其关系；
- Focus把多个中心同时装入一个运行面，造成中心竞争、联合Ready和上下文膨胀；
- 用中心数量、投票或平均权重替代联合闭合规则。

## 12. 实现前沿

当前构造型Focus已经实现：一个选中中心与多个平级中心引用、有类型中心关系与汇合规则校验、四类前沿、证据绑定地址、唯一下一决定、新差异分型、选择性失效传播、父接口重开、版本分支及选中中心／完整场闭合分离；并保留`ProjectionCertificate／FocusReturn`、单层递归展开和`Fold／Unwind`。这些能力只验证记录一致性，不自动发现真实中心，也不实现多中心联合执行调度。

仍未完成的工程前沿至少包括：

1. 完整场全景的`center_system／center_membership／center_relation／center_join_rule`记录；
2. 候选、活动、阻断、闭合和失效状态机；
3. 中心删除、替代、分裂、合并与接口等价审计；
4. 投影版本失效后的自动切换、重投影和完整场重新汇合协议；
5. 跨多个独立FocusReturn的机器级中心系统合并和冲突审计；

在这些剩余工作完成前，最准确的表述是：

> 多中心已经进入完整场域的内部理论规范；新Focus作为父任务内部的单中心投影、导航、失效和继承层运行，sidecar只作历史导入。证据绑定执行、闭合分离、版本判退和基础接口重开已有可运行子集，但中心生命周期、自动语义重投影、跨任务完整场汇合和经验有效性仍未闭合。
