# 分层谱系与结构差异矩阵

> 本文用于回答两个不同问题：递归中心场域论与既有思想和方法在哪里相接；它又在哪些结构位置上不能被现有方法直接替代。相似不等于继承，差异不等于优越，哲学邻近也不能自动证明技术新颖性。

## 一、比较规则

比较必须在同一层级、同一功能位置上进行。不能拿递归中心场域论的哲学目标去对比某个检索算法的速度，也不能拿一个 Skill 的操作流程去宣称超越一套哲学。

每个比较对象至少回答：

1. 它处理什么对象和问题；
2. 边界由谁、依据什么划定；
3. 什么承担组织或“中心”功能；
4. 它表达哪些关系，哪些关系具有必要先行性；
5. 它怎样展开、压缩和重新打开；
6. 失败、未知、冲突或不可表达项怎样保存；
7. 执行结果是否反过来改变原结构；
8. 哪些重合已经有明确先例，哪些差异仍只是待验证候选。

全文使用三种状态：

- `[D]`：本文已经规定的构成性定义或协议；
- `[H]`：有待实验、实现或更完整先前技术检索的工作假设；
- `[O]`：尚未解决的开放问题。

## 二、递归中心场域论的结构签名

```text
任务相对场契约
→ 形成并审计候选承重中心
→ 从一般关系中提取必要前驱偏序
→ 全景展开或 Focus 不等深渗透
→ 将暂时稳定的子场压缩为可重开接口
→ Execute / Audit 把证据写回当前结构
→ 以 [+] [◇] [-] [∅] 保存地址模态状态
→ 以 R_t 与 χ_t 保存剩余、可达性、吸收状态和历史
→ 失效传播、扩场、分裂或版本重构
```

`[D]` 本协议的结构身份不由其中任何单项单独构成，而由这些环节之间的联合约束构成：

> **任务相对场契约＋候选中心形成与审计＋必要前驱偏序＋全景/Focus双运动＋可重开压缩＋执行回写＋剩余驱动的版本重构，被约束在同一套动态地址协议中。**

`[H]` 这一组合是否具有足够的历史新颖性、是否能改善检索、上下文恢复或强化学习，仍需更完整的先前技术检索和实验。

## 三、L1：哲学层

哲学层的详细比较见[《哲学谱系与非同一性：结构匹配稿》](./philosophical-lineage.zh-CN.md)。这一层只承担思想定位：有限显现、关系身份、暂时奠基、闭合与剩余、生成和重构分别可以与不同传统对话，但不存在一条从某位哲学家直接推导出本理论的单线谱系。

比较的结论应写成“结构邻近与非同一性”，而不是“某传统已经被本理论综合”或“本理论是某位哲学家的技术实现”。

## 四、L2：知识表示、规划与系统方法

| 方法 | 已有核心能力 | 与本理论的强重合 | 本理论拟增加的结构位置 | 不能宣称 |
|---|---|---|---|---|
| 分类树、SKOS、OWL | 类属、上下位、多重层级、开放世界、本体导入和版本标识 | 递归地址、层级导航、未知项保存 | 根不被直接当作中心；依据场契约形成并审计任务承重关系，并把地址接到执行和重构 | 首次分层、首次开放世界、首次本体版本化 |
| 知识图谱、属性图 | 异构节点和边、多路径、环、图遍历、子图与视图 | 显式关系、跨层连接、任意深度查询 | 为若干边规定“必要前驱”语义，并加入中心选择、压缩契约、模态剩余和运动规则 | 比通用图数据库表达力更强，或图模型没有动态能力 |
| DAG 工作流 | 前后依赖、任务就绪、并行、子工作流、运行状态 | 必要前驱和合法行动前沿 | 相对于任务场形成并审计候选中心；把未建模差异作为剩余写回并允许改版 | 工作流不能嵌套、不能版本化或不能处理失败 |
| Petri 网 | 使能条件、并发、同步、冲突、循环、可达性和死锁分析 | “何时可以行动”的严格语义和动态状态 | 任务相对中心、双展开、语义压缩接口、四模态剩余与地址版本 | Petri 网不能表达反馈、并发、层级或异常 |
| HTN | 复合任务递归细化、部分有序子任务、方法前提和回溯 | 与递归分解、偏序和执行准备最接近 | 相对于场形成并审计而非预先给定中心；区分全景与 Focus；执行后重算地址和中心；持续保存剩余 | 首次递归任务分解，或 HTN 只是固定树 |
| 系统工程、模块化 | 使命边界、递归分解、接口、需求追踪、基线、变更和风险账本 | 场边界、承重环节、压缩接口、版本和审计 | 用统一地址把中心、展开深度、剩余状态和 Focus 视图连接起来 | 系统工程没有反馈、版本、追踪或问题管理 |
| 因果图、SCM | 因果机制、干预、路径识别和不可识别性 | 依赖链、额外信息需求、反事实检验 | 允许同时保存因果、功能、证据等异构关系，但只把必要前驱投影为偏序 | 所有耦合都能由中心链完全解耦，或功能依赖就是因果关系 |

### 4.1 这里最强的现有基线

如果要严肃验证方法差异，不能只对比普通目录树或静态提示词。最强基线至少应包含：

```text
HTN 的递归细化与部分有序任务
+ Petri 网或工作流的使能与运行语义
+ 系统工程的接口、基线、变更和风险账本
+ 知识图谱／本体的异构关系与版本
+ 因果识别对信息缺口的显式处理
```

递归中心场域论只有在说明这些能力怎样被同一场契约、地址和重构协议约束时，才不会退化为已有方法的术语拼接。

## 五、L3：AI 检索、上下文与智能体

| 方法 | 它主要解决什么 | 与 Focus 的关系 | Focus 的候选增量 | 当前证据边界 |
|---|---|---|---|---|
| 稀疏词汇检索、BM25 | 按词项统计召回相关文档 | 提供候选材料 | 进一步判断材料在当前任务中的功能位置和必要前驱 | 未证明能提高召回或排序指标 |
| 稠密检索、RAG | 按语义表示召回，并让生成模型使用外部材料 | 作为底层召回器 | 防止“语义相似”替代“结构必要”；保存来源、状态和失效影响 | 未证明同预算下优于成熟 RAG |
| Microsoft GraphRAG | 由实体图和社区摘要支持局部、全局及混合查询 | 提供显式关系和候选子图 | 把查询结果编译为任务相对中心、必要偏序、压缩接口和合法前沿 | 不是 GraphRAG 的替代，也不拥有更强的一般图表达力 |
| 长上下文与摘要 | 扩大可读材料或压缩历史 | 提供原文、摘要和缓存 | 编译最小充分结构包，并保留压缩条件、证据和重开地址 | “保留更多必要信息”只是待测目标 |
| 上下文工程 | 选择、维护系统指令、工具、消息和外部数据 | Focus 属于一种特定上下文组织协议 | 以场契约和偏序约束选择，而不是只按相关性或最近性 | 不能把现有上下文工程说成完全无结构 |
| 智能体记忆 | 分层存储、检索、更新跨会话经验 | 可承载 Focus 状态 | 保存任务版本、已审计下闭集、合法前沿、剩余及失效传播 | 未证明比现有记忆策略更省 token 或更稳健 |
| ReAct、规划—执行循环 | 交替推理、行动、观察并更新下一步 | 可作为 Execute 层 | Focus 规定要恢复的任务结构、行动合法门和审计回写 | 不是首个动态智能体循环 |
| Agent Skill | 打包可复用说明、脚本和资源 | Focus 可以作为一个 Skill 分发 | Skill 内运行持续状态模型，而不只是返回一次性文本模板 | Skill 载体本身不是理论创新 |

Focus 在 AI 层的最准确定位是：

> `[H]` **底层召回、图查询和语言模型先产生候选信息；Focus 被提出为其上的任务相对结构编译与上下文编排层。**

它不是把 Transformer 换成显式树，也不是证明显式结构必然优于隐式表示。显式协议的候选价值是可检查、可重开、可迁移和可审计；代价是结构抽取、维护、版本传播和错误中心带来的额外成本。

### 5.2 漂移抑制假设

Focus的候选优势不只是“解释结果”，还包括让漂移可见并受约束。需要区分：

- **目标漂移**：局部任务逐渐替换根目标 F0；
- **结构漂移**：必要前驱、接口或中心关系在压缩中被省略；
- **语义漂移**：同一术语在不同轮次悄然改变功能身份；
- **版本漂移**：过期证据与当前结论混用；
- **状态估计漂移**：进度、剩余工作量或完成时间随叙事变化而无证据修订。

`[H]` 显式F0、地址、已审计下闭集、前沿、证据和版本可能降低上述漂移。在一次内部工作流中，进度比例估计在恢复显式结构后由约40%修正到约75%，且修订理由能够定位到具体完成项；这只是提出假设的观察。若要声称“更准确”，必须预先统一完成度口径，并以最终实际结果重复比较估计误差、无证据修订幅度、约束违背率和置信度校准。

反面风险同样明确：错误中心、漏掉的前驱或不当权重可能把偶然误判固化为稳定结构。因此实验必须同时测量**漂移减少**与**错误固化**。

## 六、L4：Focus Skill 与普通提示、工作流的区别

| 载体 | 通常保存什么 | 能否运动 | 与 Focus Skill 的决定性区别 |
|---|---|---|---|
| 一次性提示词 | 当前指令、格式和限制 | 模型可在一次回答内推理，但提示本身不必持久更新 | Focus 把场状态、地址、前沿、剩余和版本写回持久账本 |
| 检查表 | 固定步骤和验收项 | 通常按预设清单前进 | Focus 允许中心候选失效、路径不等深展开和升场重构 |
| 固定工作流 | 已知节点、依赖和分支 | 可执行、重试和条件跳转 | Focus 还规定未知结构如何成为剩余并触发改图，而不只在旧图中选边 |
| 普通 Skill | 可复用的领域说明、工具和脚本 | 取决于 Skill 的实现 | Focus Skill 的内容恰好是一套动态建模协议；“Skill”只是包装格式 |
| ReAct／计划—执行—反思 | 根据观察循环修订行动 | 明确具有动态性 | Focus 增加可持久恢复的场契约、候选中心、偏序合法门、双展开和剩余类型 |
| 递归任务分解 | 把任务不断拆成子任务 | 可以动态加深 | Focus 不要求每个分支等深；展开由当前场和 Focus 决定，并保留根路径中压缩接口的重开地址 |

`[D]` Focus Skill 的必要输出不是一棵漂亮的分类树，而是一个可继续运动的状态：

```text
F0 根场契约
+ 当前版本选用的候选中心
+ 一般关系图与必要前驱偏序
+ 全景地址和活动 Focus 地址
+ 已实现下闭集与合法行动前沿
+ 压缩接口和重开条件
+ 带 [+] [◇] [-] [∅] 模态标记的地址图
+ 剩余账本 R_t 及其可达性、吸收状态与历史 χ_t
+ 下一次 Execute / Audit 的写回位置
```

`[H]` 相比一次性提示词，它可能减少反复重述和无方向发散；相比成熟规划器，它可能更适合边界尚未完全给定的语言任务。两项都必须通过对照任务验证。

## 七、L5：强化学习与显式策略结构

| 方法 | 已有机制 | 与本理论的重合 | Focus 化策略的候选增量 | 关键风险 |
|---|---|---|---|---|
| 扁平策略网络 | 从状态直接输出动作分布或价值 | 权重可隐式学习关联 | 在策略外提供显式任务地址和依赖合法门 | 错误结构会排除有价值探索 |
| Invalid Action Masking | 在状态中屏蔽非法动作 | 与偏序就绪门最接近 | 合法性由已审计前驱和当前场版本导出，并保存屏蔽理由 | 地址和前驱维护可能比环境原生 mask 更昂贵 |
| Hierarchical RL／Options | 在原始动作之上学习或给定时间扩展动作 | 层级、子策略、进入与终止条件 | 把 option 放入任务相对场地址，并把执行失败回写为剩余或结构失效 | 尚未证明候选中心形成机制能学出更好的 option |
| Hierarchies of Abstract Machines | 用先验机器层级约束策略空间、促进迁移和组合 | “正确结构缩小搜索空间”已有强先例 | 结构不完全预给定，允许通过剩余和 Audit 改版 | 不能再把减少搜索空间本身当作新贡献 |
| Behavior Tree | 模块化、层级化、反应式任务切换 | 可解释控制路线、接口和反馈 | 区分一般关系与必要偏序；保存跨版本地址、压缩和无地址剩余 | Behavior Tree 在控制执行上更成熟、更可形式分析 |
| 图策略／GNN | 在关系图上聚合信息并学习策略 | 利用结构化观测和多实体关系 | 输入图由场契约和功能角色生成，而非仅由邻接关系给定 | 显式图不等于正确因果或正确 credit assignment |
| 模型式规划 | 用环境模型预测后果并搜索行动 | 显式状态转移和计划 | Focus 可作为任务模型、合法前沿和证据账本 | 它本身还不是环境动力学模型或规划算法 |

### 7.1 可以提出的强化学习假设

- `[H1]` 当形成并审计的必要偏序正确且原动作空间含大量结构非法组合时，合法门可能降低无效探索并加快收敛。
- `[H2]` 显式地址、前驱和执行证据可能提高策略追踪、模块复用和跨任务迁移的可解释性。
- `[H3]` 当中心错误、环境存在必要的跨层反馈或最优策略违背人工先验时，结构约束可能降低最终性能。
- `[H4]` 只有把结构抽取、额外计算、人工标注和维护成本计入，才能比较总体收益。

首轮实验应区分四个基线：扁平 PPO、PPO＋原生动作 mask、层级/模块化 PPO、PPO＋Focus 协议。否则即使 Focus 版本变好，也无法判断收益来自偏序、动作屏蔽、层级模块还是剩余回写。

## 八、当前可守住的定位

截至当前比较，递归中心场域论不能稳妥地宣称“比分类学更高级”“解决了强化学习黑箱”或“现有 AI 方法不如本理论”。可以守住的定位是：

> **它是一套哲学—方法—工具连续体：以相对中心回应去中心后的行动问题，以偏序和递归地址组织复杂任务，以全景/Focus双运动控制展开深度，以可重开压缩和剩余账本维持开放重构；在 AI 中，它被实现为候选的任务相对结构编译层。**

这段定位同时保留了理论魅力和证据边界：它说明本理论正在统一什么，也明确哪些优势尚未由实验给出。
