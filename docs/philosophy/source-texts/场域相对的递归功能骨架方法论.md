# 场域相对的递归功能骨架方法论

> 状态：独立方法论原型（v0.11），已加入前向构成闸门、依赖偏序与根地址合法性、全局展开／Focus 渗透双运动、场形成与人工校对闸门、剩余—地址正交关系与可达距离、逐运动剩余审计、偏序波前执行、对象场／关系场双重递归、根层／上层场约束、公共骨架／个人实例双层结构、动态场寻址引擎与 AI 执行规范，仍需跨领域样本、多人标注和对照实验验证。

## 一、目的

本方法用于在进入一个研究领域时，从代表性材料中识别不可任意删除或换序的依赖主轴，再围绕主轴递归展开可变部分。它区分功能位置、具体实现与观察层级，为论文和知识对象分配可回溯地址，从而支持领域导航、论文比较、创新定位与进一步下潜。

它不是先设一棵外部分类树，再把材料塞入目录；而是先恢复对象本身怎样完成任务，再从多种实现的不变关系中提取暂定中心。中心不是一次发现的真理，而是由样本支持、可被反例修订的结构假设。

基本流程：

```text
恢复当前需求、上级目的与成功标准
→ 限定候选工作场，完成关系图／偏序／中心与剩余检验，再确认稳定 F0
→ 选择代表性样本并恢复完整的有类型功能／关系图
→ 对齐功能并合并等价实现
→ 从完整关系图投影、恢复并验证必要依赖偏序（含可比／不可比关系与合法运动方向）
→ 从必要偏序提取并检验不可删除的最小充分承重中心子偏序
→ 递归展开或压缩
→ 分配全局、中心、创新和目标地址
→ 用新样本、剩余与反例调整场域
```

## 二、基本概念

### 1. 场

场是在特定任务下，由以下条件共同限定的相对完整问题空间：

- 任务与核心结果；
- 起点、终点与系统边界；
- 观察方向；
- 展开粒度；
- 适用条件；
- 允许进入的关系类型。

场不是预先存在的绝对分类，也不是空容器。研究者或行动者根据当前需求选择观察什么、解决什么问题以及展开到什么粒度，由此划定场。场一经限定，就规定哪些差异重要、哪些实现可以合并，以及中心应保留到什么粒度。

场的选择具有需求相对性，但不是任意命名。一个有效的场必须受到实际任务、功能闭环、必要接口和对象关系的约束。

#### 1.1 当前工作场 F0

`F0` 表示当前注意力所打开的局部工作根，不表示整个人类知识的绝对根，也不要求它是当前域中尺度最大的场。研究者把关注范围从一个系统切换到其中某个功能节点时，被打开的子场在自己的视图中重新以 `F0` 运行；上一级场转为压缩背景，但其持久身份、上级绑定、返回地址和完整根路径必须保留。

因此，“哪个结构是中心”必须同时说明“对哪个场、哪项任务、何种粒度而言”。同一对象既可以在上一级场中压缩成一个节点，也可以在被关注时展开成新的完整局部 F0。

### 2. 严格中心与场内中心

本方法需要区分两个层次的“中心”。

**严格中心**不是场内的某个对象或节点，而是使递归场这种组织形式得以成立的构成原则 $P$。它至少规定：需求怎样限定场，功能等价怎样合并，必要依赖怎样通过删除、替代、换序和压缩检验，节点怎样展开为子场，子场怎样压缩回父节点，以及无法定位的剩余怎样迫使场扩展、分裂或重构。抽掉 $P$，仍然可能剩下一批数据和关系，但它们不再构成本方法所说的递归场。

可以把场的生成写成：

$$
F=\operatorname{Closure}_{P}(N,B,L,X)
$$

其中 $N$ 是需求或任务，$B$ 是边界，$L$ 是观察粒度，$X$ 是候选对象与关系，$P$ 是递归场的构成规则。$P$ 是使用本方法时暂时接受、允许修订的建模公理，不被宣称为现实本身永恒有效的绝对中心。

**场内中心**则是在某个具体场中，由上述原则提取出来的结构：

> 在当前场中，把功能等价的多种实现压缩以后，仍为维持任务闭环所不可缺少的最小充分承重依赖子偏序，以及维持该子偏序功能契约所必需的有类型接口。

场内中心由必要功能位置、必要中介、依赖关系和不可任意交换的生成次序构成。它会随需求、边界、粒度和现实反例而变化。除非特别说明，本文后续的“中心”均指场内中心。

### 3. 功能等价

不同实现如果在当前场、粒度和适用条件下承担相同功能契约，就属于同一功能位置。功能契约包括：

- 输入；
- 必要变换；
- 输出；
- 下游用途；
- 最低能力要求。

功能等价不要求物理部件、算法或内部步骤完全相同。等价实现共享功能地址，以实现后缀区分。

### 4. 不可约

不可约是相对于场而言的功能属性。继续删除某个关系后，出现以下任一结果，即说明触及中心骨架：

- 核心任务不能完成；
- 必要接口不能保持；
- 结果失去生成来源；
- 系统转变为另一类系统。

物理结构简单不等于功能不可约。

### 5. 依赖偏序与方向

在给定场版本和时间切片内，必要功能位置之间的依赖关系形成偏序。它规定：哪些位置必须先于另一些位置成立，哪些位置能够比较先后，哪些并行位置在当前证据下不可比，以及行动可以沿哪些方向合法运动。

若 $x \prec_F y$，表示在当前场 $F$ 中，$y$ 的成立、生成或合法执行依赖 $x$；删除或绕过 $x$ 会破坏必要契约。若两个节点没有可证成的先决、因果或生成关系，应保留为不可比分支，不能为了得到单线计划、统一评分或整齐图形而强行排序。需要汇合时，应增加具有明确接口的汇合节点或展开二者之间的关系场。

中心是该偏序中不可删除的最小承重依赖子偏序，不是“重要类别”列表。场内还可以保留归属、相关、语义、规范等其他有类型关系；这些关系不因进入同一张图就自动成为依赖偏序。

方向首先表示顺序不可任意交换，不自动等同于所有物理过程都不可逆。图可以反向追溯，但实际生成关系不能因此随意倒置。反馈应按版本或时间展开为 $O_t\rightarrow\cdots\rightarrow O_{t+1}$，不能用下一版本的反馈否定同一版本已经成立的必要前序。

### 6. 功能变化轴

“维度”指围绕同一功能位置反复出现的一类稳定变化方式，不是线性代数中的正交维。常见变化包括：

- 实现方法；
- 能力范围；
- 对象规模；
- 环境与约束；
- 精度、实时性和可靠性；
- 适用条件。

同一变化轴上的不同类型是取值，不是新的中心层级。

### 7. 局部字母中心与数字展开

每个被打开的场都使用一套局部字母表示不可约中心，用数字表示中心节点右侧的类型、实现或条件分支：

```text
当前场中心：A → B → C → D → E → A′
节点展开：  A1、A2……；B1、B2……；C1、C2……
```

字母的意义只在当前场内成立。数字节点一旦成为新的关注对象，就可以打开为子场，并在子场内部以局部 `F0:A → B → C……` 重新建场。持久 `field_id` 和上级绑定保存其身份；返回上一层时，内部字母导航压缩回上一层根字母后的数字路径。因此，字母表示“当前场的中心位置”，数字表示“上一层视图中的分支或被压缩子场”，二者不能混用。

雷达闭环可作为校准示例，而不是所有领域的固定模板：

```text
F0:A 当前帧量测
→ B 量测解释与 Belief 更新
→ C 当前航迹／Belief
→ D 感知决策
→ E 雷达执行感知并形成下一帧量测
→ A′ 下一帧量测
```

其不可任意倒置之处在于生成依赖：当前证据先被解释并形成 Belief，决策再依赖该 Belief，执行结果才形成下一帧证据。具体滤波器、目标数、决策方法和信号级细节属于可展开或替换部分。

### 8. 全局展开、Focus 渗透与层级定位

地址由两种不能混同的运动生成。

**全局展开（Global Expansion）**在当前场版本的合法前沿上进行：不按传播热度或任务权重筛选，把所有可展开中心节点或已有合法前沿统一向下一层展开。统一分辨率用 `L_t → L_(t+1)` 记录。F0 稳定后的默认首轮只做一次 Global，形成 `F1`；随后做一次 Focus，形成 `F2`。这是最低有界成场顺序，不是 field_id、地址前缀、通用深度变量、执行队列或递归上限。由于每个展开节点本身都要重新形成并验证一个递归子场，额外轮次只能由剩余、未决前沿、任务深度或用户要求触发，不能机械执行 2+2。全局展开在实践中受深度和成本限制，但中心偏序及其合法前沿不由这些权重产生。

**Focus 渗透（Focused Penetration）**则从当前完整中心和合法偏序出发，同时选择一个或多个合法节点，并按当前问题、硬约束和影响权重给予不同的继续展开深度。它不必等待全景逐层完成，可以生成此前尚未被全景显式枚举的深层地址，并把新增部分写回全景：

$$
M_{t+1}=M_t\cup\Delta M_{\mathrm{focus}}
$$

返回 `F0` Focus 视图时，活动地址压缩显示为“根字母＋不等长数字后缀”，例如：

```text
A1.2
A2.1.3
B1.1
B3.2.1.4
```

同一根字母下可以同时存在多条活动地址。内部完整展开时，子场成为当前注意力下的局部 `F0`，并用持久 `field_id`、上级绑定和语义面包屑保存结构；返回包含场视图时，应把这段内部导航压缩回所属根字母的数字递归后缀，而不把 Focus 主要展示为若干并列 `F1／F2` 子场。

未被本轮渗透的中心位置保持为可重开接口、压缩状态或约束锁。例如某个不可约前序 `A` 被标记为 `A⟨内容契约锁定，不展开⟩` 时，它仍保留最高结构先行性、功能契约和重开地址；锁定只禁止本轮改写或下潜，不表示删除、降权或永久关闭。

一句话调用分为两种任务意图。用户说“用 Focus 理清／定位／分析”时，默认在 F2 完成剩余审计后交付稳定问题场，不执行外部任务；用户说“用 Focus 做／执行／完成”时，则在同一 F0—F2 成场运动后从活动地址诱导 `D_t／Ready_t` 并继续执行。两种模式共享同一场状态，区别只在 F2 之后是否进入现实行动；不得把“理清”误当成执行授权，也不得把“执行”停在图或计划上。

### 9. 四类论文地址

论文进入一个已定义场后，使用四种用途不同的地址。它们共同描述论文，但不能互相替代。

1. **全局地址**：展开后的中心地址。当前场的整根字母中心必须完整保留，在论文实际涉及的节点上附加递归后缀，用于从全局直接看到论文内部结构。
2. **中心地址**：不展开内部细节的当前场主路径，用于说明论文经过哪些中心位置及其一级分支。
3. **创新地址**：只标记论文实际改变、增加或重新组织的结构位置，用于与同类论文比较。
4. **目标地址**：标记论文最终优化、约束或评价的结果位置，用于区分“以什么结果为价值”。

例如：

```text
全局地址：F0:A1 → B2.2.1 → C6 → D1 → E1 → A1′
中心地址：F0:A1 → B2     → C6 → D1 → E1 → A1′
创新地址：F0:B2.2.1
目标地址：F0:C6.1
```

全局地址不是把创新地址写长，而是始终保留未被压缩的中心，再把已展开细节挂回其所属节点。论文若同时改变多个分支，可以记录一条主全局路径和若干次要挂接点，或记录一个结构地址集合；不能为了得到单线地址而伪造不存在的线性关系。

地址解释遵守以下规则：

- 先展示中心结构，再展示创新，最后展示目标，以保留“通过何种结构变化得到何种结果”的解释顺序；
- 在下潜后的子场中，只写该场能够定义的创新和目标；目标若位于场外，则省略，不强行搬入；
- 论文声明的创新、结构比较发现的差异和实验支持的贡献，作为地址注释分别记录，不另造地址类型；
- 地址更长只表示观察得更深，不表示论文更好、更新或更有价值；
- 同一对象可以在不同场中拥有多个合法角色地址，不存在脱离场定义的唯一绝对地址。
- 任何进入聚焦或执行的路径都必须保存从 F0／本体根到当前节点、保持依赖偏序的完整根路径子图；它可以包含不可比的并行前序与汇合关系。显示可以折叠根路径中的上层接口，但该子图不得从结构中删除。

### 10. 双显示模式

同一场提供两种视图，但底层结构只有一份：

- **Focus 模式**：显示完整中心偏序轴、一个可含多根且同根多条的活动地址集合，以及各地址的不等长数字递归后缀；未展开位置显示为压缩或锁定接口；
- **全景模式**：保持整根中心不被压缩，并显示所需的递归后缀，如 `F0:A1 → B2.2.1 → C6 → D1 → E1 → A1′`，用于跨论文总览和细微比较。

核心原则是：

> 显示可以压缩，结构不能丢失；子场可以折叠成点，但其限定、接口与内部地址必须可逆恢复。

这种“保留已有规定性后再压缩”的形式可以与“扬弃”作结构类比，但该类比不构成对黑格尔哲学的严格等同或证明。

### 10.1 公共中心结构与个人使用结构

同一类活动可以同时具有两个相互映射、但不能混为一体的结构层：

- **公共中心结构**：在一个群体中被共同采用，并持续组织身份、目的、实践、关系或任务的共享骨架。它既可能来自物理和功能约束，也可能由多数人的习惯、信仰、规范及反复实践生成。前者具有较强的因果或功能依据，后者具有社会约定和制度再生产依据，二者不能混称为同一种“客观性”。
- **个人使用结构**：公共骨架在某个主体、目的、条件和历史中的具体实例。它记录当前用户实际激活的路径、个人约束、实现选择、压缩粒度、剩余和新生成的分支。

二者的关系可以写成：

$$
F_u=\operatorname{Instantiate}(F_{pub},I_u,G_u,C_u,H_u)
$$

其中 $F_{pub}$ 是特定群体共享的公共场，$I_u$ 是主体相关条件，$G_u$ 是当前目的，$C_u$ 是情境与约束，$H_u$ 是个人活动历史，$F_u$ 是实际运行的个人场。公共结构提供可复用先验，个人结构决定本次任务具体打开、压缩和执行哪些部分。公共场的证成方式必须注明：它究竟来自功能必要性、物理因果约束，还是来自群体习惯、信仰、制度和规范。

地址也相应分为两层：

```text
公共规范地址：科研活动 > 文献调研 > 获得证据 > 方法重建
个人执行地址：用户U > 当前投稿任务 > 雷达论文P > 方法重建 > 当前疑问Q
```

公共规范地址回答“这一类活动通常由哪些不可缺少的功能位置构成”；个人执行地址回答“这个人在当前目的和情境下，正在使用其中哪条路径”。相同公共节点可以产生不同个人实例；个人活动中反复出现且通过功能检验的新结构，也可以成为修订公共骨架的候选材料。

该地址空间是**潜在无界**而不是一次实际展开为无限长：任何节点都可继续向上寻找上一层或更高层场，或向下展开内部功能，但当前任务只激活有限路径。稳定的长前缀应压缩成可命名模块，具体使用时采用相对地址和延迟展开，需要核验时再恢复完整路径。

多数人的重复实践可以生成公共中心，但不能仅凭多数性把它称为客观因果中心。宗教信仰、礼拜和仪式未必因对应某种可验证的超验实体而成立，却可以通过共同相信、反复执行、身份确认和制度传承，成为宗教共同体不可忽略的中心结构。它的现实性表现为对群体行为和场域再生产的实际组织作用，而不是其信仰对象已经获得本体论证明。

因此，公共中心至少需要区分两种来源：

- **约束型公共中心**：主要由任务闭环、功能必要性或物理因果关系支撑；
- **建构型公共中心**：主要由共同信念、规范、语言、习惯、仪式和制度性重复支撑。

二者都可能构成真实有效的场内中心，也可能相互叠加。检验方法却不同：约束型中心主要接受删除、替代、因果和功能检验；建构型中心主要检查它是否持续组织成员身份、规范行动、分配角色并再生产共同体。高频行为若不承担这些构成功能，只能算多数习惯，不能自动提升为中心。这里的中心是场域相对的构成位置，不等于真理、价值正确性或跨场域的绝对客观性。

### 11. 关系场与有类型传导

递归展开不仅作用于节点，也作用于关系。节点表示被压缩的对象场，边表示被压缩的关系场：

$$
\operatorname{Expand}(v)=F_v,
\qquad
\operatorname{Expand}(e_{AB})=F_{AB}
$$

一条合法的影响边不能只表示“A 与 B 相关”，而应在需要时展开出输入、必要中介、共同约束、接口、作用方向、适用条件和不确定性。若两个平级子系统表现出耦合，优先寻找能够同时容纳双方关系的最小桥接场；找不到传导机制、共同原因或合法接口时，只能暂记为待解释相关，不能直接提升为结构因果。

关系至少区分：归属、先决依赖、物理因果、功能传导、信息通道、资源竞争、统计相关、语义、体验与规范价值。不同类型的边不能因都可画成连线而被压在同一维度。

场的底层结构不预设为一棵全局无环树。当前任务内部可以存在局部偏序和不可任意换序的生成链；反馈、跨场桥接和多重角色由有类型图保留。若某条反馈边过于复杂，可以把它展开为关系场；若多个变量无法在不损失功能语义的情况下分开，则将其共同保留为一个不可约关系模块。

### 12. 剩余

剩余是场运动暴露或生产、尚未被当前结构无失真解释、实现、容差处理或人工裁决的结构差额。它不是所有微小差异，也不等于无地址，而是相对于当前任务、评价指标、边界和分辨率仍然影响闭合的模型失配。

每次全局展开、Focus 渗透或执行批次以后，至少保存：

$$
S_t=(M_t,Frontier_t,R_t,\chi_t)
$$

其中 $M_t$ 是已经实现并获得合法地址的现实结构，$Frontier_t$ 是现实或假设的候选地址边界，$R_t$ 是本轮运动暴露或生产、尚未被吸收的差额账本，$\chi_t$ 保存每条剩余与现实地址、前沿地址、地址假设、负地址或空地址之间的关系。$M_t$ 与 $Frontier_t$ 主要保存地址，$R_t$ 保存差额，三者不是同类型对象的互斥分箱。只报告 $M_t$ 会把动态场伪装成完全闭合的分类树。

判定时先分开两个问题：它当前有什么地址状态，以及它是否已经被场吸收。

地址状态至少包括：现实地址、合法前沿地址、待验证地址假设、负地址、空地址和无关场外信息。只有对 F0 有实质影响、且尚未得到无失真解释、实现、容差处理或人工裁决的差额进入 $R_t$。单纯未展开不自动成为剩余；但一条仍未吸收的差额可以关联一个合法前沿地址，并在该地址真正实现和通过吸收检验以前同时保留“前沿地址＋剩余记录”。

地址与剩余附加四种模态：

- `[+]` 已实现、已经进入 $M_t$ 的现实地址；
- `[◇]` 与当前中心兼容或尚待验证，可由继续展开、压缩或升场尝试吸收的潜在地址；
- `[-]` 与当前场不可约原则冲突、原则上禁止生成的负地址；
- `[∅]` 当前场不能独立生成、无法保证或尚无合法表达的无地址结果。

模态是地址属性，不能替代吸收状态。未展开节点是 `[◇]` 前沿，不是 `[∅]`；若它承载一条未吸收差额，前沿记录地址，剩余账本记录差额，二者由 $\chi_t$ 关联。执行失败也可以关联已经实现的 `[+]` 地址，却仍作为未吸收剩余保留。

对 `[◇]` 地址增加当前版本的可达距离：$d=1$ 表示下一次展开可能实现，$d=k$ 表示需要有限但较深的展开，$d=?$ 表示根路径仍待验证；`[-]` 与 `[∅]` 在当前场内通常记为 $d=\infty$。距离是基于当前中心、偏序和证据的估计，不是对象的永久属性。

$$
\rho_F(r)=\left|\Delta J_F(r)\right|
$$

当 $\rho_F(r)\leq\varepsilon_F$ 时，差异仍处于当前场的稳定域，可以继续压缩；当 $\rho_F(r)>\varepsilon_F$ 时，才触发参数修正、节点或关系场展开、向外扩场、场域分裂或中心重构。数值很小的差异若作用于关键位置或长期累积，也可能成为重要剩余。

剩余可能表现为以下差异，前提是它与 F0 相关且当前仍未被无失真吸收；即使已有候选前沿地址，只要地址尚未实现或接口尚未证明能够吸收差额，剩余仍然保留：

- 现有功能契约无法容纳的新实现；
- 新的能力取值或变化轴；
- 被遗漏的必要中介；
- 跨场对象；
- 场域边界变化；
- 当前中心的反例。

剩余不自动等于创新。

每条剩余记录至少包括：编号；产生它的动作与地址；当前尚未吸收的原因；关联地址种类与候选地址；根路径与偏序合法性；$d=0／1／k／?／\infty$ 的可达距离；未吸收、部分吸收、容差挂起、等待人工、已吸收或禁止等吸收状态；向下展开、向上升场、场内重构、保持外部、人工校对或禁止等可能去向；以及是否改变 Focus 或执行顺序。执行中的暂缺输入和未满足前提先作为运行缺口记录，不自动升级成理论性剩余。已吸收剩余转入历史，保留吸收地址、证据和版本。

> **剩余不是在场外静止等待的杂项，而是场追求闭合并发生运动时显现或生产出来的结构差额；它反过来使场保持敞开。**

剩余审计不能预设 $R_t$ 为空。它必须检查遗漏、压平、错误外置和前沿／剩余混淆；复杂运动若没有新增剩余，还要反查多个 F0 结果是否被压成同一标签、下游优化是否与锁定的上层必要接口冲突、目标结果是否依赖当前场不能生成或保证的外部系统。上层接口锁只禁止改写，不会自动保证下游摘要、标签、受众接口或媒介保持原契约；必须存在合法保真机制和证据，才能把张力记为已吸收。缺少数据属于运行缺口，但不能抹去已经可识别的结构保证缺口。空剩余结论应说明当前结构与容差怎样吸收了全部相关结果；该规则不要求为形式完整虚构剩余。

## 三、核心原则

### 1. 场与中心共构

场规定哪些实现可以视为等价、什么关系不可约；中心骨架反过来组织场内对象、关系和边界。

### 2. 压缩不等于删除

压缩把必要子过程封装成节点，同时保存其功能、前提、输入输出和展开接口。删除则抽掉必要中介，使任务闭环失效。压缩只改变显示和读取深度，不改变根路径中上层节点的结构先行性，也不把它降为低价值或可绕过位置。

### 3. 展开不改变核心身份

节点向下展开会增加显式功能位置、内部关系和结构分辨率。只要中心功能和外部接口保持，展开前后仍属于同一场的不同粒度表达。

全局展开与 Focus 渗透都能增加地址，但前者统一推进合法全景前沿，后者按焦点对多个合法节点进行不等深下潜并把新增地址回写全景。前者必须同时报告 $\Delta M_{global}$、$\Delta R_{global}$ 与新前沿；后者必须报告 $\Delta M_{focus}$、被压缩的合法前沿与 $\Delta R_{focus}$。Focus 权重只决定本轮哪些合法地址继续展开、展开多深，不能决定中心必要性、偏序合法性或结构优先级。

### 4. 递归展开增加结构维数

增加同一功能的实现只增加取值；把功能节点展开为新的必要中介和依赖关系，才增加场的显式结构维数。每个承重点都可以继续成为子场中心。

### 5. 相对功能完备

在当前任务、边界和粒度下，必要功能位置完整、必要中介无缺失、结果能够追溯到生成来源时，场达到相对功能完备。

相对功能完备不等于实现已穷尽或研究已经终结。

### 6. 开放与可修订

场只能相对稳定。新材料可以增加实现、细化节点、扩展边界、分裂场域或迫使中心重构。旧场及其适用范围应被保留。

### 7. 节点与关系双重递归

对象节点和影响关系都可以成为新的关注对象。节点展开回答“这个对象内部怎样成立”，关系展开回答“A 怎样通过中介、接口或共同约束影响 B”。压缩可以隐藏复杂性，但必须保留外部功能契约、适用条件和再次展开入口。

### 8. 根层与上层场规定不得被局部偷换

当前场的任何调整都必须沿根路径向上检查根层及各上层场。若一个操作改变了上级目标、成功指标、比较对象或关键现实条件，它不是原场内部的解决方案，而是建立了新场。简化条件可以作为调试或机制验证子场，但不能冒充原任务已经完成。

可将合法性写为：

$$
a\text{ 在 }F_i\text{ 中合法}
\iff
a\text{ 保持根层及各上层场的核心规定}
$$

### 9. 显式结构与可学习权重分工

递归场规定候选拓扑、节点身份、关系类型和允许的信息路径；数学模型、神经网络或强化学习负责学习节点内部函数和关系权重。中心是否不可缺少与当前权重是否较大不是同一问题：中心由删除检验确定，权重由数据和任务状态确定。错误显式结构可能限制最优解，因此必须允许残差通道、桥接关系和结构修订。

### 10. 公共骨架与个人实例分离

公共结构保存一个群体共同维持的功能骨架、信念规范或实践模块，个人结构保存主体、目的、情境、历史及本次执行路径。公共骨架不得覆盖个人差异，个人偏好也不能未经群体传播和场域构成检验直接升级为公共中心。二者通过规范地址与实例地址映射，使共享经验可以复用，同时保留每次活动的具体身份和剩余。

## 四、构建方法

### 步骤一：限定场域

明确记录：

```text
任务：
核心结果：
成功指标与比较基线：
起点：
终点：
边界：
方向：
粒度：
适用条件：
关系类型：
根层及上层场的不可改写规定：
允许改变的变量：
未经授权不得改变的变量：
当前仍含糊、可能改变 F0／中心的解释：
场契约状态：候选／稳定可执行／等待人工校对／无效
```

自然语言任务开始时这里只形成候选场契约。不会改变中心的细节可由 Agent 暂定；不同解释会产生不同 F0、中心、边界或不可逆行动方向时，必须进入人工校对闸门，不能把其中一个解释静默锁成 F0。

### 步骤二：建立代表性样本集

优先选择能够完成相同或相邻任务、但机制、复杂度或适用条件不同的经典论文、权威综述和代表性反例。单一实例不足以区分中心功能与具体实现。发现中心时使用一组核心样本，同时预留未参与建模的论文作样本外检验。

### 步骤三：恢复功能链与依赖偏序

对每个对象依次提取：

```text
输入
→ 必要变换
→ 必要中介
→ 输出
→ 下游用途
```

不能用结果名称代替结果的生成过程。完成候选提取后，先判断各位置之间的必要依赖、可比与不可比关系，再进行中心提取、路径评分或资源排序。热点、用户画像、媒介和外部对象不能仅因相关性高就被提升为本体前序。

### 步骤四：对齐并合并功能位置

比较不同实现的功能契约。承担同一功能的线路、算法或部件合并到同一功能位置，具体差异转入实现后缀或能力变化轴。

如果不同路线只能依靠空洞的“输入—处理—输出”才能统一，则停止合并，建立平行子场。

### 步骤五：提取中心骨架

保留完成核心任务所必需的功能位置、必要中介、接口和有向次序，形成暂定的最小承重依赖子偏序。完整中心不是若干重要类别的并列清单。

### 步骤六：检验不可约性

对每个候选中心环节进行五项检验：

1. **删除检验**：删除后核心任务是否失效；
2. **替代检验**：能否由另一实现替代而保持同一功能位置；
3. **换序检验**：改变次序后生成关系是否仍成立；
4. **压缩检验**：封装后能否保持功能与外部接口；
5. **空洞检验**：抽象后是否仍有足够区分力。

可替代的是实现，不可删除的是功能位置。能够压缩但不能删除的是必要子过程。

在任何 frontier 评分或路径排序之前，还必须执行结构合法性检验：候选路径必须能回溯到 F0 或当前本体中的具体命题、能力或必要功能位置，并满足全部必要前序；否则只能记录为外部信息、待解释关系或无地址剩余，不能以热度、匹配度、影响或成本补足其结构合法性。

### 步骤七：递归展开

需要整体提高全景分辨率时，对全部合法可展开中心节点和已有前沿统一推进一层；需要解决当前焦点时，对一个或多个合法节点不等深渗透。两者都可把节点打开为局部子场：打开后该子场成为当前局部 `F0` 并重复步骤一至六，返回时再把结果压缩进上一级地址；Focus 新生成的深层地址必须回写当前全景版本。数字递归节点分为 `hypothesized／forming／validated`：前两者只形成 `[◇,d=?]` 地址假设，可留在展开前沿或剩余账本，不能进入闭合、活动／执行路径或实现；第三者才是通过局部契约、完整关系图、必要偏序、最小充分中心、父场／返回接口、递归结构和剩余审计的可用地址。其成场证明必须内嵌证据绑定的可恢复状态快照、逻辑引用与规范哈希，并由验证器复算哈希和检查快照结构，不能用数字后缀、证书字段或摘要格式冒充已经展开。场形成、中心调整、全景展开、Focus、节点／关系展开、压缩、地址实现和执行都要记录 $\Delta M$、前沿变化、$\Delta R^+$、$\Delta R^-$、剩余—地址关系和人工边界项。

### 步骤八：分配地址

先生成完整中心地址，再记录全局展开层级；Focus 输出使用根字母加不等长数字后缀，并允许同一根字母下同时存在多条活动地址。随后单独标记创新地址和目标地址。不得把算法名称直接提升为功能中心，也不得用论文自述的创新替代结构比较。

动态地址生成不是运动结束后的纯编号步骤。每次运动都可能实现新地址、提出待验证地址、暴露负地址或形成空地址；每条未吸收差额都要更新其候选地址和可达距离。

### 8.1 动态场寻址引擎（Address）

> 状态：用户明确提出并于 2026-07-19 修正为引擎结构；其跨领域复用价值以及相对于 token、词源、嵌入、分类和知识图谱方法的收益仍是待验证命题。

Address 不是 Focus 的附属编号功能，也不只是保存地址格式的协议。它是把递归中心场域论转化为可运行映射的动态场寻址引擎：原始信息、概念、关系、动作、外部遭遇或剩余进入候选场以后，通过定场、关系恢复、中心／偏序检验、全景或聚焦运动、吸收与重构，获得场相对的功能身份、动态地址和潜在可执行位置。Focus 是围绕任务目标调用该引擎、决定渗透优先级并继续执行的客户端。

```text
递归中心场域论
→ 动态场寻址引擎 Address
→ Focus／科研知识组织／多 Agent 协作等方法与应用
```

Address 的核心价值不是“给所有概念编一个号码”，而是使身份不足的输入通过场运动获得一个合法、可追溯、可执行、可重开的场相对身份。它可以表示为有状态偏映射：

$$
\Phi_t(x,F_t,\Gamma_t,G_t,\Pi_t,K_t,R_t)
\rightharpoonup
(F_{t+1},\operatorname{identity}_F(x),a_{t+1}(x),R_{t+1})
$$

该映射不保证成功：输入可以获得 `[+]` 现实地址或 `[◇]` 潜在地址，也可以成为 `[-]` 冲突／禁止结果、`[∅]` 当前场无地址结果，或保持为无关场外信息。地址必须由场契约、中心偏序、根路径、必要前序和版本共同生成；仅有词、token、标签、相似度或数字后缀不构成结构身份。

引擎至少包含七个连续运动：

- `INGEST`：保留原始信息及来源，生成接收身份但不冒充结构地址；
- `FORM`：形成候选场、恢复有类型关系、偏序与候选中心；
- `MAP`：把对象绑定到可追溯的场相对功能位置；
- `MOVE`：执行全景、聚焦或最小必要结构展开，生成并回写地址；
- `ABSORB`：用后续展开、压缩、重构或升场尝试吸收剩余；
- `REALIZE`：在必要前序与证据成立后形成 `[+]` 地址及可执行地址视图；
- `AUDIT`：更新现实图、前沿、剩余—地址关系和版本决定。

`VALIDATE／COMPARE／REOPEN` 继续作为检验操作；旧 `CREATE／LOCATE／UPDATE` 分别兼容映射为 `MAP／MAP／MOVE`。

动态地址与对象身份必须分开。对象应有跨版本稳定的身份标识；地址记录它在特定场、特定版本中的结构位置。场重构可以使地址迁移、退役或重新生成，但不能抹除对象身份和历史地址。一个对象可以在不同场中拥有多个合法角色地址；并非所有对象都必须在当前场取得地址，`[∅]` 是协议诚实表达当前场边界的必要状态。

> 产品化决策：用户于 2026-07-19 明确要求把 Address 从纯协议升级为独立的动态场寻址引擎 Skill；这不等于其跨领域收益已经验证。

Address 已被提取为独立引擎 Skill，既可显式接受“把这些信息地址化”的 standalone 调用，也可供 Focus、Distill 及后续客户端调用。它可以形成候选场并运行地址生成运动，但止于可审计地址图与可执行地址视图，不直接执行外部领域任务；Focus 仍负责根目标确认、任务优先级、渗透策略和实际执行。下一阶段应分别在长期 Agent 任务／交接、科研知识与证据演化、多 Agent 协作等差异较大的场中检验。需要验证的关键指标包括：同义改写下的地址稳定性、不同分析者的一致性、身份生成质量、目标漂移变化、额外 token／建图成本，以及系统是否能如实保留 `[∅]` 而不是强行赋予身份。

### 步骤九：判断相对功能完备

检查：

- 必要功能是否齐全；
- 必要中介是否可追溯；
- 每个结果是否具有生成来源；
- 压缩节点是否保留展开接口；
- 新实例是否主要增加实现和局部后缀。

满足以上条件，并且会改变本轮动作合法性的歧义、负地址和空地址已经获得人工裁决，活动地址的必要前序已经满足或由有效接口保持时，当前场在选定粒度下达到相对可执行稳定；这不表示全部剩余归零或场最终闭合。

相对完备的判断必须附带剩余审计结果。若一次复杂运动声称没有新增剩余，需说明为何未发现遗漏、冲突压平、错误外置或前沿误标；“没有看到剩余”不能自动推出场已经闭合。

### 步骤十：用新样本检验并版本化

将未参与中心提取的新论文投射到现有结构，检查它是增加实现、迫使节点展开，还是构成中心反例。每次改变中心语义、编号或父子关系，都记录场版本、地址版本、样本范围和修改原因。地址用于导航，不应假装永久不变。

对于多人活动数据，先保留每个个体的原始执行路径，再按功能、信念、规范、仪式或制度角色对齐不同措辞、工具和操作方式。重复路径可以产生公共模块候选；若主张它是约束型中心，必须继续接受删除、替代、换序、跨情境和样本外反例检验；若主张它是建构型中心，则必须检验它是否组织群体身份、规范行动并参与场域再生产。公共版本与个人实例版本分别记录，并保留二者之间的映射及中心来源类型。

## 五、论文投射、比较与记录

### 1. 单篇论文的最小投射过程

```text
恢复论文的物理／功能闭环
→ 将各环节对齐到当前场中心
→ 生成中心地址
→ 展开论文真正研究的内部节点，生成全局地址
→ 通过同类比较确定创新地址
→ 根据优化、约束和评价对象确定目标地址
→ 分离作者声明、结构差异与实验证据
```

目标必须区分“正文明确声明”和“根据功能推断”。创新也必须通过基础论文或同类论文比较确认；没有足够对照时，可以暂记候选位置，但不能把候选写成已经证实的结构创新。

### 2. 多篇论文的比较方法

- **中心和目标相同、创新不同**：比较解决同一任务的竞争方法；
- **中心和创新相近、目标不同**：观察同一结构向不同任务或价值标准的迁移；
- **比较全局地址的共同前缀与首个分叉点**：定位论文最早发生实质差异的位置；
- **创新地址相同但证据不同**：区分结构相似与贡献强度，不因地址相同就判定论文等价；
- **论文无法获得合法地址**：先记录为剩余，再判断是跨场对象、遗漏节点还是中心反例。

### 3. 最小记录模板

```text
对象编号与题名：
当前场／场版本：
样本与证据来源：

全局地址：
中心地址：
创新地址：
目标地址：

作者声明的创新：
结构比较发现的差异：
实验实际支持的贡献：
地址证据：明确陈述／功能推断／待核验
剩余与反例：
```

作者声明、结构差异和证据状态是地址的注释层，不是第五、第六种地址。记录应服务于定位和比较，不能为了形式完整制造不存在的信息。

## 六、场的调整规则

新内容进入后，按最小改动原则处理：

1. **保持场**：属于已有功能的新实现，只增加实现后缀；
2. **增加取值**：只改变参数、性能或适用条件；
3. **增加变化轴**：一种差异跨多个对象反复出现并稳定改变能力边界；
4. **细化节点**：节点内部差异已经影响当前任务，需要展开为子场；
5. **扩展场**：输入输出、参与者或外部接口发生变化；
6. **分裂场**：不同对象只能依靠空洞抽象统一；
7. **重构中心**：发现遗漏的必要功能，或原必要关系可以被功能等价地替代；
8. **建立桥接**：同一对象在不同场中承担不同功能角色。

调整后保留旧版本、适用条件及变更原因。

## 七、有效性标准

一份有效的场域结构至少满足：

- **任务闭环**：骨架能够说明核心结果怎样生成；
- **不可约性**：删除必要功能会导致场失效或变质；
- **方向性**：必要依赖和生成次序明确；
- **压缩保真**：压缩前后外部功能和接口一致；
- **功能区分性**：中心不是空洞的输入输出描述；
- **地址复现性**：不同使用者能在相同场定义下得到相近地址；
- **结构稳定性**：新实例通常增加局部实现，而非频繁推倒骨架；
- **覆盖性**：领域中的代表性对象能够获得有解释力的地址；
- **导航收益**：相较关键词、普通目录或单层分类，更快定位相关论文及其差异；
- **创新—目标区分力**：能够区分“改了哪里”和“为了什么结果而改”；
- **样本外稳定性**：加入未参与建模的材料后，中心不会只因表面术语变化而崩溃；
- **可修订性**：反例能够真正改变节点、边界或中心；
- **关系可展开性**：重要耦合边能够展开为有输入输出、接口和适用条件的关系场；
- **上层契约一致性**：局部调整不会通过降低任务难度或改写指标伪造成功；
- **根地址合法性**：进入聚焦和执行的重点路径能够回溯 F0／本体根，并保留全部必要前序与压缩接口；
- **前向构成性**：中心、偏序和地址能够回溯到需求、上级目的、场契约及有类型功能／关系证据；不得由预期结果、权重或语言相似性倒推并自证；
- **暂时闭合可检验性**：活动剩余只有在关联合法 `[◇]` 前沿、完整根路径、全部必要前序及证据支持的 $d=1$ 或有限 $d=k$ 时才不阻断下一运动；`[◇,d=?]` 仍是待形成的地址假设；
- **剩余可操作性**：剩余具有任务相关的检测指标、容差和对应结构操作；
- **运动审计完整性**：全局展开、Focus 和执行后都能区分 $M_t$、$R_t$ 与 $Frontier_t$，并记录模态、产生动作和剩余驱动决策；
- **基线可比性**：知识组织应与普通树形目录、分面分类和知识图谱比较；策略学习应与扁平、人工分层、随机结构及其他相近架构比较，而不是只展示自身案例。

## 八、方法边界

- 不预设所有领域都存在唯一全局中心；
- 不把功能等价误写成机制完全相同；
- 不把压缩后的黑箱当作没有内部过程；
- 不把所有差异都提升为新维度；
- 不把所有空白都视为研究创新；
- 不用空洞抽象强行统一不能保持区分力的对象；
- 不把当前场的相对完备当作全部知识的终点；
- 不把线性中心误写成整个领域只有线性关系：跨场归属、反馈和多重角色通过桥接或多地址保留；
- 不把统计相关直接写成结构耦合；找不到共同原因、接口或传导关系时保留为待解释相关；
- 不把所有训练发散都归因于没有找到中心：数值错误、优化不稳定、任务不可行和结构失配必须分别诊断；
- 不因一次运动只产生合法地址就默认剩余为空；复杂运动的空剩余结论必须给出审计理由；
- 不把单纯未展开或被 Focus 降低运行优先级的合法节点自动标成 `[∅]` 或结构剩余；也不因节点位于前沿就删除与它关联的未吸收差额；
- 不通过修改上级目标、降低比较条件或替换成功指标来消除剩余；
- 不让热度、用户兴趣、匹配度或低成本为无根路径制造合法地址；
- 不用地址深度、编号大小或分支数量评价论文质量；
- 不宣称已经得到适用于一切知识的唯一拓扑。

本方法与百科、主题分类、分面分类和知识图谱有交集，但关注点不同：百科重在解释对象，分类法重在稳定归类，知识图谱重在显式表示多种关系；本方法优先寻找任务生成所依赖的不可任意换序主轴，再让节点按需求递归成为新场。实际产品可以把这些方法组合，而不必互相排斥。

## 九、上位结构命题

本方法的核心不在于预先建立一个覆盖所有知识的固定分类表，而在于建立以下生成关系：

```text
观察或行动需求
→ 限定场
→ 提取场内中心
→ 将中心节点与关系递归展开为对象场和关系场
→ 生成结构地址
→ 组织知识、模型或策略并执行
→ 用任务相关剩余决定保持、展开、扩场或重构
```

### 1. 需求先于场

人关注哪个问题、选择哪一段过程作为起点和终点、要求什么结果以及需要多高分辨率，共同决定当前打开哪个场。同一对象可以因需求不同进入不同场，并获得不同的功能身份。

### 2. 场先于中心

中心不是脱离场独立存在的绝对实体。只有在任务、边界、方向和粒度明确以后，才能判断哪些功能可以替代、哪些关系可以压缩，以及哪些功能位置不可删除。场的定义改变，中心也可能改变。

### 3. 中心生成递归结构

中心骨架中的每个功能位置都可以在需要时被重新定义为子场，并在子场中提取新的中心。递归展开不是任意增加层级，而是继续恢复被压缩的必要中介、依赖关系和实现条件。压缩则把已经展开的子场封装回父节点，同时保留功能契约和再次展开的接口。

### 4. 结构用于组织知识与策略

知识、算法、论文、模型和策略不再只按关键词或表面语义归类，而是按照它们在当前场的功能位置、上下游关系、替代关系和约束关系获得地址。相同对象在不同任务中可以拥有不同地址；承担相同功能的不同实现可以共享主地址。

### 5. 普遍性是可检验命题

该结构可能迁移到学科知识、工程系统、决策过程和策略网络，尤其适用于人类建构的、具有明确目标、接口、功能分工和层级关系的系统。其更广泛的普遍性目前是一项待验证命题，不预设自然、社会、知识和认知中的全部结构都必然服从同一骨架。

## 十、自动化设想

自动化的起点不是让系统凭空决定人应该关注什么，而是从使用者的一句话和已有上下文形成可校对的候选场定义：

```text
需求与任务
主体身份与上级目的
起点与终点
系统边界
核心结果
成功指标与比较基线
观察方向
展开粒度
允许改变与禁止偷换的变量
候选对象及其输入输出关系
```

系统应尽量推断这些字段，但把会改变 F0、中心、边界或不可逆方向的分歧送入人工校对闸门。随后可将过程操作化为：

```text
读取已有公共骨架与个人历史
→ 从含糊任务生成候选个人实例场并审计歧义／冲突
→ 必要时请求人工选择、拆场、升场、容忍或禁止
→ 恢复候选功能链及其必要依赖偏序
→ 对齐功能契约并合并等价实现
→ 执行删除、替代、换序、压缩和空洞检验
→ 提取最小充分承重依赖子偏序
→ 为节点和关系分配类型
→ 检验候选路径的 F0／本体根地址与全部必要前序
→ 按需要执行无权重筛选的全局逐层展开，或多节点不等深 Focus 渗透
→ 将 Focus 新生成地址 ΔM_focus 回写全景
→ 从活动地址与必要前序诱导可执行子偏序和 Ready 波前
→ 调用可用工具执行就绪动作并回收结果
→ 在每次地址生成或执行运动后审计 ΔM、ΔFrontier、ΔR+、ΔR-、χ_t 和运行前提缺口
→ 以 S_t=(M_t,Frontier_t,R_t,χ_t) 保存任务相关状态
→ 检查候选操作是否保持根层与上层场规定
→ 按需要保持、展开、扩场、分裂、重构或报告不可行
→ 将本次有效结构写回个人实例
→ 将跨个体稳定结构提交为公共骨架候选
```

自动化系统必须在内部保存下列结构；普通用户回复默认只显示 F0 与中心偏序轴、当前 F0—F2 快照或执行结果、剩余摘要和一个下一状态决定。全景地址、活动地址、根路径、子场验证、详细剩余账本、F0—F2 运动差分和 Ready 执行顺序仅在用户点名时展开：

- 当前场的中心骨架；
- 当前版本的必要依赖偏序、可比／不可比关系及合法运动方向；
- 当前全景分辨率层级及其合法未展开前沿；
- F0 中心偏序轴与根字母＋不等长数字后缀的活动地址集合；
- 每条重点活动路径的根路径、前序满足状态及压缩／锁定接口；
- 本轮由 Focus 新生成的地址 $\Delta M_{\mathrm{focus}}$ 与回写后的全景版本；
- 全局展开新增地址 $\Delta M_{\mathrm{global}}$、新增剩余 $\Delta R_{\mathrm{global}}$ 与新前沿；
- Focus 压缩的合法分支、$\Delta R_{\mathrm{focus}}$ 及其是否要求改焦、扩场或重构；
- 当前调用的公共规范地址与个人执行地址，以及二者的映射；
- 当前场契约、根层／上层场规定及允许／禁止改变的变量；
- 必要功能位置及其方向；
- 对象场、关系场和有类型接口；
- 功能等价实现集合；
- 父场与子场关系；
- 对象的全局、中心、创新和目标地址；
- 折叠模式与全景模式的可切换表示；
- 现实地址、合法前沿、待验证地址假设、负地址、空地址与无关场外信息的地址状态；
- 当前现实图 $M_t$、压缩前沿 $Frontier_t$、剩余账本 $R_t$ 与剩余—地址关系 $χ_t$；
- 地址的 `[+]／[◇]／[-]／[∅]` 模态以及 `[◇]` 的 $d=1／k／?$ 可达距离；
- 每条剩余的编号、产生动作／地址、未吸收原因、关联地址、距离、吸收状态、去向及对 Focus／执行顺序的影响；
- 需要人工校对的歧义、负地址、空地址和边界选择；
- 剩余的任务影响、容差、证据与剩余驱动的下一状态决策；
- 建议保持、展开、扩展、分裂、重构或判定不可行的依据；
- 候选方案是否偷换上级目标、指标或比较条件的检查结果。

这里的自动化首先是“给定场定义后的结构生成与执行监控”，不等同于完全无监督地发现唯一真实结构。场的选择仍来自人的需求，算法可以从语言和上下文推断隐含的主体身份、上级目的和比较标准，但必须把推断显式化并允许核验。算法负责在既定需求和现实约束下，使中心提取、关系展开、地址分配、剩余定位和结构调整能够复现、检验和修订。

若系统从多人数据中生长公共结构，还必须把个体可识别信息与公共功能模板分离，并记录样本覆盖、群体偏差、结构置信度和反例。公共骨架的更新不应由单次对话直接触发，而应经过跨个体证据、版本审查和回滚机制；个人场可以即时生长，但不得自行改写系统根层与上层场的角色、认识论和安全规定。

## 十一、一句话定义

> 场域相对的递归功能骨架方法，是一种由需求及根目标限定当前工作场，从对象与关系中恢复必要依赖偏序及其中不可删除的最小承重中心子偏序，通过全局逐层展开或 Focus 多节点不等深渗透生成并回写可追溯地址，将节点和影响边按需展开为对象场与关系场，并以任务相关剩余控制压缩、扩场和重构，从而约束知识组织、模型计算与 AI 行动的方法。
