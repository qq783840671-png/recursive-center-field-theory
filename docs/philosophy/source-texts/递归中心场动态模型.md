# 递归中心场偏序动力模型

> 状态：运行模型原型（2026-07-19）。本文沉淀“递归中心场域论”从哲学、方法论进入 AI 任务执行层以后形成的最新结构。它规定模型怎样生成、聚焦、运动和执行，不把尚未经过对照实验的性能优势写成既定事实。文件名保留早期称呼，仅作为历史兼容路径。

## 一、统一定位

递归中心场偏序动力模型不是另一套与递归中心场域论并列的理论，而是它的运行形式：

```text
递归中心场域论
→ 给出相对中心、开放场、剩余与重构的哲学结构

场域相对的递归功能骨架方法论
→ 在限定场内提取不可约中心并生成递归地址

递归中心场偏序动力模型
→ 让场随信息、Focus、执行证据和剩余持续运动

运行 Skill
→ 驱动 AI 按该模型完成具体任务
```

早期 `recursive-field-theory` 草稿 Skill 所承载的定场、不可约中心提取、递归地址、Focus 和压缩原则，已经吸收到本动态模型与本地方法论文档中；该旧 Skill 已删除，不再作为独立工具调用。当前运行 Skill 为 `recursive-center-field-dynamics`。

### 快捷调用协议

“递归中心场偏序动力模型”是正式名称，`Focus` 是用户面向任务的快捷调用口令，不取代正式名称，也不等同于模型内部的 Focus 变量。用户不需要使用固定句式；只要明确把任务交给 Focus，例如“用 Focus 做一下……”“这个任务用 Focus”或“Focus 一下……”，就视为主动调用当前 Skill。

调用后，任务内容先进入开放的候选场形成运动；需求及上级目的限定场，完整有类型关系图产生必要偏序，再沿偏序从根层向下逐段验证必要前序，随后用删除、替代、倒序、压缩等检验确定最小充分中心。下游结果不能为自己的上游前提作证。这个过程的相对稳定产物才记为当前注意力下的局部 F0，F0 不是“寻找偏序”这一过程本身。打开子场时，子场在自己的视图中成为新的局部 F0；上一级被压缩但保留持久 `field_id`、上级绑定、返回地址与完整根路径。默认首轮随后只形成 `F1=第一次 Global` 与 `F2=第一次 Focus` 两个有界快照；这些标签只记录运动来源，不表示子场、地址或执行顺序。用户说“理清／定位／分析”时，在 F2 审计后交付，不执行外部任务；用户说“做／执行／完成”时，则从 F2 活动视图编译 `D_t／Ready_t` 并继续执行。只有剩余、未决前沿、显式深度或用户要求证明额外运动会改变结果时，才继续更多版本化 Global／Focus，不再机械执行 2+2。用户明确指定停止点或执行范围时，以用户指定为准。

### 场内绝对，升场相对

递归中心场必须拥有使自身得以成立的构成规则。对当前理论场而言，“限定场域—形成中心—递归展开或压缩—显现剩余—升场或重构”这一组生成规则，在场内承担不可删除的绝对中心：如果连这些规则也在同一场内被当作普通分支任意替换，当前理论场就失去身份。

这种场内绝对性不等于宣称该理论是万事万物的终极本体。理论场本身具有有限定义域，并且可以整体压缩为更大认识场中的一个节点：

$$
P_F\text{ 在 }F\text{ 内具有构成性}
\qquad
F\hookrightarrow F^{+}
\Rightarrow
P_F\text{ 在 }F^{+}\text{ 中成为可比较、可修正的局部中心}
$$

当新内容与生成规则相容时，它在当前场内获得地址；当内容不属于当前定义域时，它保留为场外对象；当与当前场目标相关的持续剩余直接触及生成规则，当前场内部已经没有合法位置可以无失真吸收它，此时必须把整个场升入更高场，或建立新版本的中心，而不能把反例强行降格为普通分支。

因此，相对中心与绝对中心不是简单互相排斥：中心在维持当前场身份时具有场内绝对性，在更大场域和历史重构中又表现为相对性。**升场与重构就是当前绝对中心面对自身剩余时的出口。**

## 二、一句话定义

> 递归中心场动态模型以相对稳定的根目标为中心，在海量异构信息中建立可递归寻址的场，使焦点在认识过程中生成，并通过不等深展开、压缩、滚动执行和剩余反馈持续完成真正的任务。

### 五个缺一不可的结构内核

> 来源状态（2026-07-18）：以下五项由用户在本轮维护委派中明确提出，作为本项目当前采用的构成性定义与 Skill 设计约束；它们不是由一次运行推导出的普遍定律，也不表示已经证明所有任务都必须采用同一结构。

1. **偏序**：在给定场版本和时间切片内，规定必要依赖、先后、可比与不可比关系，以及合法运动方向；反馈通过版本展开表达，而不是用同轮反馈倒置必要前序。
2. **中心**：当前场中不可删除的最小承重依赖子偏序，以及维持其功能契约所必需的接口；它不是一组“重要类别”或高权重节点。
3. **场**：规定中心、边界、合法地址、允许进入的关系类型和可接受容差。
4. **递归展开／压缩**：节点和关系可以打开为下一层场；稳定子场可以压缩为保留契约、根路径位置和重开地址的接口。
5. **动力学**：规定闭合、剩余、展开、升场、分裂、重构以及执行结果怎样进入下一版本。

删除偏序以后，中心不再具有可检验的依赖方向，Focus 也会退化为对任意分类维度的重加权；在本模型的定义域内，这将使它退化为普通递归分类或任意树状整理，而不再是同一个递归中心场动态模型。

## 三、三个不可混淆的变量

### 1. 根目标 F0

根目标规定当前任务最终为了什么，以及什么结果算作完成。它在场形成期可以校准；通过执行稳定闸门后，在一个运行周期内保持相对稳定，局部分析不得通过降低难度、替换比较基线或改变成功标准偷换它。

### 2. Focus

Focus 是在完整中心和当前版本依赖偏序保持有效的前提下，对多个合法节点进行不等深渗透的观察与行动投影。它不只是从已完成全景中静态挑选地址，也不默认只选择一条路径；它可以直接生成此前尚未显式枚举的深层地址并回写全景。Focus 不要求在任务开始前被完整说出，也不是对任意分类维度重新分配权重。

### 3. Active Task

Active Task 是当前 Focus 在本轮能够实际执行的有限任务批次。它受根目标约束，随 Focus 改变，并在完成后把结果返回场模型。

```text
F0 相对稳定
Focus 随认识变化
Active Task 随 Focus 滚动生成
```

若只是改变实现同一成功标准的关注路径，属于 Focus 变化；若成功标准、主体或上级目的改变，则需要形成新的 F0 版本，而不是把它伪装成局部聚焦。

## 四、动态场状态

在第 t 轮，模型至少包含：

```text
G_t：正在形成或已经相对稳定的场契约；包含候选／稳定 F0、边界、容差和人工裁决状态
S_t = (M_t, Frontier_t, R_t, χ_t)：每次运动后的耦合状态，不能只报告已入图地址
M_t：当前已经实现、具有合法地址的现实结构
H_t：当前全景的统一展开分辨率
Π_t：当前场版本内已经恢复并通过检验的必要依赖偏序
K_t：当前场的暂定不可约中心
q_t：当前 Focus
V_t：由 Focus 形成的不等深活动视图
Frontier_t：场内现实或假设的候选地址边界；可继续展开，也可暂时压缩、锁定或降低运行优先级
R_t：由运动暴露或生产、尚未被当前场无失真吸收、解释或解决的结构差额账本
χ_t：把每条剩余关联到现实地址、前沿地址、待验证地址假设、负地址或空地址的剩余—地址关系
E_t：本轮执行快照与任务队列
O_t：执行结果、证据和异常
Z_t：重点活动路径从 F0／本体根到当前节点的完整根路径
ΔM_global：本轮全局展开新增的现实地址
ΔM_focus：本轮 Focus 渗透新生成、准备连同支撑关系一起回写全景的地址集合
ΔR_global／ΔR_focus／ΔR_execute：各次运动经剩余审计确认的新剩余
I_lock：本轮保持压缩或锁定、但仍保留结构优先级和重开地址的接口
```

全景场不是世界的完整地图，而是当前目标、边界、资料和探索历史下已经建立的结构。地址深度表示当前观察粒度，不表示对象价值或理论先进程度。

这里的“完整状态”不是要求剩余非空，也不是把 $M_t$、$Frontier_t$ 与 $R_t$ 当成三个同类型且互斥的箱子。前两者主要保存地址，$R_t$ 保存尚未吸收的差额，$χ_t$ 保存二者怎样关联。单纯未展开不自动构成剩余；但一条尚未吸收的差额可以指向一个近端或深层前沿地址，并在该地址真正生成、实现和通过契约检验以前继续留在 $R_t$。复杂运动若报告 `R_t` 没有新增，必须说明当前中心、接口和容差为何足以吸收全部相关结果；不得为了形式制造剩余，也不得默认场已经闭合。

### 场生成、剩余寻址与相对可执行稳定

一句含糊任务不会自动给出已经稳定的 F0。调用开始时先形成候选场契约 $\hat G_t$：候选目标、主体、边界、成功标准、冲突条件和仍需校对的歧义。只有不会改变当前中心的细节才由 Agent 暂定；若不同解释会形成不同 F0、中心或不可逆行动方向，进入 `HUMAN_CALIBRATION_REQUIRED`，由人选择、拆场、排序、升场、容忍或禁止。F0 在场形成期可以版本化修正；进入执行稳定态以后，局部工作不得再静默偷换它。

场形成具有构成性的前向顺序：**当前需求及上级目的 → 场契约 → 完整的有类型功能／关系图 → 经证据检验的必要依赖偏序 → 最小充分承重中心 → 递归展开与地址生成 → 偏序波前执行 → 剩余与闭合审计**。这不是输出排版顺序。不能先由语言相似、任务结果或传播权重编出一个地址，再倒推一组看似合理的前序；下游结果也不能反过来为自己缺失的必要前序作证。证据可以迫使前面任一位置修订，但修订必须形成新版本并重新通过下游闸门。

场生成、中心调整、全景展开、Focus 渗透、节点／关系展开、压缩、地址实现和执行都属于场运动。统一写成：

$$
\mu_t(S_t)\rightarrow
(\Delta M_\mu,\Delta Frontier_\mu,\Delta R_\mu^{+},\Delta R_\mu^{-},H_\mu,S_{t+1})
$$

其中 $\Delta R_\mu^{+}$ 是本轮新显现或生产的剩余，$\Delta R_\mu^{-}$ 是本轮已被某个现实地址、子场接口、重构或人工裁决吸收的剩余，$H_\mu$ 保存需要人的边界决定。已吸收剩余不从历史中抹除，而记录吸收地址、运动、证据和版本。

对每条剩余 $r$，定义当前版本的地址关系与可达距离：

$$
\chi_t(r)=(\alpha_t(r),d_t(r),g_t(r),a_t(r))
$$

- $\alpha_t(r)$：现实地址、前沿地址、待验证地址假设、负地址或空地址；
- $d_t(r)\in\{0,1,k,?,\infty\}$：已经实现、下一次展开可达、有限深层可达、路径未知或当前场内不可达；
- $g_t(r)$：根路径、必要前序与偏序合法性的证据状态；
- $a_t(r)$：未吸收、部分吸收、容差内挂起、等待人工、已吸收或禁止。

四种模态继续保留，但改为地址模态而不是剩余分类：`[+]` 表示现实地址，`[◇]` 表示潜在或假设地址，`[-]` 表示与当前不可约原则、硬约束或同版偏序冲突的负地址，`[∅]` 表示当前场没有合法表达或生成能力的空地址。`[◇]` 再以 $d=1／k／?$ 区分近端、深层和未验证路径。一个执行失败可以关联 `[+]` 地址却仍未吸收；一个 `[◇,d=k]` 差额可以同时在剩余账本中保留，并把候选地址挂在前沿。

场达到的不是最终静止，而是“相对于本轮动作的可执行稳定”：候选根目标契约稳定；完整关系图和必要偏序已经验证；中心通过最小性检验；会改变它们的歧义已经人工裁决；阻断当前动作的 `[-]／[∅]` 已处理。这个稳定产物才显示为候选 F0 并请求用户确认；确认是对成场结果加锁，不是开始成场的许可。若仍有相关活动剩余，它们必须关联通过根路径、必要前序和子场成场检验的 `[◇]` 前沿地址，且可达距离已由证据支持为 $d=1$ 或有限的 $d=k$。`[◇,d=?]` 只是地址假设，不能支撑 F0 暂时闭合，也不能提前进入活动／执行路径。只有通过闸门并完成确认，才能进入 Global／Focus 或从活动地址诱导执行子偏序。

## 五、模型运动

完整运动闭环为：

```text
接收自然语言任务并形成候选场契约 Ĝ_t
→ 审计语义歧义、冲突和空地址，必要时请求人工校对
→ 从需求、上级目的和场契约恢复完整的有类型功能／关系图
→ 从完整关系图中投影并验证当前版本的必要依赖偏序
→ 从必要偏序中提取、检验并调整暂定不可约中心
→ 对场生成和中心调整分别审计新增地址、已吸收／未吸收剩余和人工边界项
→ 只有图、偏序、中心和剩余闸门通过后，才把稳定产物显示为候选 F0 并由用户确认
→ 确认后以有限深度对合法前沿执行初始全局展开
→ 报告 ΔM_global、ΔR_global+、ΔR_global-，并更新 Frontier_t 与 χ_t
→ 为候选路径建立可回溯、保持偏序的根路径子图并检验必要前序
→ 标记地址、证据、前沿、剩余—地址关系和可达距离
→ 从当前认识中生成 Focus
→ 对多个合法节点进行不等深渗透，其余节点压缩或锁定
→ 将 Focus 新生成地址写回全景
→ 报告被 Focus 压缩的合法 Frontier_t，并审计 ΔR_focus
→ 形成不等深活动视图
→ 生成有限执行批次
→ 执行并获得结果
→ 对失败、冲突、意外结果与未满足前提进行剩余审计
→ 结果分别进入 M_t、Frontier_t、运行前提缺口、R_t 或人工校对闸门
→ 更新 Focus、中心假设和场版本
→ 继续运动或完成 F0
```

可以压缩表示为：

```text
Ĝ_0 = FormCandidateField(UserUtterance, Context)
ΔR_form = ResidualAudit(FormCandidateField)
G_t = StabilizeField(Ĝ_t, UserJudgment, Evidence)
M_0 = Survey(G_t)
H_t = RecoverTypedFunctionalGraph(F0, G_t, M_t, Evidence)
Π_t = ProjectAndValidateNecessaryOrder(H_t, O_(t-1))
K_t = ExtractAndTestMinimumCenter(F0, H_t, Π_t, Evidence)
L_t = StructuralGate(F0, M_t, Π_t, K_t)
M_global^(h+1) = GlobalExpand(M_global^h, L_t)
ΔM_global, ΔR_global, Frontier_(t+1) = ResidualAudit(GlobalExpand)
q_t = SelectFocus(F0, M_t, Π_t, L_t, O_(t-1), UserJudgment)
ΔM_focus = FocusPenetrate(M_t, Π_t, K_t, q_t, Constraints, Weights)
M_(t+1) = M_t ∪ ΔM_focus
ΔR_focus, Frontier_(t+1) = ResidualAudit(FocusPenetrate)
V_t = RenderF0Focus(M_(t+1), Π_t, K_t, q_t)
E_t = Schedule(L_t, V_t)
O_t = Execute(E_t)
ΔR_execute = ResidualAudit(O_t)
χ_(t+1) = AddressResiduals(R_t ∪ ΔR, M_(t+1), Frontier_(t+1), Π_t)
S_(t+1) = Update(M_(t+1), Frontier_(t+1), R_t, χ_(t+1), O_t)
```

模型允许的主要转换包括：

- `Survey`：在重点尚不明确时形成初始合法前沿；
- `FormField`：从含糊任务生成候选场契约，显式保留会改变 F0 或中心的歧义；
- `Calibrate`：由人处理当前场不能合法自行决定的歧义、负地址、空地址和边界改变；
- `GlobalExpand`：不按传播权重筛选，把全部合法可展开中心节点或已有前沿统一推进一层，并报告 `ΔM_global`、`ΔR_global` 与新前沿；
- `RecoverOrder`：从本体、功能链和有类型关系中恢复当前版本的必要依赖偏序；
- `StructuralGate`：拒绝无根、缺少必要前序或违反根层／上层场规定的候选路径；
- `FocusPenetrate`：同时选择多个合法节点，生成不等深新地址并回写全景；未选合法分支进入前沿，并审计 `ΔR_focus`；
- `Expand`：向内打开节点或必要关系；
- `Compress`：把稳定子场折叠为保留契约的接口；
- `Promote`：把当前完整场压缩为更大场的节点；
- `Split`：无法由非空洞公共中心统一时分裂为平行场；
- `Rebuild`：反例推翻必要位置或方向时重构中心；
- `Execute`：依据当前活动视图执行有限任务批次，并检验结果能否被原场吸收；
- `Audit`：在每次地址生成或执行运动后检查遗漏、压平、错误外置、剩余—地址关系和吸收状态，以结果检验中心、地址、Focus 和执行假设；
- `Stop`：满足根目标、达到边界或遇到真实阻断时停止。

## 六、Focus 是生成过程

使用者最初可以只知道一个模糊目标，并不知道真正值得关注的节点。模型可先执行有限的全局展开，让结构变得可见；使用者和 AI 再依据结构形成更准确的 Focus。二者都是地址生成运动，但不能混同。

### 全局展开与 Focus 渗透

全局展开沿当前版本的全部合法可展开前沿统一推进，不用传播热度或任务权重先筛掉某个中心分支：

```text
L_t → L_(t+1) → L_(t+2) → …
```

这里的 `L_t` 表示同一全景的统一分辨率计数。实践中可以因深度或成本停止，但中心偏序不由权重生成。默认首轮在 F0 稳定后执行“一次 Global＋一次 Focus”：`F1` 表示第一次 Global 快照，`F2` 表示第一次 Focus 快照。它们保存运动来源并规定默认首轮的最低有界成场顺序；但不是 field_id、地址前缀、通用分辨率变量、执行队列或递归上限。后续运动按全景版本继续，不因次数增加而机械建立新的 F 层名称。

Focus 渗透不必等待全景完成。它可同时选择多个合法节点，对不同路径给出不同深度，并直接产生尚未在 $M_t$ 中显式出现的地址：

$$
M_{t+1}=M_t\cup\Delta M_{\mathrm{focus}}
$$

内部展开保留完整子场和局部字母中心；当子场成为当前关注对象时，它以自己的局部 `F0` 运行。返回包含场视图时，再把内部导航压缩显示为包含场的根字母加数字后缀。同一根字母下允许同时存在多条活动地址，不再默认“一个中心位置只有一条活动路径”。

数字后缀本身不证明子场已经展开。数字递归节点必须记录 `hypothesized／forming／validated`：前两种只是 `[◇,d=?]` 地址假设，可以保留在展开前沿或剩余账本，却不能支撑闭合、活动／执行路径或实现。只有 `validated` 才表示局部 F0 契约、完整有类型关系图、必要偏序、最小充分中心、父场绑定与返回接口、递归结构以及剩余审计均通过；同时必须内嵌证据绑定的可恢复子场状态快照、逻辑引用与规范哈希，由验证器复算哈希并检查快照图／偏序／中心结构，不能只接受一组证书字段或格式正确的摘要。普通回复可以折叠这些内部状态，但不能以标签代替子场。

Focus 不删除中心，而使中心位置拥有不同的活动深度。例如：

```text
F0 中心：A → B → C → D → A′

当前 Focus 视图：
A1.2.3.1
A2.1
B1
C3.2.1.4.2
D2.1
```

A、B、C、D 仍是不可约承重位置，但当前任务在 A、C 上需要更深的观察，在 B 上只需保留压缩接口。

若 F0 中心为 `A对象 → B公开接口 → C传播媒介 → D外部对象 → E实际看到 → A′`，而本轮硬约束是“不修改对象，只研究怎样让更多人看到”，则：

```text
A⟨内容契约锁定，不展开⟩
B1.1、B2.1.3
C1.2、C3.1.1
D2.1
E1.1.2
```

`A` 仍是全部路径的不可约前序，并通过锁定接口保留内容契约和重开地址。Focus 权重只决定 B／C／D／E 下哪些合法地址本轮继续渗透以及渗透多深，不能降低 A 的结构优先级；后续 Focus 改变时 A 可以重新开放。

被压缩的 B 仍保留它在依赖偏序中的结构先行性、功能契约和再次展开地址。压缩只减少当前显示与读取深度，不表示该上层必要接口已经删除、价值较低或可以绕过。

因此 Focus 是一种场内运动触发器：

```text
看到结构
→ 产生新的相关性判断
→ 调整展开与压缩
→ 形成新的可见结构
→ 再改变认识与行动
```

每次 Focus 都必须在内部保存：F0 中心偏序轴；活动地址集合；每条地址的根路径、子场成场证明与压缩／锁定接口；本轮新生成地址 $\Delta M_{\mathrm{focus}}$；被 Focus 压缩但仍合法的 `[◇]` 前沿；本轮新生产和新吸收的 $\Delta R_{\mathrm{focus}}^{+／-}$；剩余所关联的候选地址与可达距离；回写后的全景版本；以及由剩余驱动的下一状态决策。普通回复默认只显示 F0 与中心轴、当前 F0—F2 快照或执行结果、剩余摘要和一个下一状态决定；全景地址、活动地址、根路径、子场验证、详细剩余账本、F0—F2 运动差分与 Ready 执行顺序在用户点名时展开。没有进入 Focus 的合法节点仅凭“未被选择”这一事实不会成为剩余，但它可以承载一条此前已经存在、仍未吸收的差额。

### 结构合法性闸门与排程

建图和评分之前，必须先恢复并验证依赖偏序。候选路径只有同时满足以下条件，才可以进入可评分的 frontier：

- 能够回溯到 F0 或当前本体的具体根命题、能力或必要功能位置；
- 所有必要前序已经满足，或已经沿合法依赖链明确排在该路径之前；
- 没有偷换根目标、成功标准、主体或边界；
- 路径中的关系具有可说明的类型、接口或传导机制。

若一条重点路径没有完整根路径，它只能暂记为外部信息或无地址剩余，并触发 `REMODEL_REQUIRED`；它不能仅凭热度、用户兴趣或低成本进入 Focus 评分。

以下四个变量必须分开保存和判断：

1. **结构必要性**：节点或关系能否删除，决定它是否属于承重中心；
2. **因果／依赖优先级**：哪些前序不可绕过，决定合法运动方向，但不必把不可比节点强排成一条总序；
3. **当前展开深度**：Focus 此刻需要看到多深，只改变活动视图；
4. **传播热度／任务权重**：相关性、影响、不确定性、热度和成本等运行权重，只能在结构合法的候选之间用于排序。

因此排程顺序固定为：

```text
合法根路径
→ 必要前置依赖
→ 当前 Focus 所需深度
→ 最后才按相关性、影响、不确定性、热度和成本排序
```

外部对象、用户画像和热点不得从对象兴趣无根向外展开。它们只能通过可回溯的关系场接入，例如：

```text
本体
→ 本体价值或能力显现
→ 问题与可验证／可传播接口
→ 证据或载体
→ 媒介
→ 对象匹配
→ 使用与反馈
→ 下一版本本体
```

媒介不能制造本体中不存在的价值；对象只能选择、检验或实现已有的潜在价值。并行媒介或用户彼此不可比时，应保留为并行分支，并在需要时通过汇合节点或关系场连接，不得为方便评分伪造成线性因果链。

## 七、海量信息的进入方式

模型不要求把全部数据一次性塞进上下文，而先做两个正交判断。

第一轴判断它的地址状态：

1. **现实地址**：已经进入 $M_t$ 的合法节点或证据；
2. **合法前沿地址**：已有合法根和必要前序，但尚未被全局展开、Focus 渗透或实际实现；
3. **待验证地址假设**：可能存在地址，但根路径、必要前序或关系类型尚未验证；
4. **负地址**：候选结果与不可约原则、硬约束或同版偏序冲突；
5. **空地址**：当前场没有相应地址语法、生成能力或保证能力；
6. **无关场外信息**：当前不影响 F0，不为形式完整强行收编。

第二轴判断它是否已经被当前场吸收。只有对 F0 有实质影响、且尚未得到无失真解释、实现、容差处理或人工裁决的差额进入 $R_t$。单纯未展开、单纯场外或单纯地址较深都不足以构成剩余；反过来，剩余也不等于无地址，它可以关联现实地址、前沿地址或待验证地址假设。

地址关系附加模态状态：

- `[+]`：已经实现并进入 $M_t$ 的现实地址；
- `[◇]`：与当前中心兼容或尚待验证，可以通过继续展开、压缩或升场尝试吸收的潜在地址；以 $d=1／k／?$ 标记可达距离；
- `[-]`：与当前场不可约原则冲突、原则上禁止生成的负地址；
- `[∅]`：当前场不能独立生成、无法保证或尚无合法表达的无地址结果。

合法但未展开的节点属于带 `[◇]` 的 `Frontier_t`，不能因为当前没有显示细节就标成 `[∅]`。若一条未吸收差额指向该节点，则节点留在前沿、差额留在剩余账本，并通过 $χ_t$ 关联；地址真正实现且通过吸收检验以后，差额才转入吸收历史。若根路径只是猜测，标记 `[◇,d=?]` 与 `unverified`，它既不能支撑暂时闭合，也不能提前进入执行。

每条剩余至少记录：编号；产生它的运动与地址；当前场尚未吸收的原因；关联地址种类与候选地址；根路径合法性；$d=0／1／k／?／\infty$ 的可达距离；吸收状态；向下展开、向上升场、场内重构、保持外部、人工校对或禁止等可能去向；以及它是否改变当前 Focus 或执行顺序。暂缺输入或未满足执行前提先记入运行审计，只有证据表明当前场无法无失真解决时才升级为结构剩余。

实际读取遵循渐进原则：

```text
先读取压缩接口
→ 再定位相关地址
→ Focus 后展开局部证据
→ 只有必要时读取原始材料
```

由此形成“检索—寻址—聚焦—展开—验证”的信息处理过程。向量检索、关键词、知识图谱和大语言模型可以负责产生候选；递归中心场负责规定候选在当前任务中的身份、依赖、接口和剩余地位。

### 闭合生产剩余，剩余迫使敞开

> **剩余不是在场外静止等待的杂项，而是场追求闭合并发生运动时显现或生产出来的结构差额；它反过来使场保持敞开。**

场为了支持认识和行动，必须形成相对闭合：规定中心、边界、合法地址、压缩接口和可接受容差。但闭合不是中性的收纳，它同时进行选择、合并、排除和压缩。某些差异原本存在，却只有在场试图给全部相关内容安排位置时，才作为“无法被当前结构无失真吸收的剩余”显现出来。

因此，剩余不只有“外部事件闯入”这一种来源，还包括：

- **闭合生产的剩余**：场的分类、边界和中心规定使某些差异失去合法地址；
- **子场内生的剩余**：父场为完成闭合而展开子场，子场围绕自身中心运动时产生超出父场既有接口的新差异；
- **压缩返现的剩余**：曾被认为低于容差的内部差异积累后重新影响上层结果；
- **外部遭遇的剩余**：现实出现了当前定义域没有预留的对象、关系或事件。

这里的“生产”不是说场凭空创造了那个现实对象，而是说：对象作为“剩余”的结构身份，由场的闭合操作共同产生。没有这套边界与地址，它可能只是尚未区分的差异；闭合以后，它才被显现为当前场不能吸收的部分。

```text
场追求相对闭合
→ 建立中心、边界和合法地址
→ 压缩或排除不能进入当前闭环的差异
→ 差异以剩余形式返回
→ 剩余暴露闭合的限度
→ 场被迫展开、升场、分裂或重构
→ 形成新的相对闭合
```

所以闭合与敞开不是两个互不相关的状态：**场追求闭合的运动，本身可能生产出迫使它重新敞开的剩余。**动态性不只来自外部世界不断输入新信息，也来自场自身组织信息的方式会制造新的边界、盲区和未被容纳的差异。

其中更深的一层运动发生在父场与子场之间：

```text
父场围绕中心趋向闭合
→ 为消除未决项而展开内部节点
→ 节点成为子场，并围绕自己的中心趋向局部闭合
→ 子场运动产生新的对象、区分、关系和可能性
→ 可兼容部分被压缩回父场接口
→ 超出接口、地址或容差的部分成为父场剩余
→ 父场展开、升场、分裂或重构
→ 新父场再次趋向相对闭合
```

因此，父场的闭合冲动会启动子场运动，而子场运动又内生地产生父场无法最终吸收的条件。每一个有限场都可以朝向局部闭合，递归中心场的整体历史却保持开放。这不是“稳定”与“开放”的外部拼接，而是局部闭合不断生成整体开放的同一运动。

在偏序表达上，也不能把全部历史理解成沿一张固定偏序图单调前进。每一版场内部可以具有不可颠倒的依赖偏序，但子场剩余可能增加节点、改变关系并重写偏序本身：

$$
\mathcal P_0\rightarrow\mathcal P_1\rightarrow\mathcal P_2\rightarrow\cdots
$$

所以动态模型对应的是“版本化偏序的生成序列”：场内运动朝向当前闭合，跨版本运动则可能改写闭合所依据的结构。

在认识层面，终极真理不是因此被取消。它可以作为引导有限场持续形成局部真理的极限中心；但任何一个有限理论场都不能仅凭自身相对闭合，宣称已经穷尽这一极限。越严格地追求真理，越需要展开此前被压缩的子场；而展开又会显现新的差异与剩余。因而，**真理既规定闭合的方向，也通过追求真理的活动使最终闭合不断后退。**

这一命题仍需保留边界：不是所有剩余都由场内部生产，也不是任何无法解释的内容都足以推翻中心。只有当剩余对 F0 的结果产生超过容差的持续影响，且不能通过现有分支、接口或局部修正吸收时，才触发场的结构性敞开。

## 八、滚动执行与监督

场不能建完以后一次性执行，因为执行本身会产生新认识。每轮只能冻结一个临时执行快照：

### 执行轴与展开层分离

> 状态：**已纳入 Skill 与协议约束**（2026-07-19）。状态模式能够保存执行子偏序与 Ready 波前；具体工具动作仍由运行中的 Agent 在权限、风险和可用工具边界内完成，不能把协议表达能力误写成独立自动调度服务已经实现。

最终动态地址生成以后，执行不应按 `F0 → F1 → F2` 逐层推进。`F0` 是根目标、验收条件与不可偷换约束，不是一个待执行动作；`F1` 是 Global 来源快照，`F2` 是 Focus 来源快照，也都不是现实动作步骤。真正的执行方向由当前版本偏序 $\Pi_t$ 及活动地址集合共同诱导出的可执行子偏序决定。

```text
F0：在每个动作前后持续约束和验收，不进入普通动作队列
F1／F2：保留一次 Global 与一次 Focus 的构造来源，不规定动作先后
A／B／C／D／E：规定必要依赖、可比／不可比关系与合法执行方向
数字后缀：说明某个中心位置被下潜到哪个具体分支，不自动表示每段都是独立动作
```

设 $Active_t$ 为当前动态地址集合，$Pred_t$ 为这些地址的全部必要前序与压缩／锁定接口，则本轮执行图应由下式产生：

$$
D_t=\operatorname{Induce}(\Pi_t, Active_t\cup Pred_t)
$$

在 $D_t$ 中，根路径上的必要前序先标记为“已满足、锁定、压缩但契约有效、待执行或阻塞”。已满足、锁定或契约有效的前序只需验证，不必机械重复执行。当前就绪集合为：

$$
Ready_t=\{v\in D_t\mid \operatorname{Pred}(v)\text{ 已满足或由有效接口保持}\}
$$

调度器只从 `Ready_t` 中选择本轮真正能够产生结果的未满足动作；不可比节点可以并行，资源限制导致的先后不得写回为因果边，多个分支在明确汇合节点重新组合。若当前地址为 `B1.2.3`，`B1` 与 `B1.2` 可能只是上一层接口和导航路径，不能在没有独立动作语义时被机械拆成三个连续执行步骤。

因此，执行既不是“沿一个数字分支纯纵向到底”，也不是“把同一 F 层全部横向执行”，而是：

```text
持续检查 F0
→ 从最终动态地址恢复可执行子偏序 D_t
→ 标记根路径上已满足／锁定／压缩／阻塞的必要前序
→ 形成偏序就绪波前 Ready_t
→ 执行其中尚未满足的具体动作地址
→ 并行处理不可比分支并在汇合点组合
→ 审计 M_t、R_t 与 Frontier_t
→ 生成下一版本偏序与执行波前
```

这项决定细化了现有“合法根路径 → 必要前置依赖 → Focus 深度 → 权重排序”规则：前者规定地址如何进入活动视图，本节进一步规定活动视图怎样变成执行队列。后续工程化仍需用正反例检验执行状态、就绪集合、汇合节点以及资源性排序与因果偏序分离是否稳定。

#### 一句话调用的目标闭环与工程边界

> 状态：**已写入 Skill 的默认调用协议**（2026-07-19）。期望的外部接口是一句话，例如“用 Focus 做一下：〈任务〉”；用户不必再手工提供中心、展开方式或动态地址，也不必在每个内部阶段重新下令。该协议不扩大权限，也不等于状态助手已经成为能独立选择和调用所有外部工具的自治服务。

一次调用应在既有授权和风险边界内连续完成：

```text
自然语言任务
→ 建立并锁定候选 F0
→ 恢复／调整中心与依赖偏序
→ 根据认识状态选择 Survey、全局展开或 Focus 渗透
→ 生成并回写动态地址
→ 从活动地址与必要前序诱导 D_t 和 Ready_t
→ 调用可用工具执行就绪动作
→ 回收 O_t，审计 M_t、R_t 与 Frontier_t
→ 由剩余调整 Focus、扩场、重构或继续执行
→ F0_COMPLETE 或真实 BLOCKED
```

用户可以看到中心、展开方式和动态地址怎样随证据变化，但这些是可审计的内部状态，不应变成必须由用户逐步驱动的操作负担。所谓“直接执行”也不意味着绕过权限、替用户批准高风险动作或在缺少必要输入时伪造结果。

当前项目源 Skill 已支持“一句话显式触发”、默认 F0—F2 成场运动和“理清／执行”双模式；schema 2.2 与状态助手能够表达并校验偏序、活动地址、子场成场证明、全景回写、剩余审计、执行子偏序、Ready 波前、更新入口和地址运动谱系。状态助手仍只负责状态转换、证据引用和一致性校验，不独立证明领域语义为真、决定使用哪个外部工具、替用户批准高风险动作或保证任务现实完成。因此，现状是“Skill 约束 Agent 连续执行并提供可审计状态”，不是一个脱离 Agent 的通用自治调度服务。

后续工程化仍需要：

- 用更多端到端任务检验执行子图、节点状态、Ready 集合、显式汇合、批次结果和证据回写是否足够稳定；
- 在不扩大权限的前提下，研究更通用的工具选择、失败恢复与长任务续跑接口；
- 验证“只要下一动作合法且在授权范围内就继续运行”在不同 Codex 工具环境中的一致性；
- 用“一句话＋无预建状态”的正向用例，以及锁定上层接口、多活动地址、不可比分支并行、汇合、剩余改焦和阻塞等反例做端到端测试；
- 保持触发边界不变：只有用户明确调用 Focus／正式名称时才启动这套闭环。

```text
读取当前场版本
→ 检查 F0 与不可偷换约束
→ 建立 F0 最低限度的功能闭环
→ 恢复依赖偏序并执行结构合法性闸门
→ 先排入合法根路径和必要前置依赖
→ 若执行全局展开，则统一推进全部合法前沿一层
→ 若执行 Focus 渗透，则在多个合法节点上按硬约束和权重决定继续与深度
→ 权重不参与中心、偏序或结构优先级判断
→ 执行一个有限批次
→ 执行剩余审计：检查证据、偏移、失败、冲突、意外结果与未满足前提
→ 更新 M_t、R_t 与 Frontier_t；未被 Focus 选择的合法分支仍属于 Frontier_t
→ 返回全景重新分配 Focus
```

场生成、中心调整、全局展开、Focus、节点／关系展开、压缩、地址实现和 Execute 之后都必须执行剩余审计。审计至少检查：是否遗漏了无法解释的结果；是否把冲突压平成已有类别；是否把相关差异误丢到场外；是否把单纯未展开误写成剩余；是否遗漏了“差额仍未吸收但已经有前沿候选地址”的重叠状态。复杂运动若没有产生任何新剩余，还要反查三处：多个 F0 结果是否曾被压成同一标签；下游优化是否与锁定的上层必要接口产生张力；目标结果是否依赖当前场不能生成或保证的外部系统。第一类旧失配可以记录为已吸收结果，第二类形成暂定结构剩余，第三类使用 `[∅]` 并决定保持外部、人工校对或升场。上层接口锁只禁止改写，不会自动证明下游摘要、标签、受众接口或媒介保持原契约；只有存在合法保真机制和证据时，才算吸收该张力。缺少测量数据只是运行缺口，不能借此抹去已经可以识别的结构保证缺口。空剩余理由接受后续证据推翻，不能被写成场已经最终闭合。

反馈必须按版本展开：本轮结构和执行产生 `O_t`，其反馈用于生成或修订 `M_(t+1)`，再影响下一轮结果 `O_(t+1)`。反馈边不能被用来否定同一轮已经成立的必要前序；若反馈改变了节点或关系，应建立新版本偏序，而不是在原版本中同时宣称两个相反方向。

它既不是严格广度优先，也不是沿单一路径无限深挖，而是“中心约束下的不等深、滚动式最佳优先执行”。

执行监督必须区分：

- 动作失败，但场结构仍成立：修正实现或参数；
- 当前地址证据不足：补充观察或下潜；
- 出现关键无地址剩余：请求重新建模；
- 含糊语义、负地址或空地址会改变 F0、中心或不可逆方向：请求 `HUMAN_CALIBRATION_REQUIRED`；
- 剩余触及当前场边界或生成规则、但在更高场可能获得合法位置：请求 `FIELD_ASCENSION_REQUIRED`；
- 局部方案改变 F0：拒绝执行并恢复根层与上层约束；
- 已满足 F0 验收条件：停止，不因理论上仍可递归而继续扩张。

## 九、模型、Skill 与执行者

工程上采用一个共享模型和两个逻辑控制器：

```text
共享状态：递归中心场动态模型
    ↕
控制器一：全景生成、Focus 与场运动
    ↕
控制器二：滚动执行、监督与结果审计
    ↕
基础 AI、代码工具、搜索工具或其他执行器
```

当前 `recursive-center-field-dynamics` Skill 把两个控制器放在同一 Skill 的不同模式中，以避免状态割裂；当执行工具、权限和验证流程显著复杂以后，再考虑拆成“场运动器”和“执行监督器”两个 Skill。拆分以后仍必须共享同一场状态、事件协议和版本历史。

## 十、当前 Skill 与旧草稿的关系

已删除的 `recursive-field-theory` 草稿中仍有效的静态建模内核，已经吸收到当前动态模型和方法论文档，主要包括：

- 限定当前场；
- 恢复输入—中介—输出—下游闭环；
- 执行删除、替代、换序、压缩和空洞检验；
- 建立字母中心、数字分支和聚焦地址；
- 判断当前问题所需的停止深度。

当前 `recursive-center-field-dynamics` Skill 在此内核上增加：

- 模糊目标下的 Survey；
- 在评分前恢复并验证当前版本依赖偏序、完整根路径与必要前序；
- 区分无权重筛选的全局逐层展开与多节点不等深 Focus 渗透；
- 从认识过程中生成中心保持、偏序约束的 Focus，并把新地址回写全景；
- 以 `S_t=(M_t,Frontier_t,R_t,χ_t)` 保存现实／潜在地址、压缩前沿、剩余账本、剩余—地址关系、模态和版本；
- 在 Global Expansion、Focus 与 Execute 后强制执行剩余审计；
- 让展开与压缩形成连续状态转换；
- 把 Focus 视图转换为有限执行批次；
- 根据执行结果重新聚焦或重构。

因此，旧 Skill 只以被吸收的能力原则继续存在，不再是可调用或可依赖的独立 Skill。对外使用正式名称“递归中心场动态模型”，也可以用 `Focus` 作为明确的任务调用口令。

## 十一、当前可检验价值

### 一次真实使用失败与本轮约束来源

> 案例状态：以下记录来自 `source_thread_id 019f6817-7931-7e43-b2dd-69dedd3d9974` 的委派摘要，作为一次真实使用失败保存；本维护线程没有直接复核该源线程的完整原始对话或运行日志。它足以支持本轮增加防退化约束，但不能单独证明“缺少偏序必然导致同类失败”的普遍因果律。

在任务“让本体系被更多 GitHub 用户看到和使用”中，Agent 没有先从本体恢复合法依赖偏序，而是先列热点、用户画像和传播媒介，再按热度、匹配度和成本加权；本体、媒介、用户和结果因而被平铺成同级类别，Focus 被误用为任意重加权，根路径中被压缩的本体接口也失去了实际结构优先性。Agent 随后从对象兴趣向外展开，再反向给本体贴热点，产生了不能回溯本体具体命题或能力的无根路径。

该次运行所要求的最低根偏序至少是：

```text
本体
→ 本体价值显现
→ 可验证／可传播接口
→ 媒介
→ 对象匹配
→ 使用与反馈
→ 下一版本本体
```

同一传播任务随后暴露了第二类真实使用缺口：一次“全局展开两次＋Focus 两次”的输出只展示了进入模型的合法地址 $M_t$，没有展示运动中新暴露的 $R_t$ 与压缩前沿，因而在表现上退化成一棵能够完全闭合的静态分类树。该案例现在只作为内部校准，不进入公共 Skill 示例。校准时至少应区分：

- “看到／理解／使用”混在一起造成的旧失配，可通过展开不同功能环节吸收，不再作为剩余保留；
- 完整体系与快速传播之间的冲突，是聚焦运动可能暴露的结构差额；
- 聚焦 AI／RL 受众可能造成理论身份失真，是 Focus 新生产的剩余候选；
- GitHub 推荐算法不能由当前传播场独立保证，属于 `[∅]` 结果，必要时触发升场；
- 未被 Focus 选择的哲学节点仍是 `[◇]` 压缩前沿，不是剩余。

这次案例支持的是“每次运动必须审计剩余并显示前沿”的 Skill 设计约束，不证明所有复杂任务每轮都一定产生非空剩余。

本记录支持的结论仅是：当前 Skill 必须把偏序恢复、结构合法性闸门和根路径审计变成评分前的强制约束。它不证明传播热度没有价值，也不证明这套偏序已经适用于所有传播任务，更不构成技术收益的对照实验证据。

动态模型的技术价值需要通过具体任务检验，当前只提出有限假设：

- 是否减少无关上下文和重复读取；
- 是否更快从模糊目标形成有效 Focus；
- 是否降低跨轮任务中的目标漂移；
- 是否提高执行路径、证据和失败原因的可追踪性；
- 是否能在信息增长时局部更新，而不必重建全部上下文；
- 是否能以更少的数据读取或工具调用达到相同完成质量；
- 是否在多任务、深层级和强约束环境中比扁平提示词表现出更明显收益。

这些是假设，不是已经获得的实验结论。若动态模型只增加地址和说明成本，却不能改善任务完成、信息选择或局部修订，它就仍是解释层，而不是有效的计算工具。

## 十二、当前边界

- 不预设使用者一开始就知道正确 Focus；
- 不把一次初步展开误认为完整全景；
- 不把 Focus 改变误写成 F0 改变；
- 不把 Focus 当作从已完成全景中静态挑选地址，也不默认只选一条路径；
- 不把 Focus 主要展示为若干并列子场，或默认每个中心位置只有一个活动地址；
- 不把所有信息强行纳入当前场；
- 不把一次运动只展示为合法地址 $M_t$，而省略 `Frontier_t`、$χ_t$ 与剩余审计；
- 不默认剩余为空，也不为了形式强行虚构剩余；
- 不把单纯未展开、被 Focus 降低运行优先级的合法节点自动标成 `[∅]` 或剩余；也不因它位于前沿就删除与其关联的未吸收差额；
- 不因地址更长就认为节点更重要；
- 不允许局部执行偷换根目标；
- 不让探索无限持续而没有成本、边界和停止理由；
- 不把动态模型的哲学完整性直接当成技术性能证据。

## 十三、阶段性结论

目前形成的整体成果可以压缩为四层：

1. **哲学层**：具体中心可以失效，但形成、检验和重建相对中心的能力可以保留；
2. **方法层**：在需求限定的场内提取不可约功能骨架，并以递归地址组织对象和关系；
3. **动态模型层**：让全景、Focus、执行、证据和剩余形成持续更新的认识—行动闭环；
4. **工具层**：用 Skill 和状态文件驱动 AI 在真实任务中运行该闭环。

其核心传播句仍然是：

> 不是给世界一个永恒正确的中心，而是保留不断形成、检验和重建中心的能力。
