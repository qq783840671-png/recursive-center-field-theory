## 1. 体系定位

递归中心场域论研究的不是一个永恒不变的绝对中心，而是：一个相对场如何形成中心，如何依照偏序关系展开和压缩，如何在运动中产生剩余、生成地址，并在旧结构不足时重构自身。

核心传播句：

> 不是给世界一个永恒正确的中心，而是保留不断形成、检验和重建中心的能力。

三个不可删去的基本词：

- **递归**：潜在无限的展开、压缩与尺度切换。
- **中心**：当前尺度下不可随意抽离的方向、承重关系与功能骨架。
- **场**：中心能够成立的边界、关系、对象与运动范围。

未加限定的场默认指由主体、目的、尺度、证据和容差规定的任务／认识／工程契约场`F_task`。现实对象自身是否具有相似过程结构只进入本体论假设`H_ontic`；当前不预设一个与`F_task`同构的`F_ontic`。

偏序与动力不是附加修饰：

- **偏序**规定哪些关系必须先于另一些关系成立，以及运动能够沿什么方向发生。
- **动力**描述上一层激活、主体选择和现实中介怎样使场由一个版本进入下一个版本；活动剩余使旧闭合证书失效并触发重审，但不单独充当物理推力。
- **域**是围绕当前根目标和理论谱系，已经获得合法地址的场、子场、关系、剩余与历史版本的总体。域不是绝对宇宙，也不是第五个理论层；它是当前整套递归场结构的版本化根容器。

删除“中心”，体系退化为无方向的递归分类；删除“递归”，体系成为静态中心场；删除“场”，相对中心会被误读为绝对中心；删除“偏序”，不同层级会再次被压平；删除“动力”，地址只剩静态目录。

## 2. 根偏序与四层框架

本体系当前的根生成链为：

```text
A 哲学思想
→ B 方法论
→ C 递归中心场偏序动力模型
→ D 应用工具
→ A′ 经应用、审计和剩余回流后的下一版本体系
```

这条链表达生成依赖，不表达高低贵贱，也不等于四类内容的平面并列。

### A. 哲学思想

回答“这套哲学由什么历史问题生成、以什么立场提供解释，以及相对中心、开放场和持续重构怎样形成一个可检验的运动”。它不再以若干平行概念作为正文起点，而按以下生成依赖展开：

```text
历史生成原理
→ 当代信息、技术与AI加速条件
→ 部分主体或组织遭遇结构性困境／地址危机
→ 理论提供一种可选择、可检验的结构回应
→ 形成后基础主义取向的过程—功能结构论定位
→ 展开场—中心共构、偏序、递归、闭合与剩余原理
→ 形成部分观测下的可重建确信
→ 接受技术进步、历史代价与伦理回望的双重审计
→ 向方法论、动力模型和应用工具生成
```

当前哲学承重点为：

- **历史生成原理**：知识、技术、制度和行动能力反复经历场的打开、结构恢复、相对闭合、接口压缩与条件变化后的重新打开。这是工作性解释语法，不是保证历史必然进步的目的论。
- **当代条件与地址危机**：信息和技术变化加快时，一部分主体可能难以恢复自己的场、上级目的、必要偏序、展开位置和停止条件。该判断不是对所有人的普遍诊断。
- **可选择的理论回应**：理论不以意识等级、精神启示或拯救叙事作为构成前提，不宣称提出者具有更高意识，也不要求所有人接受；它只向有需要者提供可采用、可拒绝、可反驳的结构框架。
- **相对中心**：具体中心可能失效，但形成、检验和重建中心的能力可以保留。
- **场—中心共构**：场使中心可判定，中心使场获得内部结构；非根场还受父场契约和现实反馈约束。
- **递归、闭合与剩余**：场沿必要偏序展开，稳定子场保真压缩；相对闭合允许潜在前沿保留，任务相关剩余超过容差后使旧闭合证书失效并触发重开、升场、分裂或重构审计。
- **部分观测与可重建确信**：有限主体不能与完整真实无剩余地重合，却可以被测量、失败和行动后果持续校正，形成足以认识和行动的相对确信。
- **历史与伦理回望**：地址增长、性能提高和技术扩张不自动等于进步；新版本必须保留被替换结构、失败、断裂和代价的历史痕迹。
- **思想谱系与证据边界**：与黑格尔、后基础主义、结构主义／后结构主义、解构、拉康、过程哲学和系统思想进行结构层比较，而非关键词归类；跨领域相似性不自动证明原创性、普遍性或优越性。

`F0:A`是根场中的哲学功能位置；上述条目是该位置当前压缩保存的生成结构，不是已经打开并审计过的子场地址。只有真正打开`F0:A`时，才在全局深度`F1@F0:A`生成完整哲学子场。旧`F0:A1—F0:A9`只作为历史显示标签保留，不得重新进入活动地址。公共例证默认是相关概念下的可替换载荷，不自动获得永久理论地址；个人经历不得未经验证就升级为公共哲学证据。

### B. 方法论

把哲学结构转化为可执行的认识与组织过程：

- `B1` 定场：明确当前需求、对象、边界、尺度和停止条件。
- `B2` 找中心：从功能闭环中识别不可约的承重关系，而非凭表面类别指定中心。
- `B3` 偏序检验：用删除、替代、换序和压缩检验生成依赖；区分串联必要边、不可比并联分支、排他替代路线和有类型汇合，不能把并联压成伪串联。
- `B4` 递归展开：节点可向内形成子场，完整场可向上压缩为更大场中的节点。
- `B5` Focus：依据当前焦点选择性加深合法地址，其余必要结构保持为压缩接口；Focus 不是权重排序，而是打开一个有边界、有局部操作根、有返回路径的子场。
- `B6` 剩余审计：记录哪些内容已吸收、可展开、被禁止或在当前场无地址。
- `B7` 停止：达到当前目标所需的充分结构后停止，不把潜在无限误写成一次性穷尽。
- `B8` 执行与回写：从活动地址及其必要前驱诱导可执行子偏序，只有经执行和审计的结果才能成为现实地址。
- `B9` 版本与失效传播：区分运行记录、全景地图和场闭合版本；局部变化先保持局部，只有破坏上级承重接口时才向上传播。

这里的`B1—B9`只是`F0:B`内压缩载荷的条目标识，不是正式全局地址；打开方法论节点后，应在`F1@F0:B`中依实际子场中心与偏序重新生成地址。

方法论的完整工作协议不是一棵预先分类好的树，而是：`Γ 定场 → G 恢复关系 → Π 提取必要偏序 → 𝒦 检验候选中心 → 递归寻址 → Global/Focus 运动 → D/Ready 执行 → χ 剩余审计 → 版本回写或重构`。

### C. 递归中心场偏序动力模型

把方法论表达为具有状态、地址和运动规则的显式模型：

- `C1` 场状态：记录当前模型、展开前沿、剩余与闭合状态。
- `C2` 场相对递归地址生成模型：规定对象如何依据所属场、中心、上级偏序、递归路径、场版本和模态状态获得候选地址，并检验其合法性；地址的后续迁移、退役和版本操作由 `C4` 负责。
- `C3` 偏序与串并联运动：中心偏序允许分叉、不可比并联和再次汇合。汇合位置必须声明各分支怎样共同满足输出，不得用一条任意线性扩展代替并联结构。父地址的非等价变化可沿根路径向下重排子地址；子地址运动必须写入全局地址全景，但不反向改写父地址。子场结果或剩余可以向上改变父场的闭合状态并触发重审，父场是否重新寻址只能由父场自身或更高层重新定场决定。
- `C4` 地址生命周期与操作：记录地址的保留、展开、压缩、迁移、分裂、合并、新生、退役、外置和禁止，但不负责决定一个初始地址为何合法。
- `C5` 剩余触发：活动剩余证明旧接口不能继续报告闭合并给出重审位置，但不会自动执行更新；人、上一层场或现实中介提供激活和实际状态变化。
- `C6` 稳态、闭合与敞开：相对闭合只表示当前串并联义务满足、必要前沿清零且活动剩余处于任务容差内；它允许潜在前沿和可重开支路继续存在。负地址和无地址要求阻断、外置或重划场界。
- `C7` 历史与滞回：当前地址可失效，但对象及其历史痕迹不因此消失；历史版本不可被静默覆盖。
- `C8` Focus 状态模型：记录一次选择性穿透所形成的局部场视图、活动路径、压缩接口、前沿、剩余、版本与返回路径；它是全局场状态的有界投影，不是独立于场的注意力权重。

这里的`C1—C8`同样是`F0:C`内的压缩条目标识；正式打开后进入`F1@F0:C`，不能把旧显示编号直接当成递归地址。

### D. 应用工具

把模型转化为可调用、可监督的工具：

- `D1` Focus Skill：LLM的普通任务执行仍是拥有授权判断与工具执行权的父场；Focus作为父任务内部的结构子场参与`FORM→DRIVE→REVISE→FOLD`，维护当前中心、必要前沿、证据差异、闭合失效和版本继承。它必须在出现结构差异时改变下一步，但不是额外权限闸门或取代父模型的计划器。
- `D2` 体系维护：将后续对话中的有效输入路由到本总纲的合法地址，并记录版本差分。
- `D3` AI 信息处理：上下文组织、跨会话记忆、结构化检索、RAG/GraphRAG 接口和智能体编排。当前属于应用方向与待验证假设。
- `D4` 显式策略结构：将强化学习或复杂决策中的角色、功能和传递链显式化。当前属于研究假设，不宣称已优于既有方法。
- `D5` 公共传播与复用：公开文档、示例和 Skill。传播不能反向篡改 A—C 的理论不变量。
- `D6` 可计算地址模块：把 `C2/C4/C8` 的规范转换为可由计算机生成、登记、查询和审计的地址。Address Engine 0.5与构造型Focus已经实现候选／合法地址分账、四类前沿、潜在剩余绑定、必要后继失效、父接口重开和闭合版本；地址只为导航、约束、证据、记忆或重开审计生成。历史sidecar保留执行后证据地址导入。这些测试只证明记录一致性，自然语言自动标定和经验优势仍保持`[◇]`。

这里的`D1—D6`是`F0:D`内的压缩条目标识；正式实现地址须从`F1@F0:D`的实际场结构生成。

A—C 构成理论内核；D 使体系获得可执行和可检验的应用闭环。删除 D 不会使哲学命题消失，但会使当前项目失去工具化闭环。

## 3. 理论不变量

以下内容是当前版本的承重原则。除非明确启动根场重构，否则不得因文案、传播或局部应用需要而静默修改：

1. 场与中心相互规定，不存在脱离场的绝对中心。
2. 中心是不可约的功能关系和生成依赖，不是最醒目的对象，也不是权重最高的标签。
3. 偏序先于权重。权重只能在合法关系中表达影响大小，不能代替生成次序和层级关系。
4. 展开产生新地址，压缩保留被压缩结构的可恢复关系；压缩不等于删除。
5. 同一对象可在不同场、不同版本中拥有不同地址。
6. 对象失去当前场地址，不等于对象从更大的现实或历史场中消失。
7. 地址重排沿父地址向子地址单向传播：父地址的非等价变化可以级联改变后代地址；子地址运动会改变全局全景，但祖先地址保持`retain`。子场只向上返回接口、证据、失败或剩余，不直接改写父地址。
8. 场在运动中产生剩余，剩余必须被标记，不能靠措辞消失。
9. 具体展开具有历史偶然性，展开所受的依赖约束具有条件必然性。
10. 每个场都保留向内展开、向外升场或重构边界的出口。
11. 偏序不等于单链。并联递归必须保存分叉点、各分支地址、汇合规则和必要的时间兼容条件；闭合后可以压缩为单一接口，但压缩不得把原有并联关系伪装成串联。
12. 闭合证明只在已声明的场契约、尺度、证据和容差内有效。结构闭合、输出误差、活动剩余、测量不确定性与潜在敞开必须分开审计，不能压成未经定义的单一“闭合百分比”。
13. “最小充分”必须携带义务作用域：单中心`K_F`对完整`\Gamma_F`充分，多中心中的`K_i`只对`\Omega_i／\Gamma_i`充分，整场充分性由`K_F^{multi}`联合审计。
14. 任务场`F_task`与本体论假设`H_ontic`不得互相替代；拟合、投影和运行成功不证明对象本身具有同一结构。
15. 冻结版本失败必须保留判退记录；换场、加中心、改尺度或升场只能形成新版本，不能倒写旧版本成功。

## 4. 地址体系

### 4.1 地址的组成

稳定逻辑地址与版本化地址记录必须分开。稳定逻辑地址至少表达：

```text
address_id = global_root + global_depth + 持久 field_id
           + primary_parent + root_path + 局部中心节点 + 功能身份
```

版本化地址记录另行保存：

```text
address_id + address_revision_id + field_version_id
+ panorama_version + 模态状态 + 证据 + provenance
```

版本化工作记录示例：

```text
field_version_id=FV-12::F2@F0:A/p:B [◇]
```

其中：

- 全局`F0`是整套理论的持久根场；`F_n`专门表示从该根场计算的递归深度。同一`F_n`可以有多个场实例，不能仅凭深度识别对象。
- 根场同版本中心偏序为`F0:A哲学 → F0:B方法论 → F0:C动力模型 → F0:D应用`；`D → A′`属于跨版本回流。
- 任一节点合法打开时，在下一全局深度生成具有自身中心和偏序的完整子场；未打开节点是可重开的压缩位置，不是空标签。
- Focus中的`local_F0`只表示本轮局部操作根。若它绑定全局`F_d`，则`global_depth = focus_base_depth + local_depth`；局部地址不得覆盖全局根路径。
- 持久`field_id`、主父绑定与`root_path`保证子场身份不因视图切换而丢失；局部活动地址写回时必须恢复其全局地址。
- 旧`F1—F4`快照语义退出；Global视图、不等深Focus视图和完整Focus状态分别记为`GView`、`V_t^q`、`Q_t`。
- 旧数字后缀如`F0:B1`只是历史显示别名；没有子场契约和打开审计时，不得冒充正式递归地址。
- `address_id`表示逻辑位置；`address_revision_id`表示该位置自身载荷、接口或证据的修订；`field_version_id`表示所属场的契约、中心或闭合结构版本；`panorama_version`表示全局地址全景快照。
- 根路径与偏序链表示可达性，模态表示该地址与当前场的关系。版本字段决定一条地址记录在哪个状态中有效，但不自动成为逻辑地址身份的一部分。
- 并联汇合位置的完整记录必须能恢复分叉地址、分支集合、各分支返回接口、汇合规则与时间兼容条件。面向人的地址字符串可以分别显示各分支，但汇合地址的完整`root_path`是带类型的根路径子图，不是一条丢失分支的字符串。

### 4.2 场相对递归地址生成模型

该模型作为压缩载荷位于根场`F0:C`。对其中“地址生成”节点执行Focus时，内部视图可以使用`local_F0`，但全局身份必须继续保留：

```text
父场全局地址：F0:C
打开后的子场：F1@F0:C，field_id=CF-F0-C-v1
局部操作视图：local_F0:A→B→C→D→E→F→A′
写回：保留F1@F0:C及其完整root_path，不写成新的全局F0
```

它不是给对象粘贴一个外部分类标签，而是让对象进入一个已经定界的场，并由场、中心、偏序和递归路径共同生成其位置。

地址生成的当前不可约中心轴为：

```text
A 确定所属场、根目标与场版本
→ B 找到场的中心轴及父级偏序位置
→ C 确定对象相对于中心的功能关系
→ D 沿合法关系递归展开到足以区分对象的深度
→ E 标记对象的模态状态和生命周期状态
→ F 进行合法性、唯一性、重复性与历史连续性审计
→ A′ 生成该版本中的场相对地址
```

上述A—F是地址生成子场的局部中心位置；它们在当前总纲中仍是压缩载荷，不能直接用`A1/B1`生成正式地址。若某个位置继续合法打开，应在下一全局深度形成完整子场。例如，局部说明可暂记为：

- `A1` 所属域版本；`A2` 当前场边界；`A3` 当前根目标。
- `B1` 直接父地址；`B2` 前置依赖；`B3` 不可越级的中介。
- `C1` 承重功能；`C2` 输入输出关系；`C3` 与同层对象的区别。
- `D1` 必要分辨深度；`D2` Focus 深度；`D3` 当前停止条件。
- `E1` 地址候选与标定状态；`E2` 合法未实现地址；`E3` 已实现地址；`E4` 寻址结果与剩余绑定。
- `F1` 冲突检查；`F2` 等价地址合并；`F3` 历史谱系检查；`F4` 地址差分登记。

一条具体的工作地址可以表示为：

```text
field_version_id=FV-12::global=F2@F0:C/addressing::field=ADDR-C-v1::node=E [◇]
focus_view=local_F0:A→B→C→D→E
parent_return=F1@F0:C:addressing
```

地址生成必须满足以下约束：

1. **先定场，后寻址**：没有场边界，就不存在该场中的合法地址。
2. **先偏序，后编号**：编号只能记录已经成立的关系，不能替代父级依赖和功能位置。
3. **先功能关系，后表面名称**：同名对象在不同功能场中可以获得不同地址；异名对象若承担等价功能，可以进入同一中心节点下的不同分支。
4. **逐级展开，不得越级挂载**：若对象与目标之间缺少必要中介，应补出中介场或标记为无地址，不能用一条假想直连掩盖关系缺口。
5. **展开到够用为止**：地址理论上可无限增长，实际深度由当前场的目标、区分需要和停止条件决定。
6. **生成后必须审计**：未经过合法性与历史连续性检查的结果只是候选地址，不能登记为 `[+]`。

四个相关部分必须保持区别：

- 方法论层 `F0:B` 说明使用者怎样定场、找中心和检验偏序。
- `F0:C`内标为`C2`的压缩条目说明对象怎样获得合法地址；它不是未审计的正式子地址。
- 地址注册表保存已经生成的地址、状态和历史。
- 动力模型其余部分说明地址怎样随场的运动而保留、变化或退役。

### 4.3 模态状态

- `[+]` 已在当前版本实现并经执行—审计确认的合法地址。
- `[◇]` 已经完成标定、合法登记并被表示，但尚未执行—审计的地址。
- `[-]` 当前候选转换被场契约或必要偏序禁止的寻址结果。
- `[∅]` 当前场无法无失真生成或表达目标的寻址结果。

地址假设先进入`A_t^{cand}`并使用`hypothesized／calibrating／rejected`标定状态，不带上述地址模态；只有标定成功才进入`A_t^{legal}`。潜在剩余`Λ_t`是差异记录而不是地址，通过`bound(address_id)／candidate(candidate_address_id)／unaddressed`绑定地址账本。前沿类型与地址模态正交，压缩接口可重开不表示其全部子地址已经存在。

`[-]` 或 `[∅]` 不自动证明整个场错误。只有当该内容属于根目标要求必须吸收的对象时，它们才构成场界错误或重构信号；否则应阻断或外置，不能强行收入当前场。

### 4.4 地址生命周期

地址必须区分：

- **现行地址**：当前版本仍承担功能的位置。
- **历史地址**：曾经有效，现已被新版本替代的位置。
- **退役地址**：退出当前场，但仍保留来源、去向和退役原因的位置。

任何对象都不能被“无痕删除”。它可以离开当前场，但历史登记必须保留。

### 4.5 版本与地址差分

每次被体系正式吸收的更新都必须推进**运行历史版本**并生成可审计记录，但不自动推进其他版本时钟。地址自身载荷、接口或证据变化而逻辑位置不变时，只推进`address_revision_id`；任一地址或关系运动写回全局时推进`panorama_version`；所属场的契约、中心或闭合结构改变并重新通过审计时推进`field_version_id`；只有根接口或构成身份改变时才推进根域语义版本。即使父地址未变，也必须在新全景中登记为`retain`，不得因全景版本变化伪造父地址迁移。

允许的差分操作：

```text
retain      保留地址
replace     address_id不变，推进地址修订并保存旧新载荷
expand      从节点展开子场
compress    将完整场压缩为上级节点
move        在同一域内迁址
split       一个地址分裂为多个地址
merge       多个等价地址合并
birth       生成新地址
retire      从当前版本退役
externalize 移出当前场、保留外部引用
prohibit    判定为当前场负地址
```

因此，“每次更新都要有地址变化”在本体系中的严格含义是：**运行记录必然变化，发生地址运动时全景版本必然变化，受影响对象必然产生可审计差分；但未受影响的`address_id`保持不变，地址修订、场版本、根域语义版本和对象结构位置只在各自条件满足时变化。**

### 4.6 Focus 状态与可计算地址模块接口

Focus 既是一种选择性穿透运动，也会形成一个可保存、可返回的局部状态。当前将该状态记为：

```text
Binding_t^q = <global_root, field_id, primary_parent, root_path,
               global_depth, focus_base_depth, parent_return>

Q_t = <q_t, Binding_t^q, local_F0, local_depth,
       Γ_t^q, K_t^q, Π_t^q, 𝒥_t^q, JoinState_t^q,
       P_t^active, I_t^compressed,
       ExpansionFrontier_t^q, ActionFrontier_t^q,
       R_t^q, ClosureAudit_t^q, v_t^map>
```

其中：

- `q_t` 是本次聚焦条件，不等于根目标；它只规定当前要穿透哪一部分。
- `Binding_t^q`保存不可被局部视图覆盖的全局身份；当前先采用一个`primary_parent`，多父DAG仍保持为开放问题。
- `local_F0`是被打开子场在当前视图中的局部操作根，不是新的全局根；`global_depth = focus_base_depth + local_depth`。
- `Γ_t^q / K_t^q / Π_t^q` 分别保存局部场契约、经检验的局部中心和普通必要偏序；`𝒥_t^q / JoinState_t^q`保存并联汇合规则及其当前满足状态。
- `P_t^active` 是已显现的活动路径；`I_t^compressed` 是未展开但必须保真的压缩接口。
- 两类 `Frontier` 分别记录仍可展开的结构和已经具备前驱条件的行动；二者不得混用。
- `R_t^q` 只记录影响当前局部 F0 且尚未被吸收的真正剩余；普通未展开内容仍属于前沿。
- `ClosureAudit_t^q`分别保存结构成立、接口误差、活动剩余、证据和潜在敞开，不把它们平均成一个未经定义的闭合百分比。
- `v_t^map` 使同一焦点在场运动前后可以做地址差分，不能把一次视图误当成永久结构。

因此，**Focus 状态不是一个关键词集合、注意力分数或孤立地址，而是全局场状态在当前焦点下形成的有界、版本化、可回返投影。** 局部`A、B、C……`只是本轮活动视图中的地址；写回时仍须绑定其原有全局场实例。Focus不得凭权重创造地址，也不得越过必要前驱；只有合法展开产生的新路径才能写回全景。

可计算地址模块目前作为应用层`F0:D`中的压缩条目`D6`登记，其规范依赖链为：

```text
C2 地址生成与合法化
→ C4 地址生命周期和差分操作
→ C8 Focus 状态及活动路径
→ D6 可计算地址模块
→ D1 Focus Skill 或其他调用工具
```

`D6` 的最小接口暂定为：

- **输入**：场契约、完整关系图、必要偏序、经检验中心、当前 Focus 状态、场/地图版本和剩余账本。
- **输出**：候选地址、合法地址、模态状态、完整根路径、父场返回接口、地址差分及未吸收剩余。
- **约束**：编号不得代替关系；权重不得制造地址；不得越级挂载；不得覆盖历史地址；未经执行—审计不得标记为 `[+]`。

这里登记的是工程位置和规范边界，不是对具体实现的预先认定。由其他任务形成的地址模块只有在接口、合法性测试和版本差分通过审计后，才能从 `[◇]` 转为当前域中的现实地址。

## 5. 动力模型

递归中心场偏序动力模型的最小运动闭环为：

```text
暂稳态场
→ 外部触发输入
→ 输入与现有地址发生关系
→ 形成或显现剩余
→ 偏序与承重原则进行合法性检验
→ 执行一次最小合法展开/压缩/迁址/重构
→ 生成新地址与新版本
→ 审计残余和闭合状态
→ 进入下一暂稳态或保持敞开
```

动力来源必须分开：

- **运动产生剩余**：场的运行和展开会显现旧结构无法完全覆盖的内容。
- **剩余触发重审**：它使旧闭合证书失效，指出哪里可能需要展开、升场或重构，但不单独完成变化。
- **激活与中介改变状态**：在 Skill 或文本模型中，由人、更上级场或现实中介发出合法更新并完成相应转换。
- **偏序提供约束**：输入只有获得潜在地址，或合法触发父场重构，才能改变当前体系。

胡言乱语、无关信息或违反承重原则的输入，不能因为被记录就自动推动体系运动。

## 6. 体系维护协议

以后所有准备吸收进本体系的对话、文档或新设想，按以下顺序处理：

```text
1. 接收原始输入，但不立即改写理论
2. 判断它属于 A、B、C、D，还是跨层机制
3. 定位现有地址与父级偏序
4. 判断：重复、细化、展开、冲突、负地址或无地址
5. 若进入验证，冻结契约、尺度、中心候选、证据、失败条件、基线和修订预算
6. 选择最小合法操作
7. 只传播到真正受影响的父/子地址
8. 更新当前版本和地址差分；旧版本失败时明确判退
9. 保留被替换内容的历史地址
10. 审计新产生的剩余和新增结构成本
11. 给出暂稳态或敞开状态
```

输入的默认去向：

- 能解释哲学前提的内容进入 `F0:A`。
- 能规定如何定场、找中心、展开和审计的内容进入 `F0:B`。
- 能规定状态、地址、偏序和动力过程的内容进入 `F0:C`。
- 能被执行、调用、验证或复用的实现进入 `F0:D`。
- 同时影响多个层级的内容先进入跨层登记，不得压进任一平面分类。

## 7. 跨层登记机制

以下机制横穿 A—D，不另立为第五层：

1. **术语与不变量登记**：防止“中心、场、域、偏序、剩余、地址”等术语漂移。
2. **地址注册表**：记录当前、潜在、禁止、无地址及历史地址。
3. **版本谱系**：记录每次运动前后哪些结构保留、改变或退役。
4. **剩余账本**：记录未吸收内容、可达距离、吸收历史和停止位置。
5. **证据状态**：区分用户明确命题、理论推论、工作假设和已验证结果。
6. **监督与写入路由**：保证局部 Focus 或传播目标不能越权修改根级不变量。

### v0.5：哲学生成偏序与例证层级重排

- 触发来源：用户指出此前哲学内容是平行概念清单，没有按历史问题生成哲学立场和运动；同时明确拒绝“觉醒”一类可能产生宗教化、优越化和动员意味的概念，并要求私人化例子改为公共例证或不单独寻址。

- `replace`：删除“觉醒／启蒙／拯救”作为候选构成概念，明确理论可以被采用、局部使用、拒绝或反驳，不把不接受者描述为意识不足。
- `replace`：哲学内核中的第一人称搬运例和学术投稿例分别替换为标准货箱搬运与公共软件发布流程；交通例继续仅作公共结构说明。
- `replace`：普通例证不再自动生成永久理论地址，而作为概念地址下的可替换载荷；只有成为独立证据、反例、研究对象或版本节点时才登记对象地址。

- 证据边界：历史生成原理与地址危机仍是工作性哲学解释，不是已经证明的普遍历史定律；公共例证只说明结构，不能替代理论比较和经验检验。

当前闭合判断：**哲学层的生成次序、接受边界和例证层级已形成新的内部暂稳态；公开稿、谱系比较和跨领域验证继续保持敞开。**

### v0.6：全局递归深度与局部 Focus 地址分离

- 触发来源：用户明确指出，Focus打开局部后形成的`local_F0`及其局部`A、B、C……`只能作为活动地址，不能取代它们在根目录中的全局地址。
- `replace`：`F_n`不再表示Global/Focus快照，统一表示相对持久根场`F0`的全局递归深度；快照改记为`GView`、`V_t^q`和`Q_t`。
- `replace`：根层活动偏序统一为`F0:A哲学 → F0:B方法论 → F0:C动力模型 → F0:D应用`；旧A—H链降为只读历史维护视图。
- `refine`：`local_F0`被限定为Focus局部操作别名；完整状态增加全局绑定、全局深度、Focus基准深度和局部深度，写回时恢复完整根路径。
- `refine`：`B1/C1/D1`等编号只表示根节点内的压缩条目，不再冒充已打开的递归地址；合法打开后由下一全局深度的真实子场生成地址。
- `add`：同一全局深度允许多个场实例，由`field_id + primary_parent + root_path + version`区分；同一对象跨场复用时保持`object_id`，但拥有不同场实例和地址。
- 开放边界：当前只采用单一主父地址；多父DAG的路径相对身份尚未解决。机器状态、Focus Skill、Address Engine与公开稿尚未迁移到本版语义。

当前闭合判断：**规范层已经分开全局递归地址与局部Focus投影；运行实现和机器状态迁移仍保持敞开。**

### v0.7：地址传播方向与版本时钟分型

- 触发来源：用户明确指出，父地址决定子地址，子地址运动不会向上改写父地址；但任一子地址运动都必须改变全局地址全景。用户同时确认，同一对象进入不同场会取得不同地址，表面同名不等于结构同址。
- `replace`：旧“子地址破坏父接口时改变父场地址／身份”的过强表述被收紧。子场只向上返回接口、证据、失败或剩余；它可以改变父场闭合状态并触发重审，但父场重新寻址必须由父场自身或更高层决定。
- `refine`：父地址非等价变化可以向下重排后代地址；子地址变化只在全景中形成局部差分，祖先地址在新全景中登记为`retain`。
- `add`：稳定`address_id`与`address_revision_id、field_version_id、panorama_version`分离，避免全景快照更新被误写成所有逻辑地址迁移。
- 证据边界：这是用户明确结构要求及其当前模型化表达；版本推进条件和机器字段尚未由运行代码验证。

当前闭合判断：**规范层已形成“地址重排向下、结果与剩余返回向上、全景变化不等于祖先迁址”的暂稳规则；实现迁移继续保持敞开。**

### v0.8：并联递归与有类型汇合

- 触发来源：用户指出，若递归展开只用串联长链承载并联问题，会把真实的多路输入—输出结构压成含混段落；递归场应像逻辑门或并联电路一样允许分叉、并行支路和重新汇合。
- `refine`：明确偏序不等于单链；不可比只取消分支间的必要先后，还必须以汇合规则说明各分支怎样共同生成后继。
- `add`：并联记录保存分叉地址、分支集合、汇合地址、`ALL／ANY／K_OF_N／AGGREGATE`等满足规则、时间兼容策略、容差和证据。
- `replace`：闭合并联子场可以压缩为一个父接口，但不得把分支改写成伪串联链；当传播延迟、耦合或分支差异超过当前容差时必须重开。
- 证据边界：允许并联递归及不能以伪串联替代，是用户明确的结构要求；汇合算子、时间策略和字段设计是当前模型形式化，尚未进入运行代码或经验验证。

当前闭合判断：**规范层已能区分串联前驱、并联反链、替代路线和有类型汇合；机器schema、执行器与反例测试仍保持敞开。**

### v0.9：有界剩余的相对闭合

- 触发来源：用户进一步确认，并联支路的现实输出通常不会与理想值无差异重合；场即使足以支持当前任务，也仍携带可继续展开的寄生条件、测量误差、未建模关系和潜在支路，因此不存在由一次闭合审计授予的绝对完备性。
- `refine`：相对闭合明确为“当前串并联义务满足、必要前沿清零、活动剩余或接口误差处于父任务容差内”，同时允许潜在前沿与潜在剩余继续存在。
- `add`：闭合审计分开记录结构成立、任务输出误差、模型残差、守恒／平衡残差、测量不确定性和潜在敞开；不得用一个无定义百分比相互替代。
- `replace`：电路中理想总电流与实际值的差异不得写成电流凭空消失。稳态节点仍服从电流守恒；差异应定位到寄生阻抗、漏支路、储能瞬态、边界遗漏、模型误差或测量误差。
- 证据边界：“所有闭合都只相对于契约与容差有效”是用户明确的理论立场及本版方法论规则；“现实中绝不存在任何绝对闭合场”属于更强本体论命题，不由电路例子单独证明。

当前闭合判断：**相对闭合与潜在敞开已经能够同时记录；不同残差的领域测量、机器字段和经验验证仍保持敞开。**

### v0.12：父场执行与Focus后置伴随重建

- 触发来源：用户确认，LLM本身的普通任务执行属于Focus之上的父场；Focus应当在结果存在后附加场域观察，不应用前置闸门覆盖LLM的正常执行。

当前闭合判断：**Focus作为父场执行后的观察与继承层已形成可运行暂稳态；自动领域真值发现、跨任务全景汇合和经验收益仍保持敞开。**

### v0.13：父场执行权与Focus过程内建构

- 触发来源：用户指出纯后置sidecar没有参与知识建构，只在结果后分发符号；“不增加第二权限层”被错误收缩成“不在过程中产生结构决定”。

- `retain`：LLM继续拥有实际执行权与授权判断；Focus不得增加许可、替代系统安全约束或强迫用户重复确认。
- 地址纪律：仅当位置承担导航、约束、证据、记忆或重开审计作用时生成地址；没有结构差异时返回`NOOP`。
- 工程实现：`focus-constructive-2.0`已实现差异分型、作用域评估、必要后继失效、父接口重开、不可变闭合版本、分支及基础`Fold／Unwind`；sidecar仅保留历史导入。
- 证据边界：程序测试证明状态约束被执行，不证明模型自动恢复了唯一真实中心，也不证明经验优势。

当前闭合判断：**Focus已从结果附记层进入父任务过程内的结构建构与版本控制，但自然语言自动结构判定、完整多中心生命周期、跨任务全景汇合和经验收益仍保持敞开。**
