# 动态地址生成与运动协议

> 版本：v0.10-draft（2026-08-26）
> 用途：把《递归动态寻址理论》转换为可实现、可校验和可审计的协议候选。本文不宣称当前代码已经支持全部字段和操作。

## 一、协议目标

本协议回答四个问题：

1. 一个候选地址需要保存哪些字段；
2. 地址怎样被赋予、标定和判为合法；
3. 场运动怎样生成、改变或退役地址；
4. 每次运动怎样保存证据、剩余和版本谱系。

## 二、地址候选与合法地址记录

汇合规则作为场结构记录独立保存，地址只引用它：

```yaml
join_rule_id: stable rule id
field_id: owning field
parallel_group_id: stable group id
fork_address_id: null
branch_address_ids: []
join_address_id: null
gate_type: ALL | ANY | K_OF_N | AGGREGATE

  tolerance: null

```

`gate_type`是通用满足语义，不把所有工程关系强行布尔化；数值守恒、融合、阈值或连续动力关系通过`AGGREGATE + aggregate_contract_ref`保存。并联也不默认严格同时，时间兼容性由`temporal_policy`明确。

汇合地址可以有多个场内入支前驱，但仍只有一个所属场的`primary_parent`；多入支关系与多父场身份不得混同。

```yaml

center_system_version: current center-system version

field_version_id: valid field version

  quota_k: null
  aggregate_contract_ref: null

```

`ANY`通常用于候选中心或替代实现的选择；未选候选不进入当前`active_center_ids`。只有至少两个活动中心分别承担不可替代闭合义务，且没有接口等价单中心能够无失真替代全部中心时，才把场标为`multi-center`。普通并联、多视角、多对象或多载荷不能据此自动升级。

Focus局部坐标不写进上述持久全地址以取代全局身份，而保存在单中心投影绑定中：

```yaml
focus_binding:
  focus_state_id: null
  global_root_id: null
  field_id: null
  source_field_version_id: null
  source_center_system_id: null
  source_center_system_version: null
  focus_base_depth: 0
  local_depth: 0
  local_display_address: null
  selected_center_ref: null
  peer_center_refs: []
  projection_certificate_ref: null
  parent_return: null
```

必须满足`global_depth = focus_base_depth + local_depth`。`local_F0`只是`local_depth: 0`的显示别名。

`selected_center_ref`是当前执行Focus偏域唯一的已激活运行中心；`peer_center_refs`只保存未选中心、候选中心或压缩中心接口的必要引用，用于回到完整场、切换中心和失效审计。它们不进入当前中心偏序、`Ready_t`或执行队列。完整场地址可以有多值`center_membership`，但一次Focus不得据此生成多中心联合运行态。候选中心只能进入不产生任务`Ready_t`的形成／审计投影。

投影证书和返回记录独立保存：

```yaml
projection_certificate_id: stable projection certificate id
source_field_version_id: null
source_center_system_id: null
source_center_system_version: null
selected_center_ref: null
required_peer_interfaces: []

```

```yaml
focus_return_id: stable focus-return id
projection_certificate_ref: null
selected_center_closure: open | relatively-closed | invalid
outputs: []
evidence: []
peer_interface_effects: []
residuals: []
reprojection_request: none | switch-center | refresh-projection | ascend
```

`selected_center_closure: relatively-closed`不产生完整场闭合证书；完整场必须重新审计全部活动中心签名、跨中心关系和联合闭合规则。源场版本、中心系统版本或任一投影假设失效时，当前Focus绑定失效并请求重投影。

四个字段不得互相替代：

- `address_id`只在功能身份、主父绑定或根路径改变时迁移；
- `address_revision_id`在同一逻辑地址自身载荷、接口或证据修订时推进；
- `field_version_id`在所属场契约、中心或闭合结构形成新版本时推进；
- `panorama_version`在任一地址或关系运动写回全局全景时推进。

子地址运动可以只推进子地址修订和`panorama_version`；祖先地址及其修订在新全景中登记为`retain`。

分支返回使`join_state`或汇合证据变化时，推进相关汇合地址的`address_revision_id`和`panorama_version`，不自动迁移父地址。`join_rule`、分支义务或汇合功能发生结构变化时推进`field_version_id`；只有功能身份、主父绑定或根路径随之改变时，相关`address_id`才迁移。

中心归属、中心关系、中心状态或中心级汇合证据变化时，推进相关地址的`address_revision_id`、`field_version_id`和`panorama_version`。若场身份、主父绑定、根路径和功能身份未变，稳定`address_id`保持不变。一个位置服务多个中心时只保存一个地址记录和多值`center_membership`，禁止按中心复制逻辑地址；地址级`modal_status`不得自动覆盖各归属项的`obligation_status`。

机器实现可以使用不同字段名，但不得混淆对象身份、地址身份、显示路径、模态和版本。`contribution_annotation`是可选决策元数据，不参与地址存在性证明；没有分解契约和证据时保持空值，不得为了排序补造数值。

禁止或无地址结果使用独立记录，而不是伪造一个合法地址：

```yaml
addressing_result_id: stable result id
candidate_object_id: null
candidate_transition: null
result_status: prohibited | no-address
modal_result: "[-]" | "[∅]"
nearest_related_address: null
target_address: null
reason: null
evidence: []
residual_id: null
proposed_destination: prohibit | expand | ascend | rebuild | externalize
```

## 三、显示地址与完整地址

面向人的显示地址可以使用：

```text
F0:A
F1@F0:C/x
F2@F0:C/x/y[◇]

Focus视图：local_F0:x → local_F1:y
```

显示规则：

- 全局`F0`始终表示当前地址域的持久逻辑根层；Focus不得重写它；
- `F_n`只表示相对全局根的递归深度，不表示唯一场实例；
- 同一深度的场实例由`field_id + primary_parent + root_path + version`区分；
- 根字母表示当前场中心或结构位置；下一深度只由完整子场的实际递归打开产生；
- 不等长地址允许同时存在；
- 同一根字母下允许多条活动地址；
- `local_F_n`只用于Focus投影，写回时必须恢复全局地址；
- 模态可以显示，但不构成地址身份；
- 版本、证据和完整根路径保存在记录中，不全部塞入字符串。

## 四、赋址流程

### 4.1 输入

```text
对象或关系 x
＋ 当前场 F
＋ 场契约 Γ
＋ 父场绑定与返回义务 B_parent（非根场）
＋ 完整关系图 G
＋ 必要偏序 Π
＋ 候选或选定中心 K
＋ 必要／潜在展开前沿 P_req／P_latent
＋ 当前版本 v
＋ 证据 E
```

### 4.2 候选生成

1. 确认 `object_id`，不得用地址字符串代替对象身份；
2. 确认`global_root_id`，判断对象是否与该根场相关；
3. 确认根场已稳定；有实质歧义时先完成候选`F0^◇ → 授权确认 → F0^+`的形成场运动；
4. 确定当前场实例的`global_depth`和`field_id`；
5. 确定候选`structural_role`及有类型`relation_roles`；若位于并联结构，还要恢复分叉、并联组、分支或汇合身份；
6. 非根场绑定唯一`primary_parent`、功能义务、闭合要求和`parent_return`；
7. 从全局F0恢复完整根路径；
8. 附加所有必要前驱或有效压缩接口；
9. 保存非偏序关系及其类型；若多个不可比分支重新汇合，创建或引用`join_rule_id`，不得只把分支列为普通前驱；
10. 若打开下一层场，令子场`global_depth = parent.global_depth + 1`，并记录子场身份及对父偏序位置的代入关系；
11. 依据父场闭合义务登记`expansion-required`或`expansion-latent`；若前驱就绪可另登记`action`；
12. 生成`address_id`及初始`address_revision_id`、全局显示地址和`provenance`；Focus局部显示另存为投影；
13. 地址假设先生成`candidate_address_id`且不带模态；标定通过并进入合法全景后初始模态才是`[◇]`，不得默认`[+]`。

### 4.3 标定

候选地址逐项通过：

```text
场相关性
→ 对象身份一致性
→ 功能角色证据
→ 父场绑定与返回义务
→ 根路径完整性
→ 必要前驱或接口有效性
→ 关系类型正确性
→ 权限与边界
→ 版本兼容性
→ 模态与证据一致性
→ 前沿类型与进入理由一致性
```

只有全部承重条件通过，地址才能进入合法全景。部分条件未知时保存在`A_t^{cand}`并标记`hypothesized`，不得隐藏未知项或预配`[◇]`。

## 五、地址合法性闸门

一个地址 `a` 在版本 `v` 中合法，当且仅当：

1. `address_id`、`address_revision_id`、`global_root_id`、`global_depth`、`field_id`与`goal_contract_id`可追溯；
2. `object_id`存在且没有被地址标签替代；
3. `root_path`从 F0 连续抵达当前角色；
4. 非根地址具有一个可追溯`primary_parent`，且`global_depth = parent.global_depth + 1`，子场入口和闭合端能接回父偏序；
5. 必要前驱已表示，或由有效压缩接口承担；
6. 关系类型和方向没有被任意压平；并联地址可恢复分叉、分支和汇合，汇合地址具有合法规则及完整入支集合；
7. 地址没有偷换主体、目标、成功标准、尺度或边界；
8. 当前权限与安全条件允许该地址进入相应前沿；
9. 版本和证据兼容；
10. 地址没有被失效或退休，候选转换也没有得到 `[-]／[∅]`结果；
11. `[+]`状态具有 Execute／Audit 证据；
12. 前沿分型有父场义务或合法延期依据，贡献和成本没有被当成地址合法性证明；
13. 若来自Focus投影，`global_depth = focus_base_depth + local_depth`成立，且局部地址能够无歧义恢复完整全局绑定；
14. 汇合规则的`gate_type`、分支义务、时间策略、容差和证据一致；资源调度造成的先后没有被写成分支间必要边。

权重、热度、相关性和成本只能在合法同级候选之间排序，不能制造地址或跳过前驱。条件贡献只有在并行分解契约成立时才可沿父预算分配；串行必要链、交互项、阈值与非线性放大必须另行标注。

## 六、运动算子

### 6.1 `birth`

创建没有旧地址前身的新地址。必须记录生成场、生成运动和新生理由。

### 6.2 `materialize`

把已经合法但仅作为假设或压缩潜能存在的位置显式写入全景。它不自动变成 `[+]`。

### 6.3 `expand`

打开节点或关系为下一全局深度的完整场实例，生成新的`field_id`、主父绑定和子场记录。完整子场可以形成失败、单中心或多中心；只有进入Focus投影时才选择一个已激活中心。父场入口与子场闭合端必须能够接回父场偏序，并保存子场承重结构对父位置的代入边；只生成后缀、不生成返回边的运动不合法。若展开形成并联，必须同时生成`parallel_group_id`、各分支地址、汇合地址和`join_rule_id`；不得把任意执行顺序固化成串联边。未打开节点仍是带说明和重开入口的压缩位置，不因未展开而成为`[∅]`。

### 6.4 `global-expand`

对快照中的全部合格展开前沿统一推进一层。不能用任务权重选择性删除分支；预算延期逐项记录。

### 6.5 `focus-penetrate`

对一个或多个合法地址进行不等深展开。生成`ΔM_focus`并回写全景；未选分支保留为前沿或有效接口。局部`local_F_n`只保存在Focus投影中，回写必须恢复全局`F_(focus_base_depth+n)`及完整父路径。

### 6.6 `compress`

将相对闭合子场压缩为接口地址。接口至少保存输入、输出、条件、证据、容差、未解决差异、版本、失效触发和重开地址。若内部含并联，还必须保存分叉地址、分支义务、汇合规则、时间兼容策略、联合输出证据和可逆映射；压缩结果不得把并联子图改写成串联链。

### 6.7 `reopen`

根据重开条件恢复压缩子场。应指向原子场版本和历史，不得新建一个无来源的同名子场。

### 6.8 `payload-replace`

保持`address_id`，替换地址承载的内容、等价接口或证据，并推进`address_revision_id`。若功能角色、主父绑定、根路径或非等价接口改变，则不得伪装为载荷替换。

### 6.9 `move`

对象或功能迁移到新地址。保存 `old→new` 关系，旧地址进入历史或退休状态。

### 6.10 `split`

一个地址因角色、条件或场版本不可兼容而分裂为多个地址。不得用一个空洞上位词假装仍是同一位置。

### 6.11 `merge`

多个地址只有在功能等价、接口和证据条件明确时才能合并。合并保留全部来源地址。

### 6.12 `invalidate`

证据使地址、前驱、关系或接口失效。场内必须沿必要偏序传播到依赖后继，重开相关压缩接口并重审中心与Focus。子场可以向父场返回失效证据或剩余，使父场闭合状态转为`open/invalidated`；它不得直接迁移父地址。只有父场自身或更高层重定场后，父地址变化才向下重排后代地址。

### 6.13 `retire`

地址退出当前版本，但历史意义保持只读。退休地址不得复用于另一种功能。

### 6.14 `externalize`

内容与当前 F0 无关或应由外部系统处理时，保留来源并置于场外，不强行赋址。

### 6.15 `prohibit`

记录当前契约禁止的直接转换。它不删除证据，也不自动证明所有替代路线不存在。

### 6.16 `rebuild`

地址语法、中心、偏序或接口无法吸收可靠差异时，从最近失稳位置做最小上溯并重构。相对闭合后才生成场闭合版本。

### 6.17 `center-candidate-birth／center-activate／center-demote`

新中心先以候选身份出生。只有通过中心检验、绑定独立闭合义务并进入当前联合闭合规则后才能激活。证据不足、义务被吸收或当前不再必要时退回候选或普通子结构；降级必须保存旧活动版本和受影响接口。

### 6.18 `center-split／center-merge`

一个中心无法在不丢失闭合义务和失效条件的情况下继续统一时，可以分裂为多个中心。多个中心只有在一个接口等价单中心无需保留逐中心闭合、失效、重开和谱系向量，仍能无失真承担全部义务时才能合并；保留逐中心签名的`Compose`只是多中心包装器。两种运动都推进`field_version_id`、保存旧新`center_id`谱系，并重算相关`center_membership`；名称不同不证明应分裂，名称相同也不证明可合并。

### 6.19 `center-substitute／center-rebind`

中心义务和结构接口保持等价而只更换实现时使用`center-substitute`；中心义务、中心关系、父契约或联合闭合规则发生非等价变化时使用`center-rebind`。前者通常保持`center_id`并推进修订，后者形成新中心版本，必要时生成新`center_id`。

### 6.20 `center-invalidate`

新证据否定中心、中心关系或中心级汇合规则时，先在受影响中心内部传播，再沿中心关系选择性重审其他中心、联合闭合和父接口。未受影响且证据仍有效的中心可以保留；活动中心降为一个、中心级必要环出现或单中心接口等价重新成立时，必须重审多中心身份。

6.17—6.20属于完整场域的中心地图维护协议，不属于Focus内部的联合调度操作。Focus只接收一个`selected_center_ref`的投影结果；若完整场中心运动破坏其父契约、输入接口或闭合条件，客户端应结束当前局部运行并请求重投影，而不是把其他中心动态并入当前`Ready_t`。

## 七、地址运动事件

每次运动至少记录：

```yaml
motion_id: unique event id
motion_type: birth | expand | move | split | merge | retire | rebuild | ...
trigger:
  source: user | upper-field | evidence | residual | execution
  reference: null
source_field_version: null
target_field_version: null
source_panorama_version: null
target_panorama_version: null
source_addresses: []
target_addresses: []
address_revision_delta: []
ancestor_retains: []
affected_scope: null
root_paths_preserved: true
interface_equivalence: true | false | unknown
modal_changes: []
frontier_delta: []
  # each item records address_id, frontier_type, change, reason_ref
residuals_produced: []
residuals_absorbed: []
evidence: []
closure_audit: open | relatively-closed
next_decision: null
```

禁止只保存新地址而删除源地址和运动来源。任何地址运动写回都必须生成新的`target_panorama_version`；未被迁移的祖先地址进入`ancestor_retains`，不能因为全景版本推进而伪造祖先地址变化。

## 八、谱系约束

跨版本地址关系允许一对一、一对多、多对一、退休和新生。必须满足：

- 所有非空源地址和目标地址都属于可追溯场谱系；
- 旧版本保持只读；
- 一个地址标签不能在新版本中悄然承担完全不同功能；
- `address_id`保持时，载荷、接口或证据差分必须由`address_revision_id`及旧新修订关系保存；
- 子地址迁移不得直接生成祖先地址迁移；祖先重新寻址必须引用父场或更高层的独立重定场事件；
- 分裂与合并保存所有父关系；
- 分支版本不能仅凭时间或权重强行合并；
- 文档改写不自动产生场闭合版本。

## 九、模态、前沿和剩余审计

每次地址生成运动后同时更新：

```text
A_t^cand：尚在标定的地址候选
M_t=A_t^legal：已经标定并表示的合法地址全景
H_t：已审计实现下闭集
ActionFrontier_t：当前可执行地址
ExpansionFrontier_t.required：本轮父场闭合必须打开、实现或由接口承担
ExpansionFrontier_t.latent：合法但本轮可延后的展开地址
Compressed_t：压缩接口
JoinRules_t：并联分叉、分支义务、汇合算子与时间策略
JoinState_t：各汇合位置当前pending／satisfied／blocked／invalid状态
Λ_t：未激活的差异记录；address_binding 为 bound／candidate／unaddressed
R_t：影响 F0、尚未吸收的活动剩余
χ_t：剩余—地址关系、可达距离和吸收状态
```

普通未展开位置不是活动剩余；`expansion-latent`不自动属于`Λ_t`；潜在剩余可以与相对闭合共存；它本身没有地址模态，找到或新生一个合法地址也不等于差异已经被吸收。相对闭合要求`ExpansionFrontier.required`清零，但允许`ExpansionFrontier.latent`与非阻断`Λ_t`非空。

潜在剩余激活必须写入处置事件，`disposition`只允许`absorbed-local／required-frontier／address-birth／active-residual／externalized`。`active-residual`还必须附带`AddressResult_t`；当前直接转换被禁止时结果为`[-]`，当前场无合法表达／生成路线时结果为`[∅]`。不得通过修改潜在剩余的“模态”来代替处置。

并联前沿由汇合规则生成：`ALL`把所有未满足的必要支路保留为`required`；`ANY`在已有一条合格支路满足后，可把其他未选替代支路保留为`latent`或压缩候选；`K_OF_N`只在未达到配额时继续激活必要支路；`AGGREGATE`按聚合契约判断还缺哪些输入或证据。任何规则都不能因为资源队列暂时先执行某一支路，就把其他支路改写成它的串联后继。

## 十、执行接口

活动地址只有在合法性闸门通过后才能诱导可执行子偏序。`Active_t`只能从必要展开、行动就绪或活动剩余处置地址中产生；先保证合法与就绪，再用父场阻断程度、贡献区间、不确定性、交互风险、成本和证据价值排序：

\[
\Pi_t^{\sigma_t}=\operatorname{JoinInduce}(\Pi_t,JoinRules_t,JoinState_t),
\qquad
D_t=\operatorname{Induce}(\Pi_t^{\sigma_t},Active_t\cup Pred_t).
\]

`\Pi_t^{\sigma_t}`只把当前汇合状态实际要求的支路纳入活动必要偏序；未选替代支路仍可保留地址和潜在前沿，但不伪装成本轮闭合的普通必要前驱。

就绪波前为：

\[
Ready_t=\{x\in D_t\mid Pred(x)
\text{中的串联前驱已满足或由有效接口承担}
\land JoinSat(x,JoinState_t)=1\}.
\]

执行队列不得把资源性先后写回成必要因果边。只有取得要求证据并通过 Audit 的地址进入 `H_t`。

当客户端是Focus时，地址引擎返回的全景增量、活动地址、两类展开前沿、压缩接口、`JoinRules／JoinState`、剩余和全局绑定必须写回完整`Q_t`；`V_t^q`只从`Q_t`派生为本轮不等深视图，不能反过来作为唯一持久状态。每条局部活动地址都必须同时保存`global_root_id、field_id、primary_parent、root_path、global_depth、focus_base_depth、local_depth、source_field_version_id、source_center_system_version、selected_center_ref、peer_center_refs、projection_certificate_ref、parent_return`。`Q_t`只运行`selected_center_ref`对应的单中心偏域；完整场多中心地图由上位状态维护，`peer_center_refs`只保留证书要求的接口。未选中心不得进入本轮`Ready_t`，只允许以已审计压缩接口被引用。Address自身不替客户端执行任务，也不把一个高分视图当作完整地址地图。

## 十一、最小示例

根目标：修复一个已确认的软件缺陷，并满足当前发布契约。这里的`F0`是该示例地址域自己的持久根，不是总理论文件的`F0`，也不是Focus临时改写出来的局部根。

```text
F0:A 确认缺陷与发布边界
→ F0:B 复现并定位缺陷
→ F0:C 形成最小合法修复
→ F0:D 执行契约要求的验证
→ F0:E 返回可交付结果
```

“额外平台兼容、非阻断性能优化、扩展诊断、可选重构”可以是`B/C/D`下的潜在地址。若当前发布契约不要求它们，便可保持未展开，场仍可能相对闭合；若契约新增兼容性、安全性或性能要求，相应地址才被上一层目标激活并进入当前根路径。若在当前架构和权限边界内不存在合法修复路径，它不是普通未展开，而可能成为活动剩余或当前场的`[∅]`结果，触发扩场或重构。

该例只演示地址生成与激活，不证明所有软件任务或其他领域具有同一中心结构。

## 十二、与当前实现的关系

v0.18构造型Focus已经能够在父任务过程中维护证据绑定的选中中心、平级接口、必要偏序、汇合和功能地址，并让冲突沿必要后继和父接口传播；每个已实现节点都必须绑定非空证据。历史sidecar、两阶段Focus与Address Engine另行保存执行后导入、候选／合法地址分账、独立标定状态、四类前沿、潜在剩余地址绑定、根路径、地址模态和运动谱系。当前尚未完整实现：

- 任意关系作为递归地址锚点；
- 从自然语言自动赋址和标定；
- 完整逻辑地址字段；
- 自动接口等价判断；
- 大规模地址地图的增量生成与查询；
- `F_n`全局递归深度、`local_F_n`Focus投影及二者的可验证换算；
- `global_root_id + primary_parent + root_path`的持久化与多层写回；
- `address_id / address_revision_id / field_version_id / panorama_version`的独立推进和谱系校验；
- 子地址运动写回全景时自动登记祖先`retain`，并阻断未授权的向上迁址；
- `parallel_binding + join_rule + JoinState`的生成、汇合就绪计算、压缩恢复和时间兼容校验；
- 完整场`center_system + center_membership + center_relation + center_join_rule`的持久化和合法性校验；
- 完整场中心候选、激活、分裂、合并、替代、降级、重绑定和失效状态机；
- 从完整场中心地图生成带源版本的`ProjectionCertificate + selected_center_ref + peer_center_refs`，并接收`FocusReturn`的单中心投影及重投影协议；
- 共享地址逐中心`obligation_status／evidence／validity_window／closure_effect`的闭合与失效审计；
- 真多中心、候选并列、普通并联、平行多场和多父绑定的反例测试矩阵，并验证Focus运行态不接纳多个中心；
- 多父DAG的路径相对身份与闭合义务。
- 多个独立 sidecar 状态之间的全景合并、冲突审计和自动重投影。

实现可以逐步靠近本协议，但不得把协议字段存在等同于地址判断正确。
