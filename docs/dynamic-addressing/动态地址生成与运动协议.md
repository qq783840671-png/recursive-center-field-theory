# 动态地址生成与运动协议

> 版本：v0.1-draft（2026-07-19）  
> 用途：把《递归动态寻址理论》转换为可实现、可校验和可审计的协议候选。本文不宣称当前代码已经支持全部字段和操作。

## 一、协议目标

本协议回答四个问题：

1. 一个候选地址需要保存哪些字段；
2. 地址怎样被赋予、标定和判为合法；
3. 场运动怎样生成、改变或退役地址；
4. 每次运动怎样保存证据、剩余和版本谱系。

## 二、地址记录

推荐的逻辑记录为：

```yaml
address_id: stable address record id
field_id: owning field
goal_contract_id: current F0 contract
object_id: stable identity of the addressed object or relation
address_kind: root | structural | recursive | interface | historical
structural_role: function in the current field
root_path:
  nodes: []
  required_relations: []
relation_path: []
recursive_path: []
parent_address: null
child_field_id: null
interfaces: []
field_version_id: null
panorama_version: null
modal_status: "[◇]"  # represented addresses use only [◇] or [+]
exposure_state: visible | compressed | locked | retired
evidence: []
provenance:
  producing_motion: FIELD_FORM | GLOBAL_EXPAND | FOCUS | EXPAND | REBUILD
  source_addresses: []
  source_update: null
validation:
  ancestry: pending
  predecessors: pending
  interface: pending
  version: pending
  evidence: pending
reopen_address: null
invalidation_triggers: []
```

机器实现可以使用不同字段名，但不得混淆对象身份、地址身份、显示路径、模态和版本。

禁止或无地址结果使用独立记录，而不是伪造一个合法地址：

```yaml
addressing_result_id: stable result id
candidate_object_id: null
candidate_transition: null
result_status: prohibited | no-address
modal_result: "[-]" | "[∅]"
nearest_related_address: null
target_address: null
reason: null
evidence: []
residual_id: null
proposed_destination: prohibit | expand | ascend | rebuild | externalize
```

## 三、显示地址与完整地址

面向人的显示地址可以使用：

```text
F0:A
F0:C3
F0:C3.2.1[◇]
```

显示规则：

- `F0`始终表示当前场谱系的逻辑根层；
- 根字母表示当前根层中心或一级结构位置；
- 数字后缀只由实际递归打开产生；
- 不等长地址允许同时存在；
- 同一根字母下允许多条活动地址；
- 模态可以显示，但不构成地址身份；
- 版本、证据和完整根路径保存在记录中，不全部塞入字符串。

## 四、赋址流程

### 4.1 输入

```text
对象或关系 x
＋ 当前场 F
＋ 场契约 Γ
＋ 完整关系图 G
＋ 必要偏序 Π
＋ 候选或选定中心 K
＋ 当前版本 v
＋ 证据 E
```

### 4.2 候选生成

1. 确认 `object_id`，不得用地址字符串代替对象身份；
2. 判断对象是否与 F0 相关；
3. 确定候选 `structural_role`；
4. 从 F0 恢复完整根路径；
5. 附加所有必要前驱或有效压缩接口；
6. 保存非偏序关系及其类型；
7. 若打开下一层场，记录实际递归路径和子场身份；
8. 生成 `address_id`、显示地址和 `provenance`；
9. 初始模态默认是 `[◇]` 或地址假设，不得默认 `[+]`。

### 4.3 标定

候选地址逐项通过：

```text
场相关性
→ 对象身份一致性
→ 功能角色证据
→ 根路径完整性
→ 必要前驱或接口有效性
→ 关系类型正确性
→ 权限与边界
→ 版本兼容性
→ 模态与证据一致性
```

只有全部承重条件通过，地址才能进入合法全景。部分条件未知时保存为 `hypothesized`，不得隐藏未知项。

## 五、地址合法性闸门

一个地址 `a` 在版本 `v` 中合法，当且仅当：

1. `field_id`与`goal_contract_id`可追溯；
2. `object_id`存在且没有被地址标签替代；
3. `root_path`从 F0 连续抵达当前角色；
4. 必要前驱已表示，或由有效压缩接口承担；
5. 关系类型和方向没有被任意压平；
6. 地址没有偷换主体、目标、成功标准、尺度或边界；
7. 当前权限与安全条件允许该地址进入相应前沿；
8. 版本和证据兼容；
9. 地址没有被失效或退休，候选转换也没有得到 `[-]／[∅]`结果；
10. `[+]`状态具有 Execute／Audit 证据。

权重、热度、相关性和成本只能在合法同级候选之间排序，不能制造地址或跳过前驱。

## 六、运动算子

### 6.1 `birth`

创建没有旧地址前身的新地址。必须记录生成场、生成运动和新生理由。

### 6.2 `materialize`

把已经合法但仅作为假设或压缩潜能存在的位置显式写入全景。它不自动变成 `[+]`。

### 6.3 `expand`

打开节点或关系为下一层场，生成合法后缀和子场记录。父场入口与子场闭合端必须能够接回父场偏序。

### 6.4 `global-expand`

对快照中的全部合格展开前沿统一推进一层。不能用任务权重选择性删除分支；预算延期逐项记录。

### 6.5 `focus-penetrate`

对一个或多个合法地址进行不等深展开。生成 `ΔM_focus`并回写全景；未选分支保留为前沿或有效接口。

### 6.6 `compress`

将相对闭合子场压缩为接口地址。接口至少保存输入、输出、条件、证据、容差、未解决差异、版本、失效触发和重开地址。

### 6.7 `reopen`

根据重开条件恢复压缩子场。应指向原子场版本和历史，不得新建一个无来源的同名子场。

### 6.8 `payload-replace`

保持地址角色和接口，替换地址承载的内容或证据。若角色、依赖、边界或接口改变，则不得伪装为载荷替换。

### 6.9 `move`

对象或功能迁移到新地址。保存 `old→new` 关系，旧地址进入历史或退休状态。

### 6.10 `split`

一个地址因角色、条件或场版本不可兼容而分裂为多个地址。不得用一个空洞上位词假装仍是同一位置。

### 6.11 `merge`

多个地址只有在功能等价、接口和证据条件明确时才能合并。合并保留全部来源地址。

### 6.12 `invalidate`

证据使地址、前驱、关系或接口失效。必须沿必要偏序传播到依赖后继，重开相关压缩接口并重审中心与 Focus。

### 6.13 `retire`

地址退出当前版本，但历史意义保持只读。退休地址不得复用于另一种功能。

### 6.14 `externalize`

内容与当前 F0 无关或应由外部系统处理时，保留来源并置于场外，不强行赋址。

### 6.15 `prohibit`

记录当前契约禁止的直接转换。它不删除证据，也不自动证明所有替代路线不存在。

### 6.16 `rebuild`

地址语法、中心、偏序或接口无法吸收可靠差异时，从最近失稳位置做最小上溯并重构。相对闭合后才生成场闭合版本。

## 七、地址运动事件

每次运动至少记录：

```yaml
motion_id: unique event id
motion_type: birth | expand | move | split | merge | retire | rebuild | ...
trigger:
  source: user | upper-field | evidence | residual | execution
  reference: null
source_field_version: null
target_field_version: null
source_addresses: []
target_addresses: []
affected_scope: null
root_paths_preserved: true
interface_equivalence: true | false | unknown
modal_changes: []
frontier_delta: []
residuals_produced: []
residuals_absorbed: []
evidence: []
closure_audit: open | relatively-closed
next_decision: null
```

禁止只保存新地址而删除源地址和运动来源。

## 八、谱系约束

跨版本地址关系允许一对一、一对多、多对一、退休和新生。必须满足：

- 所有非空源地址和目标地址都属于可追溯场谱系；
- 旧版本保持只读；
- 一个地址标签不能在新版本中悄然承担完全不同功能；
- 分裂与合并保存所有父关系；
- 分支版本不能仅凭时间或权重强行合并；
- 文档改写不自动产生场闭合版本。

## 九、模态、前沿和剩余审计

每次地址生成运动后同时更新：

```text
M_t：地址全景
H_t：已审计实现下闭集
ActionFrontier_t：当前可执行地址
ExpansionFrontier_t：当前可展开地址
Compressed_t：压缩接口
Λ_t：未激活的潜在剩余
R_t：影响 F0、尚未吸收的活动剩余
χ_t：剩余—地址关系、可达距离和吸收状态
```

普通未展开位置不是活动剩余；潜在剩余可以与相对闭合共存；找到潜在地址也不等于活动剩余已经被吸收。

## 十、执行接口

活动地址只有在合法性闸门通过后才能诱导可执行子偏序：

\[
D_t=\operatorname{Induce}(\Pi_t,Active_t\cup Pred_t).
\]

就绪波前为：

\[
Ready_t=\{x\in D_t\mid Pred(x)
\text{已满足或由有效接口承担}\}.
\]

执行队列不得把资源性先后写回成必要因果边。只有取得要求证据并通过 Audit 的地址进入 `H_t`。

## 十一、最小示例

根目标：吃到一个满足当前要求的西瓜。

```text
F0:A 形成购买意图
→ F0:B 明确当前验收条件
→ F0:C 获取候选西瓜
→ F0:D 选择并取得
→ F0:E 验收并食用
```

“品种、大小、水分、价格、购买地点”可以是 `B/C` 下的潜在地址。若当前验收只要求“吃到西瓜”，它们可以保持未展开，场仍相对闭合；若用户增加“水分多、两公斤以内”，对应地址被上一层目标激活并进入当前根路径。若现实中没有合法购买路线，它不是普通未展开，而可能成为活动剩余或当前场的 `[∅]` 结果，触发扩场或重构。

该例只演示地址生成与激活，不证明所有欲望或消费行为具有同一中心结构。

## 十二、与当前实现的关系

当前 Focus 状态助手已经能够保存部分地址、根路径、模态、三类前沿、更新入口和地址运动谱系，但尚未完整实现：

- 任意关系作为递归地址锚点；
- 从自然语言自动赋址和标定；
- 完整逻辑地址字段；
- 潜在剩余 `Λ_t` 的独立机器表示；
- 自动接口等价判断；
- 大规模地址地图的增量生成与查询。

实现可以逐步靠近本协议，但不得把协议字段存在等同于地址判断正确。
