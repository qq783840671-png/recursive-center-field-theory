# 场域相对的递归动态寻址理论

> 版本：v0.12-draft（2026-08-29）
> 身份：递归偏序多中心动态场域论的中层展开理论
> 证据边界：当前是结构与协议候选，不是经过实验确证的普遍自然地址体系

## 一、问题与理论定位

普通编号系统先规定一个固定容器，再把对象填入预留位置。递归动态寻址理论处理的是另一类问题：当问题边界、中心、必要关系、观察深度和场版本都可能变化时，对象怎样获得可追踪的位置；场在展开、聚焦、压缩、执行和重构以后，新位置怎样产生，旧位置怎样保留或迁移。

本理论的根命题是：

> **地址不是对象脱离关系后的永久坐标，而是对象在特定场契约、中心偏序和递归路径中的结构身份；地址记录在具体版本中成立并随场的合法运动修订，但稳定逻辑地址、对象身份、版本快照与旧新谱系必须分别保存。**

地址因此同时承担五项功能：

1. 定位：说明对象或关系在当前场承担什么结构角色；
2. 约束：说明它依赖哪些必要前序、经过哪些合法接口；
3. 导航：允许从根层进入下一层子场，并在压缩后重新打开；
4. 记忆：保存当前版本、历史版本和失效来源；
5. 审计：说明地址为何生成、何时实现、如何迁移以及什么仍未被吸收。

## 二、它在总理论中的结构位置

递归中心场偏序动力场域论的五个核心对地址分别提供不同条件：

| 理论内核 | 对地址的作用 |
|---|---|
| 场 `F` 与契约 `Γ_F` | 决定地址在哪个定义域、尺度、目标和证据标准下成立 |
| 中心 `K_F` | 决定哪些功能位置构成当前任务的承重结构 |
| 必要偏序 `Π_F` | 决定根路径、必要前驱和合法运动方向 |
| 递归 `Exp/Comp` | 允许位置与关系打开为下一层场，并压缩为可重开接口 |
| 动力、闭合与剩余 | 触发地址生成、状态变化、失效、升场和版本重构 |

由此得到：

\[
\mathcal A_t
=
\operatorname{Address}
(F_t,\Gamma_t,G_t,\Pi_t,K_t,
P_t^{req},P_t^{latent},
\operatorname{Exp},\operatorname{Comp},T_t,v_t,E_t).
\]

这里的 `Address` 不是一个一次性编码函数，而是一组受场运动约束的生成、校验和版本操作。

地址层向上不替代场域论，向下约束 Focus、知识地址、动态地图、长期记忆、多 Agent 编排和可能的地址引擎。

## 三、八种必须分开的身份

### 3.1 对象身份

对象身份回答“我们正在追踪的是谁或什么”。它不应因显示路径变化而自动改变。一个论文、概念、任务、证据、关系或子场可以拥有稳定的 `object_id` 或 `relation_id`。

### 3.2 场身份

场身份回答“该判断在哪个问题域和契约中成立”。同一对象进入不同场，可以承担不同功能，因此可以拥有多个合法场相对地址。

### 3.3 地址身份

地址身份回答“对象在当前场中位于哪里、承担什么功能、怎样从根层抵达”。它由场、角色、父绑定和根路径共同生成。同一对象进入不同场产生不同`address_id`；同一名称也不能证明两个地址相同。

### 3.4 地址修订身份

`address_revision_id`回答“同一逻辑位置的载荷、接口或证据经历了哪一次修订”。地址修订变化不等于`address_id`迁移。

### 3.4.1 地址候选与标定身份

`candidate_address_id`标识尚未取得合法地址资格的结构假设；`calibration_status`记录`hypothesized／calibrating／calibrated／rejected`。`calibrated`是从候选账本进入合法地址账本的门，而不是一种地址实现模态：成功标定产生或关联`address_id`，拒绝候选则保留反例和来源，不制造`[-]`地址。

### 3.5 模态状态

模态回答“本次寻址或地址当前以何种方式成立”：

- `[+]`：地址对应的结果已经执行并通过审计；
- `[◇]`：地址已经完成标定、合法登记并被表示，但尚未执行并通过Audit；
- `[-]`：某个候选直接转换被当前契约或必要偏序禁止；
- `[∅]`：当前场无法无失真地表达、生成或保证该候选结果。

模态不是地址编号的一部分。地址候选`A_t^{cand}`先保存`candidate_address_id`及`hypothesized／calibrating／rejected`标定状态，不带地址模态；通过标定后才新生为`A_t^{legal}`中的稳定`address_id`。合法地址记录只使用`[+]／[◇]`；`[-]／[∅]`是对候选转换或寻址结果的判断，应保存在`AddressResult_t`并允许目标地址为空，不能伪装成已经进入`M_t`的合法地址。地址可以保持不变而`[+]／[◇]`状态发生变化。

### 3.6 版本与证据身份

`field_version_id`回答地址记录在哪个场版本中有效，`panorama_version`回答它出现在哪个全景快照；证据回答为什么相信地址角色、根路径和模态判断。地址字符串不能替代版本和证据账本。

### 3.7 中心归属身份

中心归属回答“当前功能位置服务哪个活动中心、承担哪项中心义务”。它通过`center_membership`引用`center_system_id／center_id／obligation_ref`，不是对象身份、场身份或稳定地址的一部分。

同一地址可以服务一个或多个中心。每项归属必须分别保存`obligation_status、evidence_ref、validity_window、closure_effect`；地址级`modality`只说明该位置本身是否实现，不自动证明它对全部中心义务都已满足。中心归属变化通常形成新的`address_revision_id`和`field_version_id`；只有场身份、父绑定、根路径或功能身份改变时才迁移稳定`address_id`。多个中心共享一个功能位置时，不得为了中心显示方便复制对象或伪造多个逻辑地址。

这里的多值`center_membership`属于完整场域地址地图，不要求一次Focus同时运行多个中心。Focus投影只保存一个`selected_center_ref`作为当前偏域中心，并以最小`peer_center_refs`指回未选中心或其压缩接口；这些同级引用不进入当前中心偏序、`Ready_t`或执行队列。

## 四、逻辑全地址

一个稳定逻辑地址可候选表示为：

\[
address\_id=\langle
global\_root,
global\_depth,
field\_id,
goal\_contract\_id,
primary\_parent,
structural\_role,
parallel\_binding,
root\_path,
relation\_path,
recursive\_path
\rangle .
\]

一个版本化地址记录再表示为：

\[
\hat a_t(x)=\langle
address\_id,
address\_revision\_id,
object\_id,
relation\_roles,
join\_rule\_ref,
center\_membership,
center\_relation\_refs,
center\_join\_rule\_ref,
center\_lineage\_refs,
interfaces,
frontier\_class,
contribution\_annotation,
field\_version\_id,
panorama\_version,
modality,
evidence,
provenance
\rangle .
\]

其中：

- `global_root`：当前地址域的持久根，不随Focus视图切换；
- `global_depth`：相对持久根的递归深度；`F_n`只显示这一深度，不识别唯一场实例；
- `field_id`：场对象身份；
- `goal_contract_id`：当前根目标和验收契约；
- `primary_parent`：非根场当前唯一主父绑定，包括父场、父地址、功能义务和返回接口；多父DAG暂不伪装为已解决；
- `object_id`：被寻址对象的稳定身份；
- `address_id`：场相对逻辑位置的稳定身份，不含快照版本和当前载荷；
- `address_revision_id`：同一逻辑位置自身载荷、接口或证据的修订身份；
- `structural_role`：对象在当前场中的功能位置；
- `parallel_binding`：对象在当前场内是否承担分叉、并联分支或汇合位置，以及所属并联组、分支和两端地址；并联身份变化属于结构变化；
- `relation_roles`：依赖、支持、冲突、耦合、分叉、并联分支、汇合，以及资源来源、结构条件、放大、阈值、触发和传播等有类型关系角色；
- `join_rule_ref`：汇合位置引用的有类型满足规则、时间兼容策略、容差和证据；规则正文属于场结构记录，不应复制成地址字符串；
- `center_membership`：当前地址所属中心及其角色、义务、逐中心满足状态、证据、有效期和闭合影响；它允许多值，但不进入稳定`address_id`或显示字符串；
- `center_relation_refs`：该位置涉及的中心级必要、共需、约束、支持、竞争、冲突、聚合或共享关系；
- `center_join_rule_ref`：活动中心怎样共同满足场契约的联合闭合规则；
- `center_lineage_refs`：中心出生、激活、分裂、合并、替代、降级、重绑定和失效的谱系引用；
- `root_path`：从 F0 到当前位置的完整根路径子图；
- `relation_path`：支撑该位置的有类型关系和必要前驱；
- `recursive_path`：实际打开子场所形成的递归路径；
- `interfaces`：被压缩但仍承担前序义务的接口；
- `frontier_class`：`action`、`expansion-required`、`expansion-latent`或空；同一地址可以具有多个进入理由，但必须分别举证；
- `contribution_annotation`：可选的条件贡献区间、分解契约、未建模剩余和成本；它不是地址合法性的来源；
- `field_version_id`：地址记录有效的所属场版本；
- `panorama_version`：本次地址或关系全景快照；任一合法地址运动写回全景时推进；
- `modality`：合法地址的潜在或实现状态；禁止或无地址判断保存在独立寻址结果中；
- `evidence`：标定地址和状态的证据；
- `provenance`：生成该地址的运动与来源。

因此，子地址变化可以使`panorama_version`推进，而祖先`address_id`及其`address_revision_id`保持不变；全景快照变化不能被解释为全景内每个逻辑地址都发生迁移。

面向人的`F2@F0:C/x:y[◇]`只是全局显示地址。Focus内部还可以显示`local_F0:y`，但二者都必须能够返回同一完整记录；局部显示不得覆盖全局根路径。

## 五、地址不是任意编号

下一层深度只有在实际打开一个完整子场后才能产生。例如：

```text
F0:C
→ 打开C中的位置x为子场F1@F0:C/x
→ 在该子场选择位置y并继续打开为F2@F0:C/x/y
→ Focus可暂显示local_F0:y，但写回仍为F2@F0:C/x/y
```

`F1/F2`表示全局递归深度，不自动表示价值、时间、执行顺序、重要性或唯一场对象。同一深度可以有多个场实例，必须结合`field_id + primary_parent + root_path + version`识别。旧`F0:C3.2.1`数字串只保留为历史显示别名，不能继续承担正式递归地址语义。

合法地址必须能够重新展开为：

```text
F0 根契约
＋ 完整根路径
＋ 必要前驱或有效压缩接口
＋ 当前结构角色
＋ 实际递归面包屑
＋ 关系类型
＋ 版本和证据
```

只有数字、没有上述结构的路径，只能叫显示标签，不能叫经过标定的动态地址。

## 六、赋址与标定

“赋址”与“标定”不能混为一次命名动作。

### 6.1 赋址

赋址是为一个对象或关系生成候选结构位置：

```text
确认对象身份
→ 声明所属场和契约
→ 确定持久global_root和当前global_depth
→ 判断候选功能角色
→ 恢复从global_root到该角色的根路径
→ 补齐必要前驱和压缩接口
→ 记录递归打开过程
→ 生成候选地址与来源
```

### 6.2 标定

标定是检验候选地址是否与现实关系、当前版本和证据一致：

1. 场标定：对象确实与当前根目标相关；
2. 角色标定：删除或替换该角色会产生预期的结构差异；
3. 路径标定：根路径及必要前驱没有被跳过；
4. 接口标定：被压缩前序仍由有效接口承担；
5. 关系标定：依赖、支持、冲突、相似、耦合等关系没有被压成同一种边；
6. 版本标定：证据和地址来自兼容版本；
7. 模态标定：潜在地址没有被误报为已实现；
8. 反例标定：无地址或冲突结果没有被强行塞入旧语法。

未经标定的结构位置只保留在`A_t^{cand}`并标记为`hypothesized`，不能取得合法地址模态、不能进入已审计下闭集或四类前沿，也不能仅凭热度进入执行。

## 七、地址生成的运动来源

地址由场运动生成。设当前地址全景为 `M_t`，则：

\[
M_{t+1}=M_t\cup\Delta M_t^{+}\setminus\Delta M_t^{-},
\]

其中新增、状态改变与退出当前版本必须通过运动账本解释，不能直接覆盖。

### 7.1 场形成

含糊输入尚不是根地址。场契约、中心候选和必要偏序稳定以后，才形成 F0 根层及第一组结构地址。若主体、目标、边界或成功条件存在实质歧义，候选`F0^\Diamond`必须经过形成场中的授权确认才成为`F0^+`；确认记录属于地址谱系，不属于剩余。

### 7.2 Global Expansion

Global 在预算内对全部合格展开前沿统一推进一层，产生 `ΔM_global`。预算不足的合法位置保留在展开前沿，不得因本轮未展开而删除。

### 7.3 Focus Penetration

Focus 在根路径合法和必要前驱保持的条件下，对一个或多个位置作不等深展开，产生 `ΔM_focus`，并把新地址写回全景。未选择的合法位置仍是前沿或有效压缩接口。

Focus必须把局部投影与全局身份分开保存。若聚焦基点处于全局深度`d_0`：

```text
local_F0 ≡ global F_d0 field instance
global_depth = focus_base_depth + local_depth
```

局部`A、B、C……`只是活动地址；写回时必须恢复`global_root、field_id、primary_parent、root_path`。Global视图、Focus不等深视图和完整Focus状态分别使用`GView`、`V_t^q`、`Q_t`，不再占用`F1—F4`名称。

### 7.4 递归展开和关系展开

节点或关系可以打开为下一层场。未打开时，它是父场中的压缩位置，可以保存说明、功能身份、接口、适用条件和重开入口；打开后，它才形成下一全局深度中拥有自身契约、中心候选、偏序、闭合端和返回接口的完整场实例。完整子场可能形成失败、单中心或多中心；只有进入Focus投影时才选定一个已激活中心运行。若父地址`u`被打开，子场根路径必须与父前驱、父后继形成可验证的偏序代入；后缀不能只是与父运动无关的挂载分支。当前活动前沿因此可以由不同全局深度的末端节点共同构成。

### 7.5 压缩与重开

相对闭合的子场可压缩为接口地址。压缩隐藏显示深度，但保留输入、输出、条件、证据、未解决差异、版本、失效触发和重开地址。重开恢复原子场，不重新发明另一个同名结构。

### 7.6 Execute 与 Audit

执行通常不生成任意新分类，而是使合法潜在地址取得现实证据。只有执行成功并通过审计，地址对应结果才能从 `[◇]` 转为 `[+]`。执行失败也可能暴露新地址、活动剩余、失效路径或重构需求。

### 7.7 更新与新版本

新证据可以使地址载荷替换、迁移、分裂、合并、退休或新生。地址变化必须保存源版本、目标版本和旧新谱系。

### 7.8 地址传播与层级返回

父地址的非等价变化可以沿`root_path`向下重排后代地址。反方向不成立：子地址的出生、修订、展开、压缩、迁移或退休必须写入全局地址地图，使`panorama_version`变化，但祖先`address_id`保持`retain`。

```text
父地址变化 → 后代地址重审／重排
子地址变化 → 全景版本变化，祖先地址retain
```

子场仍可向上返回接口结果、证据、失败或剩余，使父场的闭合状态改变并触发重审；这不是地址向上传播。只有父场自身或更高层重新定场，改变父场功能身份、父绑定或根路径时，才生成父地址迁移，并再次向下作用于后代地址。

### 7.9 并联分叉、汇合与压缩地址

场内递归展开允许形成分叉—并联—汇合子图。它不等于多父场：并联分支仍可以共享同一场实例和`primary_parent`，但各自拥有不同`address_id`；汇合地址通过多个有类型`relation_path`接收分支返回。

```text
fork_address
├─ branch_address_1 ─┐
└─ branch_address_2 ─┴→ join_address
```

完整记录必须满足：

1. 每个分支地址绑定同一`parallel_group_id`和唯一`branch_id`；
2. 汇合地址保存全部入支地址及`join_rule_ref`，不能选一条路径冒充完整根路径；
3. `ALL／ANY／K_OF_N／AGGREGATE`等规则决定哪些分支返回足以使汇合位置就绪；
4. 并联不自动表示严格同时，采样时刻、有效时间窗、稳态假设或动态方程由规则另行声明；
5. 含并联的子场压缩后，父接口仍保存分叉、分支义务、汇合规则、时间容差、联合证据和重开入口；重新展开必须恢复同一结构，不能还原成一条伪串联链。

若某一分支失败，地址引擎先依据汇合规则更新`JoinState`和父场闭合状态：`ALL`可能立即阻断，`ANY`未必阻断，配额或聚合规则需要重新计算。这个返回不直接迁移父地址；只有汇合规则、父功能身份或根路径本身被重新定义时，才进入父场重新寻址。

### 7.10 完整场多中心归属与单中心Focus投影

完整场地址引擎可以接收已经由理论层或Agent举证的候选中心、活动中心和联合闭合规则；多个候选不能直接写成活动多中心。它校验以下边界：

1. 活动中心不少于两个，且每个中心绑定独立闭合义务；
2. 每个中心成员地址都能追溯到同一`center_system_id`和有效场版本；
3. 共享位置只保留一个`address_id`，通过多值`center_membership`表示；
4. 中心级严格必要关系无同版本环，其他支持、竞争、冲突和耦合关系不进入中心偏序；
5. 中心级联合闭合规则能够区分候选选择、共同必要、配额和聚合；
6. `center-split／center-merge`保存接口等价或不可压缩差异的证据，不能只按名称或显示结构操作。

`Compose`产生的是保留逐中心签名的场级中心系统，不自动成为单中心候选。若所谓合并接口仍必须携带逐中心闭合、失效、重开或谱系状态才能支持父场判断，它只是多中心包装器；只有在当前契约、尺度和允许接口语言下，无需保留这些逐中心状态仍能无失真恢复父场决策时，才允许登记为复合单中心。

中心出生、激活、降级、分裂、合并、替代、重绑定和失效首先改变中心谱系及`field_version_id`，再计算受影响地址的修订。若一个位置仍保持相同场、父绑定、根路径和功能身份，只改变中心归属，则保留`address_id`并推进`address_revision_id`。中心失效先沿该中心内部必要偏序和中心关系选择性传播，再重审场的联合闭合及父接口。

进入执行Focus前必须执行中心投影：从完整场的活动中心中选定一个`selected_center_ref`，把该中心的节点、必要关系、递归前沿和闭合义务映射为单中心偏域；其余中心只以`peer_center_refs`、候选引用或压缩接口留在绑定中。候选中心若需检验，只能进入不产生任务`Ready_t`的形成／审计投影。`peer_center_refs`用于返回全景、切换中心、重投影和失效审计，不得被并入当前`Ready_t`或伪装成本中心节点。

投影绑定必须携带源`field_version_id`、源中心系统版本及`ProjectionCertificate`：其中至少保存选定中心、必要平级接口、被省略义务、投影假设和失效触发。Focus返回完整场时生成`FocusReturn`，分别报告选定中心闭合、输出、证据、平级接口影响、剩余和是否请求重投影。选定中心闭合不能自动推出完整场闭合。

因此上述中心出生、分裂、合并和选择性失效传播首先是完整场地址维护操作。Focus只接收投影后的局部结果；若源版本或未选中心的变化破坏投影证书、当前选中中心的父契约、输入接口或闭合条件，必须结束本轮、重开接口或请求上位全景重新投影。

### 7.10.1 v0.18过程内功能寻址

当前新Focus调用不为所有预计步骤预先分配地址，也不等到结果完成后才恢复结构。它在父任务过程中只为承担导航、约束、证据、记忆或重开审计功能的位置生成地址：

\[
M_t^{constructive}
=
\operatorname{Update}
(F_t,Decision_t,\Delta_t,E_t).
\]

`Decision_t`只允许一个当前结构决定；`\Delta_t`保存新证据、失败、冲突、用户纠正或约束变化。合法未实现地址可标`[◇]`，但普通工具调用、文本段落、材料条目和没有结构作用的候选不得仅为记录方便而地址化。每个`[+]`仍必须具有非空证据。

当`\Delta_t`反驳必要前驱、汇合分支、压缩接口或闭合条件时，地址运动先撤回受影响`[+]`，沿必要后继传播，重开最近失败接口，使旧闭合证书失效，再决定局部替换、升场、分支或回卷。传播只沿记录的必要关系和父返回接口进行，支持、竞争或时间先后本身不产生失效传播。

### 7.10.2 v0.17 sidecar的历史导入寻址

已完成的外部或历史任务仍可把实际轨迹记录为`O_t^{trace}`，并通过`observe→reconstruct`恢复执行后证据绑定地址。sidecar不得把偶然工具顺序写成必要偏序，也不得为了完整性伪造未观察中心。它现在是导入和审计接口，不再定义新Focus调用的默认过程。

### 7.11 递归场栈、尺度地址与分层回卷

动态地址不能只保存“走过哪些文本或工具步骤”，还必须保存每次子场打开时的父子层级。候选递归场栈写为：

\[
\mathcal S_t^{field}
=
(\Phi_0,\Phi_1,\ldots,\Phi_{d_t}),
\]

\[
\Phi_k=
\langle
field\_id_k,parent_k,address_k,
\Gamma_k,\delta_k,\epsilon_k,\tau_k,
closure_k,best_k,upper_k,
evidence_k,residual_k,reopen_k
\rangle .
\]

每个`\Phi_k`是一个可返回的场帧：记录为什么从父场打开、当前要求多细、做到什么算局部闭合、已经获得什么证据、理论上还能达到什么上界，以及失败后怎样重新打开。`d_t`是模型中的递归深度；若尺度可比较，另记分辨率数量级：

\[
q_t=\log_{10}\frac{\delta_0}{\delta_t}.
\]

`d_t`与`q_t`必须分开。`F_d`只说明已从持久根递归打开`d`层，不证明已经进入`d`个物理数量级，也不证明对象自身存在同样数量的结构层。中心数量、偏序高度、分支宽度和交互秩同样独立记录。

当监测器发现地址重复、闭合残差长期不下降、有效证据增量低、可达上界低于门槛或上下文／预算接近边界时，应停止继续下钻，并把当前帧压缩为：

\[
\operatorname{Fold}(\Phi_k)
=
\langle
conclusion,evidence,best,upper,
residual,assumptions,reopen
\rangle .
\]

随后沿`primary_parent`逐层返回，直到最近一个仍有合法平级中心、能够吸收当前误差，或有权重新分配闭合要求的祖先。这个过程叫`Unwind`。`Unwind`只改变活动Focus和显示深度；已经走过的子场、证据和失败上界仍保存在地址谱系中，祖先稳定`address_id`继续`retain`。

门槛调整属于契约运动而不是显示运动。只对已经合法标量化、且“数值越大表示越满足要求”的审计分量`j`，设原要求为`g_{\mathrm{old},j}`，当前证据估计为`\hat m_{k,j}<g_{\mathrm{old},j}`。若父接口实际只要求`g_{\mathrm{parent},j}\le\hat m_{k,j}`，应修正此前对子场要求的过严传导；否则必须把该分量契约显式修订为`g_{\mathrm{new},j}\le\hat m_{k,j}`，记录依据、影响范围和新`field_version_id`。不得在原契约下把该分量报告为达标，也不得由此单独推出完整场闭合；未标量化的审计分量和不可补偿硬门继续分别判断。

本节描述的是可审计的工程寻址候选，不宣称场栈复原了对象自身结构，也尚未进入地址引擎或Focus运行时。

## 八、地址运动

地址运动不是简单重命名。跨版本地址谱系写为：

\[
\mu_{v\rightarrow w}
\subseteq
(A^v\cup\{\bot\})\times(A^w\cup\{\bot\}).
\]

它至少包含：

| 运动 | 含义 |
|---|---|
| `a→a` | `address_id`和功能保持；载荷、接口或证据修订由`address_revision_id`记录 |
| `a→b` | 功能迁移到新地址 |
| `a→{b₁,b₂}` | 一个旧地址分裂为多个新地址 |
| `{a₁,a₂}→b` | 多个地址在明确接口下合并 |
| `a→⊥` | 地址在新版本退休，但历史保留 |
| `⊥→b` | 新地址出生 |

同一对象可以从地址 `a` 迁移到 `b`；地址 `a` 退休不等于对象死亡。反过来，相同字符串也不保证相同地址功能：角色、依赖、范围或接口改变时，必须生成载荷修订或新地址关系。

## 九、地址与动态地图

地址集合及其有类型关系构成当前场的动态地址地图 `M_t`。它不是世界全图，而是相对于当前场契约、证据和版本已经表示的结构全景。

```text
M_t：当前已表示地址和关系
H_t：其中已经执行并通过审计的下闭集
S_t^field：当前递归场栈及逐层返回接口
d_t：模型内递归深度
q_t：声明尺度可比较时的分辨率数量级
ExpansionFrontier_t.required：父场当前闭合要求打开、实现或由接口承担的合法`[◇]`地址
ExpansionFrontier_t.latent：合法存在但本轮不要求打开的`[◇]`地址
ActionFrontier_t：前驱满足、当前可以执行的地址
Compressed_t：以有效接口保存的闭合子场
Λ_t：可能在以后被激活的差异记录；通过bound／candidate／unaddressed绑定地址，但本身不是地址
R_t：影响 F0、但仍未被当前结构吸收的活动剩余
χ_t：剩余与现实、前沿、假设、负地址或无地址的关系
```

动态地图发生变化时，必须同时报告地址增量、前沿变化、剩余变化和版本依据。任何子地址运动都会形成新的全景快照，但未参与迁移的祖先和其他地址在新快照中登记为`retain`。只画出新增节点而不记录保留、失效、未展开和剩余，会把运动场误写成静态分类图。

活动地址不是“当前权重最高的全部参数”。一个地址进入`Active_t`至少要通过：场契约与父绑定合法、根路径连续、必要前驱已满足或有有效接口、版本与权限兼容、模态允许，并且它属于当前必要展开、行动就绪或活动剩余处置范围。随后才允许使用父场阻断程度、条件贡献区间、不确定性、交互风险、展开成本和证据价值在合法同级候选中排序。

条件贡献只能作为带分解契约的可选标注。并行且近似穷尽的子贡献可以在父预算内分配区间；串行必要位置、强交互、阈值和非线性放大必须保存在不同关系角色中。任何权重都不能制造根路径、证明中心或让执行越过必要前驱。触发地址也不能直接短接到宏观结果：地址图应分别保存资源来源、结构条件、放大机制、阈值、触发和传播轨迹；若触发载荷可替换，它保留触发接口身份而不冒充整个场中心。

## 十、开放前沿、潜在剩余和活动剩余

任何有限场都不能穷尽自身，因此可以始终保留继续展开的合法前沿。相对闭合不等于没有潜在地址。

但以下四者必须分开：

1. **必要展开前沿 `P_t^{req}`**：已有合法结构位置，且本轮闭合必须打开、实现或由有效接口承担；
2. **普通潜在前沿 `P_t^{latent}`**：已有合法结构位置，但本轮不要求展开；
3. **潜在剩余 `Λ_t`**：尚未被上一层目标、证据或现实变化激活的差异记录；它可以绑定合法地址、地址候选或暂时无地址，但本身没有`[◇]`模态；
4. **活动剩余 `R_t^a`**：已经影响当前 F0，却无法被现有结构无失真吸收的差额。

例如，“修复一个已确认的软件缺陷并满足当前发布契约”可以达到任务相对稳定，同时保留额外平台兼容、非阻断性能优化、扩展诊断和可选重构等合法潜在前沿；尚未确认能否归入这些前沿的新差异则保存在`Λ_t`。只有当某项进入验收契约，或证据表明它会阻断交付时，合法前沿才迁入`P_t^{req}`；若差异只绑定候选地址，则必须先标定。这个例子只演示地址激活，不证明软件工程与其他领域具有同一对象结构。

潜在剩余激活后的机器分流固定为：局部无失真吸收；绑定合法地址并迁入`P_t^{req}`；验证候选并新生／拒绝地址；形成带`[-]`寻址结果的活动剩余；形成带`[∅]`寻址结果的活动剩余；或在边界审计后外部化。激活不是“把`Λ_t`的模态从`[◇]`改成别的模态”，而是差异记录、地址绑定、前沿状态和寻址结果之间的一次有证据转换。

合理的临时闭合条件不是“所有地址已经展开”，而是：

> 必要展开前沿已经清零；普通潜在前沿可以继续保留；影响 F0 的活动剩余低于容差或已有不阻断闭合的合法处置；没有未处理的冲突或无地址阻断；当前证据足以支持本轮行动或交付。

## 十一、负地址与无地址

`[-]` 和 `[∅]` 不是普通地址类型，也不进入合法地址全景，而是对转换能力和表达能力的寻址结果。

- `[-]`：当前直接转换违反场契约、硬约束或必要偏序。它不自动否定所有替代路径。
- `[∅]`：当前场无法无失真表达、生成或保证某个与 F0 相关的结果。

可靠反例如果在当前语法中无地址，必须保留为无地址剩余，随后向下一层展开、向上一层升场、分裂平行场、重构中心或修改地址语法。不能因为反例不合旧理论就标成“禁止”。

## 十二、版本、时间和反馈

需要区分六种身份与版本时钟：

- 运行修订：每次状态事件；
- 地址修订：同一`address_id`自身的载荷、接口或证据发生修订；
- 动态地图版本：地址或关系全景发生结构写回；
- 场版本：场契约、中心或闭合结构改变并形成相应版本；
- 根域语义版本：根接口或构成身份发生变化；
- 文档修订：文字、例子、引用或排版变化。

六者不自动同步。子地址运动至少改变运行修订和动态地图版本；它不自动推进祖先地址修订、祖先场版本或根域语义版本。

反馈不能在同一版本内把必要偏序写成循环。可以通过阶段展开或版本转换表达：

\[
O_t\prec\cdots\prec O_{t+1}.
\]

版本谱系保存可追踪继承，不表示后来的地址必然更真、更善或更完整。

## 十三、动力闭环

动态寻址的最小运动循环为：

```text
上一层目标、现实变化或用户触发
→ 读取当前暂稳场版本
→ 检查 F0、中心和必要偏序
→ 激活合法潜在前沿，或激活潜在剩余并按绑定状态分流
→ 选择 Global／Focus／展开／重构等合法运动
→ 生成新地址、地址变化和关系变化
→ Execute／Audit 获得证据或失败
→ 监测地址进展、闭合残差、证据增量、尺度与预算
→ 必要时Fold当前场帧并Unwind到最近可决策祖先
→ 更新模态、前沿、剩余和地址谱系
→ 达到相对闭合，返回新的暂稳场版本
```

地址使场运动可见，但地址不是运动的充分原因：潜在剩余保存差异材料，上一层推动提供激活，标定决定候选能否取得合法地址，偏序约束合法路径，闭合判据决定何时停止。

## 十四、应用接口

本理论可以向下支持：

- Focus Skill：复杂任务的动态建模、执行和审计；
- 动态地址引擎／SDK：地址生成、解析、校验和迁移；
- 研究地址系统：论文贡献、证据和争议的结构定位；
- Focus Memory：跨会话恢复任务版本、前沿、失效和重开地址；
- Focus RAG：检索补齐当前根路径所需的必要前提；
- Focus Orchestrator：按必要偏序和接口协调多个 Agent；
- Focus Audit：追踪上下文选择、闭合理由和失效传播；
- Focus Policy：把合法地址和前驱结构编译为策略约束。

应用失败不能直接证明总理论错误。必须先定位失败来自错误场契约、中心恢复、偏序、地址标定、运动协议、实现缺陷还是理论本身无法容纳的反例。

## 十五、当前失败条件

出现以下情况时，本理论必须缩小定义域或重构：

- 相同场契约和证据下，不同分析者无法形成任何可比较地址；
- 地址字符串稳定，但功能角色和根路径持续漂移；
- 新路径频繁跳过必要前驱，仍被系统接受为合法地址；
- 压缩后的地址不能可靠恢复接口、证据和版本；
- 地址维护成本长期高于导航、执行或审计收益；
- 所谓地址只是人工分类编号，无法由场运动重新生成；
- 无地址反例总被重新命名为旧场内部的普通分支；
- 错误中心使有价值地址长期被禁止且无法通过剩余重构。
- 多个候选、载荷、视角或普通并联分支仅被并列命名，就被写成已成立的多中心；
- 中心归属改变导致对象或地址被无依据复制，完整全景遗失未选活动中心，或Focus把多个中心同时装入当前偏域运行态。

## 十六、当前开放边

1. 地址的最小稳定字段是什么；
2. 不同分析者怎样标定功能等价地址；
3. 关系自身怎样成为完整递归锚点；
4. 跨场平行、重叠和耦合场怎样共享对象身份；场内分叉—汇合按本版`parallel_binding／join_rule_ref`处理，但跨场共享仍未解决；
5. 地址相似、结构同构和功能等价怎样计算；
6. 地址合法性怎样从自然语言和证据中自动恢复；
7. 潜在剩余怎样与普通展开前沿稳定区分；
8. 地址地图在大规模任务中怎样增量维护；
9. 什么条件足以迫使修改地址语法而不只是新增分支；
10. 显式地址收益能否超过建图、标定和版本维护成本；
11. 必要／潜在展开前沿、潜在剩余与活动剩余怎样在机器状态中稳定迁移；
12. 条件贡献、交互项和因果角色怎样获得领域证据，避免被标签化伪精确；
13. 已明确的`Binding_t^q + Q_t + V_t^q`怎样进入统一实现，而不丢失全局根路径、未选前沿和父返回接口；
14. 事件场、测量场、估计场和行动场怎样保留同一对象的跨场身份与证据转换；
15. 多父DAG中怎样区分对象共享、场实例共享与路径相对地址，并审计各父场不同的闭合义务。
16. 并联汇合规则、时间兼容策略和`JoinState`怎样进入机器schema、增量执行与反例测试。
17. 完整场`center_membership／center_relation／center_join_rule`怎样进入中心地图，并向Focus稳定生成带源版本的`ProjectionCertificate／selected_center_ref／peer_center_refs`而不复制共享地址；
18. 完整场中的中心分裂、合并、降级和重绑定怎样推进地址修订、场版本及选择性失效传播，并在何种条件下触发Focus重投影；
19. 真多中心、候选并列、普通并联、平行多场和多父绑定怎样形成可执行反例矩阵，同时验证Focus始终只运行一个选定中心。
20. 线性对话、工具轨迹和递归场栈怎样保持可逆引用，而不把摘要误作完整结构；
21. 递归深度、分辨率数量级、偏序高度、分支宽度和交互秩怎样在不同领域稳定标定；
22. 停滞检测怎样区分困难但必要的长地址与错误尺度下的重复细化；
23. `Unwind`应退回多少层，怎样由父容差、可达上界、平级中心和契约修改权限共同决定；
24. 回卷后的摘要怎样保存未闭合债务、反例、来源和重开条件，并在上下文受限时仍可审计。

## 十七、首版来源与关系

- `expands`：总理论根节点`F0:C`中关于地址生成、地址生命周期和Focus状态的压缩载荷；
- `interfaces with`：总理论根节点`F0:D`中的可计算地址模块与Focus工具；
- `depends on`：递归中心场偏序动力模型的场契约、中心、必要偏序、递归、闭合与剩余定义；
- `constrains`：Focus Skill 和未来地址引擎的地址语义；
- `does not replace`：总理论、方法论、动态模型或现有状态实现；
- 状态：用户明确要求把动态地址从分散定义展开为独立理论、明确Focus局部根不能替代全局地址，并进一步澄清“完整场域多中心、Focus偏域单中心”。v0.8补充中心不可约分解、完整子场／Focus投影分层、逐中心义务状态及投影—返回证书；v0.9进一步明确本理论是工程拟合和寻址模型而非对象结构本身，并增加递归场栈、分辨率层级与分层回卷候选；v0.11增加sidecar执行后证据地址；v0.12恢复地址在过程中的导航、约束、证据、记忆与重开作用，并把sidecar降为历史导入接口。必要后继失效、父接口重开、闭合版本和版本分支已有运行时子集；自动停滞判定、多父约束、跨任务地址汇合和中心生命周期仍待反例与实现验证，Focus仍不升级为多中心联合调度。
