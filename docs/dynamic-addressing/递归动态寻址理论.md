# 场域相对的递归动态寻址理论

> 版本：v0.1-draft（2026-07-19）  
> 身份：递归中心场偏序动力场域论的中层展开理论  
> 证据边界：当前是结构与协议候选，不是经过实验确证的普遍自然地址体系

## 一、问题与理论定位

普通编号系统先规定一个固定容器，再把对象填入预留位置。递归动态寻址理论处理的是另一类问题：当问题边界、中心、必要关系、观察深度和场版本都可能变化时，对象怎样获得可追踪的位置；场在展开、聚焦、压缩、执行和重构以后，新位置怎样产生，旧位置怎样保留或迁移。

本理论的根命题是：

> **地址不是对象脱离关系后的永久坐标，而是对象在特定场契约、中心偏序、递归路径和版本中的结构身份；地址随着场的合法运动生成和变化，但必须保留对象身份、根路径、证据与旧新谱系。**

地址因此同时承担五项功能：

1. 定位：说明对象或关系在当前场承担什么结构角色；
2. 约束：说明它依赖哪些必要前序、经过哪些合法接口；
3. 导航：允许从根层进入下一层子场，并在压缩后重新打开；
4. 记忆：保存当前版本、历史版本和失效来源；
5. 审计：说明地址为何生成、何时实现、如何迁移以及什么仍未被吸收。

## 二、它在总理论中的结构位置

递归中心场偏序动力场域论的五个核心对地址分别提供不同条件：

| 理论内核 | 对地址的作用 |
|---|---|
| 场 `F` 与契约 `Γ_F` | 决定地址在哪个定义域、尺度、目标和证据标准下成立 |
| 中心 `K_F` | 决定哪些功能位置构成当前任务的承重结构 |
| 必要偏序 `Π_F` | 决定根路径、必要前驱和合法运动方向 |
| 递归 `Exp/Comp` | 允许位置与关系打开为下一层场，并压缩为可重开接口 |
| 动力、闭合与剩余 | 触发地址生成、状态变化、失效、升场和版本重构 |

由此得到：

\[
\mathcal A_t
=
\operatorname{Address}
(F_t,\Gamma_t,G_t,\Pi_t,K_t,
\operatorname{Exp},\operatorname{Comp},T_t,v_t,E_t).
\]

这里的 `Address` 不是一个一次性编码函数，而是一组受场运动约束的生成、校验和版本操作。

地址层向上不替代场域论，向下约束 Focus、知识地址、动态地图、长期记忆、多 Agent 编排和可能的地址引擎。

## 三、五种必须分开的身份

### 3.1 对象身份

对象身份回答“我们正在追踪的是谁或什么”。它不应因显示路径变化而自动改变。一个论文、概念、任务、证据、关系或子场可以拥有稳定的 `object_id` 或 `relation_id`。

### 3.2 场身份

场身份回答“该判断在哪个问题域和契约中成立”。同一对象进入不同场，可以承担不同功能，因此可以拥有多个合法场相对地址。

### 3.3 地址身份

地址身份回答“对象在当前场版本中位于哪里、承担什么功能、怎样从根层抵达”。它由场、角色、根路径和递归运动共同生成。

### 3.4 模态状态

模态回答“本次寻址或地址当前以何种方式成立”：

- `[+]`：地址对应的结果已经执行并通过审计；
- `[◇]`：地址合法或有待验证，但尚未实现；
- `[-]`：某个候选直接转换被当前契约或必要偏序禁止；
- `[∅]`：当前场无法无失真地表达、生成或保证该候选结果。

模态不是地址编号的一部分。合法地址记录使用 `[+]／[◇]`；`[-]／[∅]`是对候选转换或寻址结果的判断，应保存在运动／剩余账本并允许目标地址为空，不能伪装成已经进入 `M_t` 的合法地址。地址可以保持不变而 `[+]／[◇]`状态发生变化。

### 3.5 版本与证据身份

版本回答地址在哪个场闭合版本中有效；证据回答为什么相信地址角色、根路径和模态判断。地址字符串不能替代版本和证据账本。

## 四、逻辑全地址

一个逻辑全地址可候选表示为：

\[
a_t(x)=\langle
field\_id,
goal\_contract\_id,
object\_id,
address\_id,
structural\_role,
root\_path,
relation\_path,
recursive\_path,
interfaces,
field\_version,
modality,
evidence,
provenance
\rangle .
\]

其中：

- `field_id`：场对象身份；
- `goal_contract_id`：当前根目标和验收契约；
- `object_id`：被寻址对象的稳定身份；
- `address_id`：当前地址记录的稳定身份；
- `structural_role`：对象在当前场中的功能位置；
- `root_path`：从 F0 到当前位置的完整根路径子图；
- `relation_path`：支撑该位置的有类型关系和必要前驱；
- `recursive_path`：实际打开子场所形成的递归路径；
- `interfaces`：被压缩但仍承担前序义务的接口；
- `field_version`：地址判断有效的场版本；
- `modality`：合法地址的潜在或实现状态；禁止或无地址判断保存在独立寻址结果中；
- `evidence`：标定地址和状态的证据；
- `provenance`：生成该地址的运动与来源。

面向人的 `F0:C3.2.1[◇]` 只是显示地址。它压缩了上述全地址，但必须能够返回完整记录。

## 五、地址不是任意编号

数字后缀只有在实际打开下一层场并选择其中的合法位置后才能产生。例如：

```text
F0:C3
→ 打开 C3 为子场
→ 在子场中依次选择第 2、1 个合法结构位置
→ 返回 F0 视图为 F0:C3.2.1
```

这里的 `3.2.1` 不是预先规定的分类码，也不自动表示价值、时间、执行顺序或理论深度。它只保存一次真实递归导航的压缩路径。

合法地址必须能够重新展开为：

```text
F0 根契约
＋ 完整根路径
＋ 必要前驱或有效压缩接口
＋ 当前结构角色
＋ 实际递归面包屑
＋ 关系类型
＋ 版本和证据
```

只有数字、没有上述结构的路径，只能叫显示标签，不能叫经过标定的动态地址。

## 六、赋址与标定

“赋址”与“标定”不能混为一次命名动作。

### 6.1 赋址

赋址是为一个对象或关系生成候选结构位置：

```text
确认对象身份
→ 声明所属场和契约
→ 判断候选功能角色
→ 恢复从 F0 到该角色的根路径
→ 补齐必要前驱和压缩接口
→ 记录递归打开过程
→ 生成候选地址与来源
```

### 6.2 标定

标定是检验候选地址是否与现实关系、当前版本和证据一致：

1. 场标定：对象确实与当前根目标相关；
2. 角色标定：删除或替换该角色会产生预期的结构差异；
3. 路径标定：根路径及必要前驱没有被跳过；
4. 接口标定：被压缩前序仍由有效接口承担；
5. 关系标定：依赖、支持、冲突、相似、耦合等关系没有被压成同一种边；
6. 版本标定：证据和地址来自兼容版本；
7. 模态标定：潜在地址没有被误报为已实现；
8. 反例标定：无地址或冲突结果没有被强行塞入旧语法。

未经标定的地址保留为 `hypothesized`，不能进入已审计下闭集，也不能仅凭热度进入执行。

## 七、地址生成的运动来源

地址由场运动生成。设当前地址全景为 `M_t`，则：

\[
M_{t+1}=M_t\cup\Delta M_t^{+}\setminus\Delta M_t^{-},
\]

其中新增、状态改变与退出当前版本必须通过运动账本解释，不能直接覆盖。

### 7.1 场形成

含糊输入尚不是根地址。场契约、中心候选和必要偏序稳定以后，才形成 F0 根层及第一组结构地址。

### 7.2 Global Expansion

Global 在预算内对全部合格展开前沿统一推进一层，产生 `ΔM_global`。预算不足的合法位置保留在展开前沿，不得因本轮未展开而删除。

### 7.3 Focus Penetration

Focus 在根路径合法和必要前驱保持的条件下，对一个或多个位置作不等深展开，产生 `ΔM_focus`，并把新地址写回全景。未选择的合法位置仍是前沿或有效压缩接口。

### 7.4 递归展开和关系展开

节点或关系可以打开为下一层场。新地址只有在下一层场形成自身契约、中心、偏序、闭合端和返回接口以后才获得完整含义。

### 7.5 压缩与重开

相对闭合的子场可压缩为接口地址。压缩隐藏显示深度，但保留输入、输出、条件、证据、未解决差异、版本、失效触发和重开地址。重开恢复原子场，不重新发明另一个同名结构。

### 7.6 Execute 与 Audit

执行通常不生成任意新分类，而是使合法潜在地址取得现实证据。只有执行成功并通过审计，地址对应结果才能从 `[◇]` 转为 `[+]`。执行失败也可能暴露新地址、活动剩余、失效路径或重构需求。

### 7.7 更新与新版本

新证据可以使地址载荷替换、迁移、分裂、合并、退休或新生。地址变化必须保存源版本、目标版本和旧新谱系。

## 八、地址运动

地址运动不是简单重命名。跨版本地址谱系写为：

\[
\mu_{v\rightarrow w}
\subseteq
(A^v\cup\{\bot\})\times(A^w\cup\{\bot\}).
\]

它至少包含：

| 运动 | 含义 |
|---|---|
| `a→a` | 地址身份和功能保持，载荷或证据可以修订 |
| `a→b` | 功能迁移到新地址 |
| `a→{b₁,b₂}` | 一个旧地址分裂为多个新地址 |
| `{a₁,a₂}→b` | 多个地址在明确接口下合并 |
| `a→⊥` | 地址在新版本退休，但历史保留 |
| `⊥→b` | 新地址出生 |

同一对象可以从地址 `a` 迁移到 `b`；地址 `a` 退休不等于对象死亡。反过来，相同字符串也不保证相同地址功能：角色、依赖、范围或接口改变时，必须生成载荷修订或新地址关系。

## 九、地址与动态地图

地址集合及其有类型关系构成当前场的动态地址地图 `M_t`。它不是世界全图，而是相对于当前场契约、证据和版本已经表示的结构全景。

```text
M_t：当前已表示地址和关系
H_t：其中已经执行并通过审计的下闭集
ExpansionFrontier_t：可继续打开的合法潜在地址
ActionFrontier_t：前驱满足、当前可以执行的地址
Compressed_t：以有效接口保存的闭合子场
R_t：影响 F0、但仍未被当前结构吸收的活动剩余
χ_t：剩余与现实、前沿、假设、负地址或无地址的关系
```

动态地图发生变化时，必须同时报告地址增量、前沿变化、剩余变化和版本依据。只画出新增节点而不记录失效、未展开和剩余，会把运动场误写成静态分类图。

## 十、开放前沿、潜在剩余和活动剩余

任何有限场都不能穷尽自身，因此可以始终保留继续展开的合法前沿。相对闭合不等于没有潜在地址。

但以下三者必须分开：

1. **开放前沿**：已有合法结构位置，尚未展开；
2. **潜在剩余 `Λ_t`**：具有潜在地址、尚未被上一层推动激活的未来展开材料；
3. **活动剩余 `R_t^a`**：已经影响当前 F0，却无法被现有结构无失真吸收的差额。

因此，一个简单的“我想吃一个西瓜”可以达到当前任务的相对稳定，同时保留品种、大小、水分、购买位置等潜在展开地址。只有当“水分多”进入验收条件或现实反馈表明现有地址无法满足目标时，它才成为当前运动必须处理的任务相关结构。

合理的临时闭合条件不是“所有地址已经展开”，而是：

> 当前场保留开放前沿；影响 F0 的活动剩余已有合法处置或潜在吸收地址；没有未处理的冲突或无地址阻断；当前证据足以支持本轮行动或交付。

## 十一、负地址与无地址

`[-]` 和 `[∅]` 不是普通地址类型，也不进入合法地址全景，而是对转换能力和表达能力的寻址结果。

- `[-]`：当前直接转换违反场契约、硬约束或必要偏序。它不自动否定所有替代路径。
- `[∅]`：当前场无法无失真表达、生成或保证某个与 F0 相关的结果。

可靠反例如果在当前语法中无地址，必须保留为无地址剩余，随后向下一层展开、向上一层升场、分裂平行场、重构中心或修改地址语法。不能因为反例不合旧理论就标成“禁止”。

## 十二、版本、时间和反馈

需要区分四种版本时钟：

- 运行修订：每次状态事件；
- 动态地图版本：地址或关系全景发生结构写回；
- 场闭合版本：重构后重新获得相对闭合；
- 文档修订：文字、例子、引用或排版变化。

反馈不能在同一版本内把必要偏序写成循环。可以通过阶段展开或版本转换表达：

\[
O_t\prec\cdots\prec O_{t+1}.
\]

版本谱系保存可追踪继承，不表示后来的地址必然更真、更善或更完整。

## 十三、动力闭环

动态寻址的最小运动循环为：

```text
上一层目标、现实变化或用户触发
→ 读取当前暂稳场版本
→ 检查 F0、中心和必要偏序
→ 激活潜在地址或暴露活动剩余
→ 选择 Global／Focus／展开／重构等合法运动
→ 生成新地址、地址变化和关系变化
→ Execute／Audit 获得证据或失败
→ 更新模态、前沿、剩余和地址谱系
→ 达到相对闭合，返回新的暂稳场版本
```

地址使场运动可见，但地址不是运动的充分原因：潜在剩余提供材料，上一层推动提供激活，偏序约束合法路径，闭合判据决定何时停止。

## 十四、应用接口

本理论可以向下支持：

- Focus Skill：复杂任务的动态建模、执行和审计；
- 动态地址引擎／SDK：地址生成、解析、校验和迁移；
- 研究地址系统：论文贡献、证据和争议的结构定位；
- Focus Memory：跨会话恢复任务版本、前沿、失效和重开地址；
- Focus RAG：检索补齐当前根路径所需的必要前提；
- Focus Orchestrator：按必要偏序和接口协调多个 Agent；
- Focus Audit：追踪上下文选择、闭合理由和失效传播；
- Focus Policy：把合法地址和前驱结构编译为策略约束。

应用失败不能直接证明总理论错误。必须先定位失败来自错误场契约、中心恢复、偏序、地址标定、运动协议、实现缺陷还是理论本身无法容纳的反例。

## 十五、当前失败条件

出现以下情况时，本理论必须缩小定义域或重构：

- 相同场契约和证据下，不同分析者无法形成任何可比较地址；
- 地址字符串稳定，但功能角色和根路径持续漂移；
- 新路径频繁跳过必要前驱，仍被系统接受为合法地址；
- 压缩后的地址不能可靠恢复接口、证据和版本；
- 地址维护成本长期高于导航、执行或审计收益；
- 所谓地址只是人工分类编号，无法由场运动重新生成；
- 无地址反例总被重新命名为旧场内部的普通分支；
- 错误中心使有价值地址长期被禁止且无法通过剩余重构。

## 十六、当前开放边

1. 地址的最小稳定字段是什么；
2. 不同分析者怎样标定功能等价地址；
3. 关系自身怎样成为完整递归锚点；
4. 多个平行场、重叠场和耦合场怎样共享对象身份；
5. 地址相似、结构同构和功能等价怎样计算；
6. 地址合法性怎样从自然语言和证据中自动恢复；
7. 潜在剩余怎样与普通展开前沿稳定区分；
8. 地址地图在大规模任务中怎样增量维护；
9. 什么条件足以迫使修改地址语法而不只是新增分支；
10. 显式地址收益能否超过建图、标定和版本维护成本。

## 十七、首版来源与关系

- `expands`：总理论地址 `F0:D2`“地址作为中心展开后的可定位关系”；
- `expands`：`F0:F1–F5`“根地址、更新入口、最小上溯、地址谱系与闭合版本”；
- `depends on`：递归中心场偏序动力模型的场契约、中心、必要偏序、递归、闭合与剩余定义；
- `constrains`：Focus Skill 和未来地址引擎的地址语义；
- `does not replace`：总理论、方法论、动态模型或现有状态实现；
- 状态：用户明确要求把动态地址从分散定义展开为独立理论；具体形式化、字段和协议为当前候选，仍待反例与实现验证。
