# 递归动态寻址理论：开放问题与验证路线

> 状态：v0.2 开放前沿（2026-08-26）。本文只保存尚未闭合的问题、反例压力和验证路线，不把计划写成已完成结果。

## 一、当前决定

动态寻址理论已经从总理论中展开为独立中层，但仍属于候选理论。当前最重要的工作不是继续增加宏大应用，而是证明：不同分析者能否在相同场契约和证据下生成可比较地址；地址运动是否比普通编号、图节点和版本标签提供额外、可测量的价值。

## 二、形式层开放问题

1. 逻辑全地址的最小稳定字段是什么；
2. 地址身份与对象身份在分裂、合并和跨场投影时怎样保持；
3. 根路径是单链、子偏序还是一般有向无环子图；
4. 关系自身怎样打开为子场并获得递归地址；
5. 反馈系统怎样通过阶段或版本展开，避免伪造同版本偏序；
6. 多个不可比较中心怎样产生平行地址空间；
7. 地址等价、功能等价、结构同构和显示路径相等怎样区分；
8. 地址语法变化何时构成局部扩展，何时构成根场重构；
9. 潜在剩余、普通展开前沿和地址假设的操作定义已在v0.10完成分层；跨领域标定一致性与迁移成本仍待验证；
10. `[∅]`结果怎样决定向下展开、向上升场、场外处理或修改地址语法。

## 三、标定与复现问题

需要至少两名独立分析者在不知道彼此结果的情况下，对相同材料完成：

- 场契约标定；
- 对象身份标定；
- 功能角色标定；
- 必要前驱和根路径标定；
- 递归边界和压缩接口标定；
- 模态与证据标定；
- 地址迁移和失效范围标定。

不能只比较字符串是否相同。应比较它们是否保持相同不可变约束、合法／非法行动区分、必要汇合、接口义务和闭合条件。

低一致率可能意味着材料不足、场契约含糊、中心不唯一、地址粒度错误或理论本身缺少可操作性。不能通过让创建者单方面裁决来掩盖这一结果。

## 四、关键反例压力

### 4.1 无稳定中心的场

若任务不存在可恢复中心，地址系统能否保留多个候选或分裂平行场，而不是制造空洞根轴？

### 4.2 强反馈与循环系统

若关系不能通过阶段展开、尺度分离或协同功能压缩形成偏序，系统能否保存 `non-poset` 结果而不强行编号？

### 4.3 同物多址与同址异物

同一对象在多个场中拥有地址时，怎样防止错误合并？相同显示路径在不同版本承担不同角色时，怎样防止地址漂移？

### 4.4 压缩失真

若子场压缩后丢失了后来才重要的条件，系统能否根据失效证据重开原地址，并正确传播下游失效？

### 4.5 无地址反例

当可靠差异不能被当前语法表达时，系统能否真正修改地址语法，而不是把所有反例重新命名成普通剩余？

### 4.6 维护成本

如果地址生成、标定和版本维护成本高于任务本身，理论应缩小到何种任务规模和领域？

## 五、实现层开放问题

- 自动恢复完整关系与必要偏序；
- 自动生成候选中心并执行删除、替代和闭合检验；
- 对同义改写保持地址稳定；
- 为关系和接口生成可递归地址；
- 支持增量图更新而非每次全量重建；
- 保存地址分裂、合并和分支版本；
- 自动验证压缩接口的输入输出和重开条件；
- 从执行证据更新地址模态并传播失效；
- 在多 Agent 环境中避免并发写入同一地址；
- 提供人类可读显示地址与机器全地址之间的双向解析。

## 六、分阶段验证路线

### 阶段 1：纸面标定

选取三个小型、边界清楚的场：软件缺陷修复、研究论文结构编码和日常任务。由两名分析者独立赋址，记录一致、分歧、无地址和重构点。

验收重点：

- 根路径和必要前驱是否可比较；
- 同一对象的多场地址是否被正确区分；
- 普通前沿与活动剩余是否被区分；
- 地址是否能由运动过程重新生成，而不是只靠记忆原编号。

### 阶段 2：最小地址引擎

实现不依赖自然语言自动判断的确定性内核：

```text
创建场和对象身份
→ 接收人工标定的关系与偏序
→ 生成完整地址和显示地址
→ 执行 expand／compress／move／split／merge／retire
→ 保存旧新谱系
→ 校验根路径、版本和接口不变量
```

该阶段只证明协议可实现，不证明自动建模正确。

### 阶段 3：动态地图与查询

在小规模数据上实现：

- 按根路径查询；
- 按功能角色和必要前驱查询；
- 查看一个对象在多个场中的地址；
- 查看地址历史、分裂、合并和失效后继；
- 打开压缩接口并返回原子场；
- 区分当前地址、历史地址、前沿、潜在剩余和活动剩余。

### 阶段 4：自然语言辅助标定

让模型从文本中提出场、关系、中心和地址候选，但保留人工校对与多候选。比较：

- 地址准确率和一致性；
- 必要前驱遗漏；
- 根路径非法率；
- 同义改写稳定性；
- 错误中心锁定时间；
- 人工修正成本。

### 阶段 5：应用对照

分别验证：

- Focus任务恢复是否优于普通摘要；
- 结构论文检索是否补充关键词和向量检索；
- 多 Agent 编排是否减少非法跳步与版本误用；
- 地址审计是否提高失效传播和证据追踪；
- 地址维护总成本是否低于其带来的收益。

## 七、基线

不能只对比静态目录树。至少包括：

- 稳定 ID＋普通属性图；
- 知识图谱／本体＋版本；
- DAG 工作流或 HTN；
- Petri 网或行为树；
- 摘要记忆与普通 RAG；
- GraphRAG；
- 人工项目结构和变更账本。

若这些组合在更低成本下复现全部收益，应缩小动态寻址理论的独立贡献。

## 八、候选指标

| 指标 | 含义 |
|---|---|
| 地址复现率 | 相同场契约下，独立分析者生成可比较地址的比例 |
| 根路径完整率 | 地址保留全部必要前驱或有效接口的比例 |
| 非法跳址率 | 跳过必要前驱仍被接受的地址比例 |
| 同义稳定性 | 表述变化而结构不变时地址保持或正确映射的程度 |
| 地址漂移率 | 无证据情况下角色、路径或版本发生变化的比例 |
| 失效传播召回 | 前驱失效后被正确重开的依赖地址比例 |
| 重开成功率 | 压缩接口能否恢复所需条件、证据和子场 |
| 无地址识别率 | 真正超出当前语法的差异被保留而非强行收编的比例 |
| 维护成本 | 新增 token、时间、存储、计算和人工校对成本 |
| 最终任务收益 | 在完整成本下的任务质量、恢复质量或执行正确性变化 |

## 九、停止与裁剪条件

出现以下任一长期结果时，应裁剪理论或限定应用域：

- 地址不能在独立分析者之间获得最低可接受一致性；
- 正确与打乱地址在任务结果上没有稳定差异；
- 普通属性图和版本账本以更低成本实现同等能力；
- 地址生成持续依赖创建者的隐性直觉，无法转成交付协议；
- 地址语法为保持自洽不断吸收反例，却不允许根规则改变；
- 维护成本长期超过导航、恢复、执行或审计收益。

## 十、当前剩余账本

- `[◇]` 最小地址字段和等价标准尚未通过多人标定；
- `[◇]` 关系地址和多场共享对象身份尚未实现；
- `[+]` 潜在剩余`Λ_t`已以`bound／candidate／unaddressed`绑定进入历史两阶段Focus与Address Engine 0.5；跨旧schema批量迁移仍未完成；
- `[+]` v0.18构造型Focus已实现过程内功能地址、已实现节点证据闸门、必要后继失效和父接口重开；v0.17 sidecar保留历史轨迹导入，跨任务全景合并仍未完成；
- `[◇]` 地址候选／合法地址分账与手工标定闸门已经实现；自然语言自动标定和多人一致性仍未建立；
- `[◇]` 与属性图、HTN、工作流和GraphRAG的同预算对照尚未完成；
- `[-]` 禁止把任意数字路径直接当作合法地址；
- `[-]` 禁止用新版本覆盖旧地址含义；
- `[∅]` 当前材料不能证明动态地址是现实本身的普遍结构。
