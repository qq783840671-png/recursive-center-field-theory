# Recursive Center-Field Focus Skill

## Quick start

Accept a direct request such as `Use Focus: turn this rough idea into a stable research question and then act on it.` First return the formed F0 checkpoint; after confirmation, return the result, symbolic residuals, and one decision. Reveal addresses or raw audits only when requested.

## Invocation contract

Run only when the user attaches `Focus` or the formal Skill name to an actual task. Accept one natural-language sentence; never require notation or a pre-built field. Discussion about the Skill is not invocation.

Use **Clarify mode** for `理清／定位／分析`: stop at the audited modeling handoff. Use **Action mode** for `做／执行／完成`: after modeling, compile and execute legal Ready work; do not return only a plan when no gate blocks action.

For a new field, form a stable candidate F0 before asking for confirmation. A reply such as “对／就按这个／确认” confirms the displayed candidate. Reuse a confirmed, unchanged field; restart formation only when its contract, selected center, necessary relations, permissions, evidence, or active blocking residuals materially change. Bypass formation or confirmation only on explicit request, without bypassing later legality, safety, or closure gates.

## Core model and forward direction

Never reduce Focus to taxonomy, tree generation, relevance ranking, or arbitrary reweighting. Preserve:

- field contract `Γ_t` and traceable F0 lineage;
- complete typed relation graph `G_t` before necessary-predecessor projection `Π_t`;
- evidence-tested candidate centers `𝒦_t` and the selected minimum-sufficient load-bearing center `K_t^v`;
- recursive opening and fidelity-preserving, reopenable compression;
- Field Formation, Survey, Global, Focus, Execute/Audit, invalidation, promotion, split, rebuild, and version return;
- raw update intake, explicit location, minimum upward propagation, lineage, and closure-qualified versions.

Keep structural necessity, dependency priority, exposure depth, and task weight distinct. Rank only legal peers. Weight may choose how far a legal address opens; it cannot create an address, remove a predecessor, certify a center, or demote a compressed predecessor.

Always proceed forward:

`current need + superior purpose → Γ_t → G_t → Π_t → K_t^v → formed F0 → confirmation → bounded address motion → Ready execution → residual/closure audit`

Never invent a result or address and backfill a plausible order around it.

## F0 formation and closure gate

1. Preserve the raw task and material ambiguities; recover the current need and superior purpose.
2. Form `Γ_t`, then build the complete typed functional/relational graph `G_t` with evidence-bound required dependencies.
3. Derive an acyclic necessary order `Π_t`. Keep unsupported same-version cycles as `non-poset` residuals.
4. Extract center candidates and test each by root-to-downstream necessity, deletion, replacement, reordering/reversal, compression, closure, cycle, and hollow-abstraction checks. A downstream result cannot certify its predecessor.
5. Audit formation residuals. If any blocking ambiguity, disputed center, `[-]`, `[∅]`, rootless path, missing predecessor, human-pending item, prohibited item, realized-but-unabsorbed item, or `[◇,d=?]` remains, continue formation or return the matching calibration/remodel decision.
6. When every active residual is either absent for an audited reason or `[◇]` at a complete legal root path with evidence-supported finite reach `d=1` or `d=k`, display the formed candidate and stop at `F0_CONFIRMATION_REQUIRED`.

Provisional closure means verified finite legal absorption routes exist, not final completeness. Do not produce F1/F2 while confirmation is pending. Confirmation is a lock event, not the start of formation.

Default pre-confirmation display:

- `F0: <one sentence>`;
- validated task-specific center axis `A → … → A′`, with one short label per position;
- material `[◇]` residuals;
- exactly one decision.

Hide task-irrelevant input. Do not display full contracts, verbose residual IDs, fabricated activity addresses, or motion snapshots by default.

## Bounded operating loop

After confirmation:

1. **Gate addresses.** Require an F0 root path, predecessors or valid interfaces, boundary/permission compliance, compatible version, and allowed modal state.
2. **Global #1.** Expand every eligible Expansion-frontier item one uniform level within budget; defer explicitly instead of weight-selecting branches.
3. **Focus #1.** Open one or more legal paths to unequal depths; keep unselected required structure as frontier/interfaces and write new addresses back to the panorama.
4. **Compile.** Build executable sub-poset `D_t` from active addresses plus required predecessors/interfaces; compute `Ready_t`.
5. **Execute/Audit.** Follow the necessary dependency order, run incomparable Ready nodes in parallel when safe, verify evidence, update realized state, propagate invalidation, audit residuals and closure, then decide.

Use `1 Global + 1 Focus` by default. Add a motion only when the residual ledger, unresolved frontier, or requested depth shows it can change the result. Never add rounds to compensate for an unvalidated field or center. F1/F2 record motion provenance; they are not an execution queue, child IDs, recursion limits, or F3. Execute along `A→B→C…`, not by snapshot depth or suffix length.

## Recursive addresses and proof

Keep `F0` as the logical root of the field opened by attention. A focused child becomes the active local F0 with its own letter center; retain its `field_id`, parent binding, numeric parent-facing path, and return interface. Compress it back to that address when returning upward. Create `F0′` only when constitutive identity is no longer traceable.

Opening a node or relation means opening a child field, not adding a suffix. Persist `field_opening_status=hypothesized|forming|validated`:

- `hypothesized` and `forming` are `[◇]` address hypotheses. Keep them in Expansion Frontier or the residual ledger; they cannot support closure, active/action paths, execution, or realization.
- `validated` requires a local F0 contract, complete typed graph, necessary order, minimum-sufficient center, parent/return interface, and residual audit.

Persist each validated opening with an evidence-bound inline restorable `state_snapshot`, logical `state_ref`, and canonical hash. Keep that proof hidden in normal rendering and reuse the already validated loaded proof while its state version is unchanged. Whenever proof must be rechecked, resolve the snapshot/reference, recompute the hash, and structurally validate the snapshot—never trust certificate fields or a digest-shaped string alone. If proof cannot be completed within budget, retain `[◇,d=?]`; never fabricate a validated deeper address.

Allow multiple unequal F0-facing paths such as `A1.2`, `B1.1.2.3`, and `C3.2.1`; preserve root paths and reopen addresses. Delegate field-relative identity/address generation to `recursive-field-addressing` Client mode when available, but keep F0 confirmation, priority, penetration depth, Ready compilation, domain execution, and final audit here.

## Residual and modal audit

Maintain distinct state:

`S_t = M_t + R_t + Frontier_t`

- `M_t`: validated and currently realized legal structure;
- `R_t`: F0-relevant structural difference exposed or produced by motion that the current field has not absorbed;
- `Frontier_t`: legal but unopened or compressed continuation.

Keep `ActionFrontier_t`, `ExpansionFrontier_t`, `Compressed_t`, and `R_t` distinct. Unexpanded, de-prioritized, compressed, external, or input-blocked items are not automatically residuals.

Use modal states consistently:

- `[+]`: realized only after `Execute → Audit`;
- `[◇,d=1|k]`: potential address with verified finite absorption reach;
- `[◇,d=?]`: hypothesis with unknown reach; it does not close F0;
- `[-]`: prohibited or structurally conflicting result;
- `[∅]`: no legal expression, route, or guarantee in the current field.

Never label an ordinary unopened node `[∅]`. After every Formation, Global, Focus, and Execute motion, record produced/absorbed residuals, reach, updated frontiers, and the next-state decision. An empty residual ledger requires an audited reason.

## Persistence and token discipline

For answer-only work, keep only the current compact state in the response. For authorized multi-turn work, initialize `.codex/recursive-center-field/state.json` without overwriting and reuse loaded state. Read legacy state without inventing or silently migrating claims.

Pay the full validation cost once per unchanged state version:

- reuse confirmed F0, `Γ_t`, `G_t`, `Π_t`, selected center tests, and validated child proofs until an explicit invalidation condition occurs;
- retain canonical evidence/snapshots in state, but render or reload their full bodies only for validation, mutation, dispute, or raw audit;
- never repeat panorama, root paths, proof shells, or ledger details in both working output and final output;
- keep the default one-Global/one-Focus motion and compact rendering, while retaining all audit data in state.

These rules reduce representation and reload cost only; they do not create a weaker runtime or make any semantic gate optional.

## Compact result and decisions

After provisional closure, return only:

1. stable F0 and center axis;
2. one motion result—the answer for a question or delivered effect for an action;
3. a symbolized residual summary;
4. exactly one next decision.

Keep F1/F2 diffs, child-opening proofs, panorama, active addresses, root paths, stable residual IDs, `ΔM`, frontiers, `D_t/Ready_t`, and the detailed ledger hidden but auditable unless requested.

Allowed decisions: `F0_CONFIRMATION_REQUIRED`, `FIELD_FORMATION_REQUIRED`, `HUMAN_CALIBRATION_REQUIRED`, `CONTINUE_EXECUTION`, `FOCUS_REQUIRED`, `EXPAND_REQUIRED`, `REMODEL_REQUIRED`, `FIELD_ASCENSION_REQUIRED`, `F0_COMPLETE`, `BLOCKED`.

Chinese rendering is fixed: F0 is `根层`, complete `root_ancestry` is `根路径`, and adjacent containment is `上一层／下一层`. Keep compatibility field names machine-only; never render “祖先” as current terminology.
